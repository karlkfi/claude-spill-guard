**spill-guard is a Claude Code hook that blocks secrets and US Social Security numbers before a call sends them to the API.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> **Upgrade if you run Claude Code on Windows without Git for Windows.** On v0.6.1 the hook command does not parse under PowerShell, so on that machine spill-guard scans nothing and nothing blocks. Tested on Claude Code 2.1.290 on `windows-latest`: a `Read` of a planted key returned the key to the model, and a prompt carrying a key reached the API. The plugin update is the half that fixes it. It now scans `Read`, prompts and PowerShell command strings. **Files a PowerShell command opens are recorded and not read**, so `Get-Content` of a planted key still returns the key.

## What v0.7.0 is for

**Blocking Anthropic API keys and labelled US Social Security numbers, scanning at all on Windows without Git for Windows, and closing the cases where a key crossed because something else in the same call could not be read.** It is a minor rather than a patch because a rule that was off is on by default, a new rule ID ships, and the hook matches one more tool.

## Highlights

- **Anthropic API keys and Admin API keys are blocked.** `anthropic-api-key` matches `sk-ant-api03-` and `sk-ant-admin01-` followed by 93 bytes of `[A-Za-z0-9_-]` and a closing `AA`. On v0.6.1 such a key crossed in a prompt, a `Read` and a `cat` with no verdict. The format is taken from gitleaks and TruffleHog, because Anthropic does not publish one, and no real key has verified it. ([#232](https://github.com/karlkfi/claude-spill-guard/pull/232))
- **US Social Security numbers are blocked in one narrow form.** `us-ssn` matches `###-##-####`, area below 900, with `ssn` or `social security` in the 64 bytes before it, in any case and spelled with a space, a hyphen, an underscore or nothing. Nine bare digits do not match, and neither does a label after the number. ([#235](https://github.com/karlkfi/claude-spill-guard/pull/235))
- **The hook scans on Windows without Git for Windows.** The command in `hooks/hooks.json` is now one string that bash, zsh, Windows PowerShell 5.1 and PowerShell 7 all parse, and the `PowerShell` tool is matched. ([#234](https://github.com/karlkfi/claude-spill-guard/pull/234))
- **The README now opens on what gets blocked, with real deny output, and no longer carries a canary**, so a session running spill-guard can read it. [`docs/installing.md`](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/installing.md) is new and holds the verifier, `go install` and `selftest` detail. ([#233](https://github.com/karlkfi/claude-spill-guard/pull/233))

### Where a key used to cross and now blocks

- **A file named after an unquoted substitution is now scanned.** `cat $(echo plain.txt) key.txt` crossed with a coverage record (a line in a local log saying what the hook could not read), and `cat <(echo a) key.txt`, `head -n $(echo 1) key.txt` and `time -p cat key.txt` crossed with nothing at all. All four now block. Words after a substitution are no longer read as a command, which ends a false block on `echo $(date) env`. A substitution in the command name, as in `$(echo cat) key.txt`, and one at a pattern or a flag's value now write a coverage record where nothing else on the line blocks. This parser change has costs, listed under **Known limits and costs**. ([#245](https://github.com/karlkfi/claude-spill-guard/pull/245))
- **A call that runs out of its 45-second budget now blocks on a secret in anything the scan finished.** The call's own text goes first and then its files, smallest first, so a key in `@notes.txt` no longer crosses because a big file sat beside it, in either order. Such a block arrives at the deadline rather than at the first finding, because the scan runs on to name every match. Files are now read when their turn comes, which cut peak memory on a six-file call to about a third. ([#244](https://github.com/karlkfi/claude-spill-guard/pull/244))
- **A secret now blocks when the same call also carries a file this build cannot decode, such as UTF-32.** Before this, `cat key.txt notes.utf32` crossed with no verdict and a coverage record naming only `notes.utf32`, and so did a key typed in the command or the prompt beside such a file. It dates from the change that made a gap defer rather than block, which shipped in v0.3.0. The block names the rule and the unread buffer. How often that pairing happens is unmeasured. ([#237](https://github.com/karlkfi/claude-spill-guard/pull/237))
- **A key in a `Read` path, or in a `Grep` pattern, path, glob or type, is now blocked, whether or not the path opens.** The `Grep` pattern used to get only a coverage record when its path would not open, such as a fifo. The same literal through `cat` was already blocked. The model wrote these values, so the API already has them. The block stops the call and tells the model. Over one machine's transcripts these fields matched no rule, in 10,075 distinct `Read` paths and 946 distinct `Grep` patterns, paths and globs, a reading taken for [#242](https://github.com/karlkfi/claude-spill-guard/pull/242) and not re-taken here. The `Grep` tool needs `--tools Grep` on that machine. ([#238](https://github.com/karlkfi/claude-spill-guard/pull/238), [#242](https://github.com/karlkfi/claude-spill-guard/pull/242))
- **A file name that holds a key no longer prints the key.** `cat dir/*` opens files whose names the model has never seen, and the deny reason naming one was where that value first reached the API. A file name, path or working directory that a rule matches is now left out of every reason, notice and coverage record, and a file so named appears as `a path a rule matches`. `_` counts as a boundary here, so `creds_<key>.csv` is covered. What still prints is under **Known limits and costs**. ([#240](https://github.com/karlkfi/claude-spill-guard/pull/240))

### Reported more accurately

- **A coverage record no longer says nothing was scanned when part of the call was.** It now says what was read, and `spill-guard coverage` no longer claims that a rule match would always have stopped the call. Records already in your log keep their old text, so a report spanning the upgrade prints separate rows for one gap. `coverage --since v0.7.0` leaves the older releases' rows out. ([#236](https://github.com/karlkfi/claude-spill-guard/pull/236))

## Upgrading

Both halves move. The binary is what changed; the plugin manifest version is what makes `claude plugin update` deliver it.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.7.0/install.sh
sh install.sh
claude plugin marketplace update spill-guard
claude plugin update spill-guard@spill-guard
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.7.0/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
claude plugin marketplace update spill-guard
claude plugin update spill-guard@spill-guard
```

The install script does not touch the plugin, so the last two lines are the half that fixes the hook command. Nothing here has run `claude plugin update` under PowerShell, and `hook-harness` does not run it, so after it check that `claude plugin details spill-guard` reports 0.7.0.

Hooks are read when a session starts, so start a new one. Then run `spill-guard selftest` and read what it says it could not establish.

**No configuration changes.** Five behaviours do:

- **A file holding a labelled SSN-shaped value is denied**, fixtures included. A `Read` has no override. A `Bash` read can take `SPILL_GUARD_OVERRIDE=<reason>`, which turns the deny into a confirmation prompt. Over 395,516 files in eight populations `us-ssn` fired in 13 (0.003%). Over 17 projects picked because an SSN field belongs there it fired in 81 of 60,637 (0.13%), peaking at 39 of 4,814 in `18F/identity-idp` (0.81%). By a path pattern, 72 of the 81 are test-, example- or docs-shaped. Those projects were picked to be adversarial, so the rates do not generalise. How many real numbers it finds is unmeasured, and no placeholder validator exists yet. Those counts were taken for [#235](https://github.com/karlkfi/claude-spill-guard/pull/235) and not re-taken here. ([Q242](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q242.md))
- **On a machine with no Git Bash, every `PowerShell` call writes a coverage record**, including one that names no file, because nothing here can tell which files a PowerShell command opens. `spill-guard coverage` counts them. By the estimate in [Q237](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q237.md), taken from one machine's `Bash` traffic because no such machine's log has been read, that rotates every other record out of the log in five or six days.
- **Updating only one half leaves a gap.** The v0.7.0 binary under the old hook command still scans nothing on Windows without Git for Windows. The v0.6.1 binary under the new hook command allows every `PowerShell` call with no record.
- **Scanning a large file costs more, and a block past the budget takes the whole 45 seconds.** **Validation** has the figures. A small hook call takes about 10 ms through the command `hooks.json` runs.
- **Some calls that were allowed are now denied even though they print no key**, and a few that denied now get a record or nothing. **Known limits and costs** lists them.

## Deprecations

None. No subcommand, flag, rule ID, environment read or output format was removed.

## Known limits and costs

Each item is a case where a value can cross or a call can be refused for the wrong reason, and each was tested unless it says otherwise. The README's [**What it does not catch**](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/README.md#what-it-does-not-catch) has the standing list, and [**A finding blocks, a gap does not**](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/README.md#a-finding-blocks-a-gap-does-not) has the 45-second budget and the `xargs` operand list. The items below are new in this release or newly stated here.

- **Other `sk-ant-` prefixes cross with no verdict, OAuth tokens among them.** The same body behind `sk-ant-oat01-`, `sk-ant-ort01-` or `sk-ant-sid01-` exits 0 through `spill-guard filter`. A key of another length does not match either. No detector consulted publishes a length for those prefixes, and nothing on the machine these notes were written on bounds one. ([Q240](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q240.md))
- **Windows was tested in one narrow way.** Only `claude -p`, on Claude Code 2.1.290, against a loopback fake of the Messages API. No interactive session was tested, and no shell prefix was tried on Windows. The hook command depends on how that version spawns a hook, and `hook-harness.yml` pins it and checks no other.
- **Files a PowerShell command opens are recorded and not read.** The `.env` refusal, the `env` dump refusal and `SPILL_GUARD_OVERRIDE=` do not reach that tool either, so a machine with no Git Bash has no override on any surface. ([Q237](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q237.md))

**A gap can still hide a key.**

- **A filesystem that stalls can defer the whole call.** A stalled `stat`, which happens before any text is matched, defers even a key in the call's own text, and a stalled read of a file smaller than the one holding the key defers too. Both were simulated in review by replacing the call, and no real stalled filesystem was tried.
- **A confirmation prompt can omit a finding.** `SPILL_GUARD_OVERRIDE=why cat key.txt .env` asks about the path and names no rule, so approving it also sends a key the prompt never mentioned. ([Q250](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q250.md))

**A name can still print a key.** `creds_<ghp_ token>.csv`, a `ghp_` token whose own `_` sits against another `_`, and `<AWS key>x.csv`, a key with a letter glued to it, still print in a deny reason. On a shell glob that can be a value the model had not seen.

**Reading substitutions moved some verdicts the wrong way.** Each row is in the table above.

- **Some shapes that denied on v0.6.1 now let a key cross, and this list is not exhaustive.** `nice $(echo /bin)/cat key.txt`, `command $(echo /bin)/cat key.txt` and `env $(echo) cat key.txt` get a coverage record. So does `$(true) cd sub; cat plain.txt` with the key in `sub/plain.txt`, because the directory move is no longer followed. `$X $(true) cat key.txt` gets nothing at all ([Q225](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q225.md)). The `.env` path refusal goes with them: `env $(echo) cat .env` gets a record and `$X $(true) cat .env` gets nothing. The `$X` deny was an accident of the old parser, which ended the command at the `$(`, and `$X cat key.txt` was already silent on v0.6.1's parser. A rough regex in the [#245](https://github.com/karlkfi/claude-spill-guard/pull/245) review found `$NAME $(`, or a backtick substitution ahead of `$(`, at a command start in 0 of 236,184 real commands on one machine. How often the other shapes occur was not counted.
- **New false blocks, where bash prints no key.** `grep $(true) key.txt` makes `key.txt` the pattern and opens nothing, but it is read as a file. `grep -r X=1 <(echo x)` reads only the pipe and is refused. `env X=$(echo a) echo cat key.txt` and `timeout $(echo 5) foo cat key.txt` deny, because a wrapper whose grammar is lost starts the command at the next reader's name ([Q254](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q254.md)). `time -p cat key.txt` denies with the hook configured for zsh, where the same command prints no key.

**A NUL in a command depends on Claude Code refusing it.** The hook skips a `Bash` or `PowerShell` command holding a NUL as binary, so a key beside the NUL is not matched when the hook is handed one directly. Claude Code refuses that call before any hook or shell runs, on the versions the [README](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/README.md#a-finding-blocks-a-gap-does-not) lists. CI re-checks only the pinned 2.1.290, so a release that delivered such a call would go unseen until somebody moves the pin. A NUL in a `Read` or `Grep` field is refused by a separate check, tested on 2.1.290 and 2.1.309, and no CI arm covers that one. ([Q246](https://github.com/karlkfi/claude-spill-guard/blob/v0.7.0/docs/queue/Q246.md))

There is still no Homebrew tap and no Scoop bucket. Both are designed and neither is built.

## The public surface

Small on purpose, and `0.x` means none of it is promised.

- **Subcommands:** `hook`, `filter`, `selftest`, `version`, `coverage`. None new, and no flag changed.
- **Rule IDs, on by default:** `aws-access-key-id`, `github-token`, `github-fine-grained-pat`, `slack-token`, `slack-webhook-url`, `stripe-live-secret-key`, `openai-api-key`, `anthropic-api-key`, `google-api-key`, `private-key-block`, `jwt`, `us-ssn`. **`anthropic-api-key` is new, and it covers Admin API keys under one ID. `us-ssn` was off.**
- **Rule IDs, off by default:** `payment-card`, `cn-resident-id`, `ipv4-public`.
- **`us-ssn`'s labels** gain `social_security` and `socialsecuritynumber`.
- **The hook matcher:** `Read|Bash|Grep|PowerShell`, where v0.6.1 had `Read|Bash|Grep`.
- **The hook command** in `hooks/hooks.json` is now one string that bash, zsh and both PowerShells parse, and its timeout is still 60 seconds. If the launcher never starts it exits 127 under PowerShell as it does under a POSIX shell, and the call goes through with a hook error on record.
- **Environment: no new reads.** The coverage record gains no field. A `Grep` path that exists and fails to open is now listed in its `Operands`, as `Read` and `Bash` already did. A fifo still lists none on `Grep`.
- **Reason strings:** one new coverage reason for a `PowerShell` call, and the sentence a coverage record opens with now has five forms, for what was read. A path a rule matches prints as `a path a rule matches`. `spill-guard coverage` rewords its header and closing line.
- **Plugin metadata:** the manifest descriptions now name US Social Security numbers. The keyword `ssn` replaces `pii`, and `fail-closed` is gone, since that stopped being true on 2026-09-05.
- **`spill-guard selftest`** runs 15 arms, where v0.6.1 ran 13. The two new ones send a `PowerShell` payload.

## Validation

<details><summary>2,758 test cases across 10 packages, 25 gates, every row in the table above run on built binaries, and scan throughput at 35.50 MB/s on the release's rule set against 94.99 on v0.6.1's</summary>

- `go test ./...` passes 2,758 cases across 10 packages, 428 top-level tests, counted from `go test -json`.
- `make check` passes all 25 gates over this tree with the version bump applied, the same set v0.6.1 ran.
- **`hook-harness` is new**, on Linux and Windows. Its fake API needs no credential and says nothing about what a real model would choose. With Git hidden on `windows-latest` it reports `Bash=False PowerShell=True`, and a mutation control shows the old hook command crossing. Its `must_refuse_nul` arms re-check Claude Code's refusal of a NUL in a command at the pinned 2.1.290.
- The precision corpus: 15 clean files producing 0 findings, 22 planted files producing exactly one finding each.
- Empty supply chain, unchanged: `go.mod` carries no `require` block, and the build graph is this module plus the standard library, reaching no `net`, `net/http` or `os/exec`.

## Security

No advisory accompanies this release. Every crossing closed here is this project's own gap, found in its own testing and review. None was reported from outside.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it.

The rest of the posture is unchanged: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.7.0/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.7.0/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.7.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.7.0_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard --signer-workflow 'karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.7.0'
```

Keep the `@refs/tags/...` suffix on the `gh` command. Without it `--signer-workflow` prefix-matches and accepts that workflow at any ref. cosign v3.1.3 prints `Flag --new-bundle-format has been deprecated` above `Verified OK`, which is a warning about the flag and not about this signature.

The provenance also travels as an asset, `spill-guard_0.7.0.intoto.jsonl`, for a consumer with no network path to the attestations API.
