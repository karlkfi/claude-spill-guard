**spill-guard keeps secrets and PII from reaching the API through a Claude Code session.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> This is a `0.x` release and the surface carries no compatibility promise. Subcommand names, rule IDs, the reason strings, and the shape of a verdict can change in the next minor.

> [!CAUTION]
> **One rule matches less than it did.** `aws-access-key-id` drops the `A3T` prefix arm, so a key beginning `A3T` is no longer matched. **Deprecations** has what the cut is and is not sourced to. Nothing else in this release narrows what is caught.

> [!NOTE]
> The scanner is **2.2x faster on the shipped ruleset** — 35.14–35.51 MB/s to 76.61–76.76 MB/s over this repository's own text — and `jwt` gained no length limit to pay for it. **Highlights** has the measurement and the control arm that makes it attributable.

## What v0.4.0 is for

**Closing edges the v0.3.0 notes published, and the one performance cliff that was left.** No new feature, no new subcommand, no new configuration.

The v0.3.0 notes ended with a list, under *What it does not read*, of every case where a credential can cross. That list is published, so it is the commitment a reader can hold this project to without a checkout, and working it down is what this release is. Three of its members are answered here — two closed, one driven from *undisclosed guess* to *measured fact*.

The second half is `jwt`, which was the eighth of eight rules opening on `\b` and the only one the loader still refused the anchored path. `eyJ` heads any base64-encoded JSON object, so it is a keyword ordinary content carries — lock files, JWKS documents, CI configuration — and each of those bought a whole-buffer scan.

Underneath both is release-path work no user sees: a signing verification that now has to prove it can *reject*, a provenance check that reads an identity rather than an exit status, and three new gates. That is named in **Validation** rather than sold as a feature.

## Highlights

- **`jwt` runs at its keyword positions, and the whole ruleset is 2.2x faster.** It was the eighth of eight rules opening on `\b` and the only one the loader refused the anchored path, because an unbounded repeat over a class covering the text reads to the end of the buffer once per keyword hit. It is now two pieces rather than one pattern: `\b(eyJ[A-Za-z0-9_-]{8})` establishes that a token starts here, and an `extent` walks forward to find where it ends, widening the capture before any check reads it. **There is no length limit on a JWT segment** — the walk terminates on any byte outside base64url, and end-of-buffer is that same terminator rather than a missing one, so it cannot run off the end.
- **The MCP file reader is driven, and it is the last member of the reader class to be.** It was disclosed as undriven in every release since v0.1.0. It is a real member — the hook sees the call as `mcp__<server>__<tool>` and a deny stops it **before the server is asked**, so it is stoppable. It stays out anyway, and the reason is sharper than expected: one server's two tools split, `read_file` bounded on a `path` and `search_tree` unbounded on a `root`, with nothing in the payload saying which arrived. **The split is inside one server**, so membership cannot be decided per server or per protocol — a per-server rule would owe those two tools opposite answers. Five `claude -p` runs on 2.1.261, every verdict read from the session transcript rather than from printed output.
- **The glob expansion's assumption is now a measurement.** v0.3.0 disclosed that the expansion follows bash's defaults on the strength of 22 of 22 shell snapshots on one machine. It is 62 of 62 now, 3,720 `shopt` lines, with a positive control — 15 options come back `-s` in every snapshot, so the parse can return non-empty. Two things fell out. **Claude Code narrows one option itself**: every Bash tool call runs `shopt -u extglob`, so that option cannot be on for a tool shell whatever your rc file says, leaving five in the residual rather than six. And **the hook cannot find the snapshot its own session sources** — no shell state in the payload, none of 55 environment variables naming one, no session id in the filename, and newest-by-mtime is wrong (the driving session's was 4th of 63). So nothing is buildable here, and the gap is bounded rather than closed.
- **`aws-access-key-id` cuts the `A3T` prefix arm.** AWS's IAM identifiers reference names twelve prefixes and `A3T` is not among them; the ruleset carried it because it was inherited rather than written. `ABIA` and `ACCA` are on that list and stay, now with the citation beside them. Four prefixes ship: `AKIA`, `ASIA`, `ABIA`, `ACCA`.
- **`private-key-block` steps over a whitespace-only separator line.** The rule crossed from header to base64 body across `[\r\n]+`, so a separator carrying a space or tab was not crossed and the key went unreported. The producer is `git diff`: unified format prefixes every context line with a space, so a blank line inside a quoted file arrives carrying exactly one — driven on git 2.55.0 rather than argued from the format spec. **Both steps widened, not the header's alone**: in an encrypted key the whitespace-only line falls after `DEK-Info:`, and a header-only fix reports three of the five new cases and misses that one and the planted patch.
- **The install scripts pin the tag when they verify with `gh`.** See **Security** — this one is a weakness in this project's own verification, and it is disclosed at length there rather than summarised here.

`BenchmarkRuleset` over this repository's own text, 1.73 MB in 196 files, `-benchtime 30x -count 3`.

## Upgrading

Both halves move. The binary is what changed; the plugin manifest version is what makes `claude plugin update` deliver it.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.4.0/install.sh
sh install.sh
claude plugin update spill-guard
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.4.0/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Two steps rather than one on purpose. The one-liner that pipes a remote script into a shell works, and for a tool whose whole pitch is that nothing leaves your machine, opening with "pipe this into your shell" undercuts the claim before you reach the second paragraph. Download it, read it, run it.

Hooks are read when a session starts, so start a new one. Then run `spill-guard selftest` and read what it says it could not establish.

**No action is required and no configuration changes.** No new subcommand, no new flag, no new environment read, no change to the coverage log's format or location, and no reason string was rewritten.

**What you will stop seeing.** Scans finish faster — 2.2x on the shipped set over ordinary text — and the effect is largest on content carrying `eyJ`, which is lock files, JWKS documents and CI configuration rather than anything unusual.

**What you may stop catching.** Nothing, except a key beginning `A3T`.

**If you read `spill-guard coverage` regularly**, nothing changes in this release: no coverage reason was added or removed. The `for`-loop and `case`-arm reasons stopped growing in v0.4.0's first half and remain closed.

## Deprecations

- **The `A3T` arm of `aws-access-key-id` is removed**, with its keyword, its test-table row and its vector. A key beginning `A3T` is no longer matched by this rule. **The cut is not sourced to a zero:** `A3T` reports 0 raw matches over 5.05 GiB of third-party Go source, and so does `AKIA` on the surviving column — exactly the reading `rules/README.md` forbids drawing an arm's death from. What settles it is that AWS does not publish the prefix. It was not settled by agreement with another scanner's ruleset either, since `docs/design/brief.md` names gitleaks as a possible origin of these rules and agreement there would be one list arriving twice.
- **Nothing else is deprecated**, and no subcommand, rule ID, environment read, or output format was removed.

## What it does not read

Each item is a case where a credential can cross. They are listed because a scanner's gaps are the only part of it a user cannot discover for themselves. v0.3.0 disclosed eleven; this is every one of them, plus what this release adds.

| Disclosed in v0.3.0 | v0.4.0 |
|---|---|
| A UTF-8 byte-order mark ahead of a NUL | **Stands.** Undeclared to the decoder, so the buffer falls through and the NUL is read raw. The call proceeds and the person is told in a notice. |
| A binary buffer on `Read` and on a `Bash` operand | **Stands.** The raw match pass is the prompt's alone, on the cost argument: 13 of the 21 binary `Bash` operands in the design corpus are the Claude Code binary, 306 MiB, 36.5 seconds of match loop. |
| A recursive read | **Stands.** A walk reads a different file set from the one the command would send — over one checkout `rg --files` reports 211 where a walk finds 11,815. The call proceeds with nothing scanned and a record. Name the files. |
| A secret synthesized at runtime, other than a bare `env` | **Stands.** Structural: nothing to open at `PreToolUse`, and `PostToolUse` cannot withhold a result. |
| An MCP server's file reader | **Stands, now driven.** The hook sees the call and a deny stops it before the server is asked — so it is stoppable. What keeps it out is that one server's tools split: `read_file` names one file, `search_tree` names a directory, and nothing in the payload says which arrived. `hooks.json` matches `Read\|Bash`, so an MCP server's reads are not scanned. |
| A command with no reader row | **Stands.** A command absent from the table is scanned as a string and no further. |
| A queued substitution body starts with an empty variable map | **Closed.** A body now starts from the map, the directory and the glob options in force where it was **written**, one marked walk recording all three, so `SP=/x; echo $(cat $SP/f)` resolves like the plain spelling beside it. 2,204 bodies in 1,405 of 163,719 real commands gain coverage that way. The map at the *end* of the string stays refused rather than seeded — it would open a file an assignment after the body named. |
| A quoted assignment is read as one where bash runs a command | **Closed.** The upstream this was blocked on landed (`claude-bouncer` #110), and the lexer here now carries each token's quote provenance beside it, so `'SP=/x'` names a program rather than assigning and `'SPILL_GUARD_OVERRIDE=x'` no longer arms the hatch. The same reading covers a quoted reserved word. A quoted *glob* still expands, which is the row below. |
| A `case` arm is read as unconditional | **Closed.** Conditional now, so a variable assigned only inside one is recorded rather than resolved to a path bash may never have used. |
| A `for` loop's variable is poisoned | **Closed.** Bound to its literal list, which is the port upstream already had. |
| The glob table is one machine's shell options | **Stands, bounded to five options.** 62 of 62 snapshots leave all six unset, with a positive control on the zero. Claude Code runs `shopt -u extglob` itself on every Bash call, so that one cannot be on regardless. The residual stands because **the hook cannot find its own session's snapshot** — nothing in the payload, the environment or the filename identifies it — so this is not buildable rather than not done. |
| A credential-file read through an interpreter, or through `env -0` | **Stands**, and is the stated under-fire rather than a hole to widen into: firing on the careful form would be the defect. |
| `!` bash mode is not a tool call | **Stands.** `PreToolUse` never sees it — over 1,661 transcripts, 62 such entries, 0 carrying a `toolUseID`. Whether `UserPromptSubmit` fires for it is unmeasured and needs a pty. |

What this release adds to the list:

- **An append assignment as a command prefix.** `LC_ALL+=C cat k.env` reads the file and this writes no verdict at all: `assignmentRE` does not match `NAME+=`, so the prefix is never peeled and the command behind it is never found. Driven against two controls that deny. Pre-existing and previously undisclosed rather than new in this release — found reviewing the quoted-prefix port, because upstream had already fixed it in a commit that port did not read. Filed as Q168.

- **A zsh tool shell.** One of the 63 snapshots measured is zsh and carries no `shopt` line at all, and `internal/bash` is a port of a bash segmenter throughout. Filed, not driven.

There is still no Homebrew tap and no Scoop bucket. Both are designed and neither is built, so a machine with neither `cosign` nor `gh` has no route that verifies for it — the install scripts refuse on such a machine rather than falling back to the checksum, because `checksums.txt` comes from the same place the archive did and answers corruption, not substitution.

## The surface this freezes

Small on purpose, and `0.x` means none of it is promised. **Nothing here is new since v0.3.0** — no subcommand, flag, environment read or output format was added.

- **Subcommands:** `hook`, `selftest`, `version`, `coverage`. None takes a flag.
- **Rule IDs, on by default:** `aws-access-key-id`, `github-token`, `github-fine-grained-pat`, `slack-token`, `slack-webhook-url`, `stripe-live-secret-key`, `openai-api-key`, `google-api-key`, `private-key-block`, `jwt`. **Three of these changed what they match** — `aws-access-key-id`, `private-key-block` and `jwt` — and none changed its ID.
- **Rule IDs, off by default:** `payment-card`, `us-ssn`, `cn-resident-id`, `ipv4-public`.
- **A finding reports the rule ID, the path, and the byte offset. Never the value, and not a redacted fragment either**, because the refusal text reaches the API as well.
- **Environment:** `SPILL_GUARD_BIN` for the launcher; the binary reads `HOME`, `TMPDIR`, `XDG_STATE_HOME`, `CDPATH`, `GIT_DIR`, `GIT_WORK_TREE` and `GIT_CEILING_DIRECTORIES`. `SPILL_GUARD_OVERRIDE=` is not in this list, because it is a command-position prefix on a `Bash` command and is never read from the environment — a property `internal/hook/override.go` went out of its way to have, and which the design doc denied in one line until this release.
- **Reason strings**, which the model reads and a script might match on: **unchanged this release.**

## Validation

<details><summary>1,419 test cases across 10 packages, 22 gates each paired with a job that breaks it, and 13 selftest arms of which 5 must allow and 1 must defer</summary>

- `go test ./...` passes 1,419 cases across 10 packages, 288 top-level tests. v0.3.0 shipped 1,267 across 9.
- **22 gates run on every pull request, three more than v0.3.0.** `release-scope` retires a release-scope record when its tag is cut. `release-notes` re-reads a published release body against its notes file, and binds on `main` rather than on a pull request, because while an edit is open the divergence *is* the proposal. `self-scan` requires every tracked file that trips the scanner to be an explicit decision — two corpus regions plus a named list — and its stale-entry check fails on an allowlist entry that no longer matches, so an exemption cannot outlive the thing it excused. `tests.yml` carries 45 jobs: each gate, a mutation control that breaks the property and requires the gate to go red, and one control over `make check` itself.
- **A separate workflow runs the harness rather than the tree.** `prompt-oracle` re-drives `internal/hook/testdata/prompt-oracle.json` — Claude Code's own answer to the `@`-token grammar — against a pinned `claude` on every pull request. It needs no credential, because the harness resolves `@` tokens and writes the transcript before it makes an API call. **24 of 24 cases agree at 2.1.261 against a census recorded at 2.1.238**, so the grammar has not drifted across those releases.
- The precision corpus: 13 clean files producing 0 findings, **16** planted files producing exactly one finding each. The new one carries a 2,647-byte payload segment, which is what pins the recall the removed ceiling would have cost.
- **The rule schema's new `extent` field has a closed vocabulary**, which is what keeps it from becoming a seam that grows sideways. The loader accepts exactly one name, `jwt-token`, and refuses any other — pinned by a test — and the pipeline fails closed on a name it does not run rather than skipping the rule. It is internal structure rather than surface: there is no user-writable ruleset, since `.claude/spill-guard.json` was retired in v0.3.0.
- **The release path's verification has to prove it can reject.** `scripts/check-signature-identity.py` verifies `checksums.txt` and then requires three identities the release was not signed under — a branch, another workflow, a fork — to be rejected **on the identity**. That clause is the point: an empty `--certificate-identity` also exits non-zero, so a control reading only the exit status is satisfied by a cosign that never looked at the bundle. `scripts/check-attestation-identity.py` does the same for provenance, reading the certificate subject out of `--format=json`, because `gh attestation verify` prints nothing at all once its output is redirected — exit 0, zero bytes.
- **Those checks run on a pull request, against the last published release.** A branch has no signature of its own, so `published-release-verify` asserts about a previous release instead. No published release is a failure and not a skip, because a skipped job reports no check at all and that reads exactly like one that passed.
- Empty supply chain, unchanged: `go.mod` carries no `require` block at all, and the build graph is this module plus the standard library, reaching no `net`, `net/http`, or `os/exec`. Three gates enforce it on the import graph.
- `govulncheck` reports no known vulnerability the build graph calls.
- All five shipped targets cross-compile from one runner: `darwin/arm64`, `darwin/amd64`, `linux/amd64`, `linux/arm64`, `windows/amd64`.
- **What no gate reaches, said here rather than implied:** the MCP drive, the shell-snapshot survey and every transcript measurement in these notes are drives against a live harness on one machine. No `make` target re-runs one. A green run proves the tree, not the readings.

## Security

No advisory accompanies this release, and nothing here patches a reported vulnerability. What follows is a weakness in this project's own release verification, found and fixed in the same release, disclosed because a user who verified a v0.3.0 download with `gh` got less than the documentation promised.

**Both install scripts passed `--signer-workflow` without a ref.** That flag matches the certificate subject as a prefix, so the bare `<owner>/<repo>/.github/workflows/release.yml` accepted an attestation minted by that workflow at **any ref** — a branch, or a tag other than the one being installed. The `cosign` branch beside it pinned the tag correctly, and the scripts verify with whichever tool is present, so which check you got depended on which tool your machine happened to have.

Measured against the published v0.3.0 attestation: the bare form exits 0, `@refs/tags/v0.3.0` exits 0, and `@refs/heads/main` exits 1 — so appending the ref is what pins it. Both scripts now do, and both verifiers assert the same string.

**What this was and was not.** Exploiting it would have required an attacker who could already mint an attestation from this repository's release workflow at another ref, and then substitute an archive on this repository's releases. It is a weaker check than documented rather than an open door, and no evidence suggests it was used. It is disclosed at this length because the whole claim of the verification step is that a signature minted somewhere else is rejected, and for `gh` users that claim was broader than what ran.

**One thing the MCP drive establishes about the hook's reach**, worth stating precisely because the two halves are easy to conflate: an MCP server's file read **can** be stopped — the hook sees it and a deny lands before the server is asked — but `hooks.json` matches `Read|Bash`, which no `mcp__…` name matches. So the hook is not powerless on that surface; it is not pointed at it. The design records that rather than fixing it.

The rest of the posture is unchanged: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too, so the script you fetch in order to read it can also be checked:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.4.0/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool — `cosign` needs the bundle downloaded alongside `checksums.txt`, `gh` fetches what it needs itself:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.4.0/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.4.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.4.0_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard --signer-workflow 'karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.4.0'
```

**The `gh` command carries the ref for the reason `install.sh` now does.** Without the `@refs/tags/...` suffix, `--signer-workflow` prefix-matches and accepts that workflow at any ref. **Security** has the measurement.

The provenance also travels as an asset, `spill-guard_0.4.0.intoto.jsonl`, for a consumer with no network path to the attestations API.
