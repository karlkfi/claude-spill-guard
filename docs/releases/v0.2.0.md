**spill-guard keeps secrets and PII from reaching the API through a Claude Code session.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> This is a `0.x` release and the surface carries no compatibility promise. Subcommand names, rule IDs, and the shape of a verdict can change in the next minor.

> [!CAUTION]
> A buffer this build cannot decode is still **allowed**, not blocked, and reported in a notice. One case remains: a file behind a UTF-8 byte-order mark with a NUL in its first 8 KiB. **What it does not read** below has it, with the trigger that would close it. Nothing here is a wall against someone who means it — the escape hatch is one environment variable.

## What v0.2.0 is for

Closing the gaps [the v0.1.0 notes](https://github.com/karlkfi/claude-spill-guard/releases/tag/v0.1.0) disclosed. That list is the commitment a reader can hold this project to without a checkout, so whether the scope held is read off the diff between the two **What it does not read** sections rather than off anyone's account of the release.

Six cases were disclosed there, plus one of a different kind added by errata. **Five are closed, one is answered with its reason and stands, and one is deferred on an argument.**

| v0.1.0 disclosed | v0.2.0 |
|---|---|
| A block does not carry the unread-buffer notice | **Closed.** Every verdict over a call carrying a buffer nothing read names that buffer, block or allow. |
| A binary-looking `@` target in a prompt | **Closed on that surface.** The prompt now matches the raw bytes. `Read` and `Bash` still skip them, on a measured cost. |
| Readers outside the three that are driven | **Closed as a class.** Driven and answered per tool: a subagent load is already covered, a search tool and a skill load stay out for two different reasons, and an MCP file reader is the one member still undriven. |
| A secret synthesized at runtime | **Closed for `env`.** A bare environment dump is refused on its shape, with the reason carrying the filtered form. |
| A recursive read | **Answered, and the refusal stands.** A walk reads a different file set from the one the command would send. |
| A UTF-8 byte-order mark ahead of a NUL | **Deferred**, on the argument below. |
| *(errata)* A scan the harness kills at 60 seconds | **Closed.** The scan has a 45-second budget of its own and blocks at the end of it. |

## Highlights

- **A scan that runs long now blocks instead of vanishing.** `hooks/hooks.json` gives this process 60 seconds; past that Claude Code kills it, discards the verdict, and the call proceeds with nothing in the transcript. The scan gets 45 of those seconds and writes a block at the end of them — the same verdict a buffer nothing could read already gets, downgradeable by an override like any other. Driven on built binaries: a 500 MiB fixture that took 68.130s on the build before this change, 8 seconds past the ceiling, blocks at 45.011s, while a 128 MiB one denies on the same rule either side.
- **A bare environment dump is refused on its shape.** `env` writes values that exist only in the tool process, so at `PreToolUse` there is nothing to open and no rule can help. The call is refused instead, and the reason carries the filtered form so the model applies it and nobody is prompted. The bar it had to clear is that it must not fire on the careful form: **0 refusals over 21,252 real `Bash` calls**, against 15 of 15 on planted dumps, with 5,380 of those real segments carrying a command name the rule knows. What decides it is position in the pipeline — `env | cut -d= -f1` has a stage after it and `env` does not.
- **A binary `@` target in a prompt is matched rather than skipped.** `@heap.dump` arrives carrying the whole file, NUL included. The match loop now runs over the raw bytes on that surface and returns the skip reason beside the findings rather than instead of them. Over 4,000 real binaries — 1,414.7 MiB — the raw pass returned 0 findings at 17.4 MiB/s, and a 54-byte fixture holding a key returned 1, so that zero is a measurement rather than an absence.
- **A block carries the unread-buffer notice too.** In v0.1.0 a call with findings in one buffer and an unread buffer in another reported the findings only, so the refusal's coverage sentence was true of what it read and not of the call. Which channel carries it is per event and was measured: a `systemMessage` survives beside a `PreToolUse` deny and is dropped beside a `UserPromptSubmit` block, where the block reason is itself shown to the person.
- **A rule's entropy ceiling reads the group's alphabet, not just its length** — a precision fix in the matcher, not a new rule.

## Upgrading

Both halves move. The binary is what changed; the plugin manifest version is what makes `claude plugin update` deliver it.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.2.0/install.sh
sh install.sh
claude plugin update spill-guard
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.2.0/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Two steps rather than one on purpose. The one-liner that pipes a remote script into a shell works, and for a tool whose whole pitch is that nothing leaves your machine, opening with "pipe this into your shell" undercuts the claim before you reach the second paragraph. Download it, read it, run it.

Hooks are read when a session starts, so start a new one. Then run `spill-guard selftest` and read what it says it could not establish.

**One behaviour change worth expecting.** A `Bash` call whose scan outlives 45 seconds now blocks where it previously went through. Where that lands is not a fixed size: the measured rate on keyword-bearing text is 6.5 MiB/s on an M5 Max, which puts the crossing near 290 MiB in one call, and the same 45 seconds is 47 GiB of binary or 4.6 GiB of inert text. It scales with single-core speed, so a slower machine crosses lower. The refusal names the budget, and `SPILL_GUARD_OVERRIDE=<reason>` in command position downgrades it to a confirmation.

## What it does not read

Every item here is measured, and each one is a case where a credential can cross. They are listed because a scanner's gaps are the only part of it a user cannot discover for themselves.

- **A UTF-8 byte-order mark ahead of a NUL.** `EF BB BF` is a declaration the decoder has no arm for, so the buffer falls through undecoded, the NUL is read raw, and the file is skipped as binary. PowerShell's `Out-File -Encoding utf8BOM`, Notepad, and Visual Studio all write that mark. Deferred on its own argument rather than by oversight: the notice covers the whole residual class where a third decode arm would cover one member of it. What would revive it is a measurement showing the mark occurring organically on a machine this runs on — the census that exists today covers UTF-16 marks and found none decoding to binary. On a prompt the raw pass reaches such a file's contents anyway, which closes the consequence on one surface and none of the reason: a `Read` of the same file still exits 0 with a notice.
- **A binary buffer on `Read` and on a `Bash` operand.** The raw match pass is the prompt's alone, and that is a cost decision rather than a policy one. 13 of the 21 binary `Bash` operands in the design corpus are the Claude Code binary itself — 306 MiB, 36.5 seconds of match loop against a 60-second timeout — where no organic binary `@` target has been observed in 881 tokens. Both cases are reported in a notice.
- **A recursive read.** `grep -rn pat docs/` names a directory, and this reads files rather than walking them, so the call is **refused** rather than allowed. That refusal is now decided rather than pending. A walk reads a different file set from the one the command would send: ripgrep honours `.gitignore` and `.ignore` and skips hidden files where `grep -r` does none of that, so over one checkout `rg --files` reports 211 where a walk finds 11,815 and 1,132 findings in them. Blocking a call over content that was never going to cross is a false positive, and precision is the product. Name the files instead.
- **A secret synthesized at runtime, other than a bare environment dump.** `env` is refused on its shape now. Anything else that produces bytes existing only in the tool process is unchanged and structural: there is nothing to open at `PreToolUse` and nothing to match, and `PostToolUse` cannot withhold a result.
- **An MCP server's file reader.** The one member of the reader class still undriven. The other three are settled: a subagent load needs nothing, because the subagent's own tool calls fire the same hooks the parent's do; a search tool stays out, because nothing a `PreToolUse` hook opens can bound a walk over a tree; and a skill load names no file in its payload, so this is a member the design cannot resolve rather than one that is not there.
- **A command with no reader row contributes no operands.** The per-command table decides which token of a segment is a path, and a command absent from it is scanned as a string and no further.

There is still no Homebrew tap and no Scoop bucket. Both are designed and neither is built, so a machine with neither `cosign` nor `gh` has no route that verifies for it — the install scripts refuse on such a machine rather than falling back to the checksum, because `checksums.txt` comes from the same place the archive did and answers corruption, not substitution.

## What it does not finish

**Closed.** This section existed in the v0.1.0 notes because a scan still running at the 60-second timeout was killed, its verdict discarded, and the call allowed with no notice — the one disclosed crossing that told the person nothing, because the process is killed before it can write.

The scan now has 45 seconds and blocks at the end of them. The margin is not sized to the measured cost of writing a verdict — that is 7.02ms at best over 30 runs for the invocation, and under 37ms for the verdict itself on a machine carrying twice as many CPU-bound goroutines as it has cores. It is sized so that being wrong about those numbers costs nothing, because what they cannot bound is scheduling on somebody else's machine.

**A size cap is not the cheaper version of this**, and that is measured rather than argued: cost is not a function of size — the same 64 MiB is 9,746 MiB/s as binary, 1,055 MiB/s as inert text and 6.5 MiB/s as keyword-bearing text — a call adds up rather than arriving one file at a time, and a directory operand has no size to cap at all.

`TestTheBudgetFitsInsideTheTimeoutTheManifestGives` holds the Go constant against `hooks/hooks.json` in both directions. They are two numbers in two files that cannot read each other, and a budget at or above the timeout is the original fail-open wearing a smaller number.

## The surface this freezes

Small on purpose, and `0.x` means none of it is promised. **Unchanged from v0.1.0** — no subcommand, flag, rule ID, or verdict field was added, renamed, or removed.

- **Subcommands:** `hook`, `selftest`, `version`. No flags.
- **Environment:** `SPILL_GUARD_BIN` tells the launcher where the binary is. `SPILL_GUARD_OVERRIDE=<reason>` downgrades a block to a confirmation, and is read only from an inline assignment prefix on a `Bash` command — never from the environment, and never from anything the model can write inside a scanned file.
- **Rule IDs, on by default:** `aws-access-key-id`, `github-token`, `github-fine-grained-pat`, `slack-token`, `slack-webhook-url`, `stripe-live-secret-key`, `openai-api-key`, `google-api-key`, `private-key-block`, `jwt`.
- **Rule IDs, off by default:** `payment-card`, `us-ssn`, `cn-resident-id`, `ipv4-public`.
- **A finding reports the rule ID, the path, and the byte offset. Never the value, and not a redacted fragment either**, because the refusal text reaches the API as well.

What did change is what a refusal can say: two new reason bodies, one naming the budget and one naming a shape that cannot be scanned. Neither names the override, and two tests hold that line — the model reads these strings.

- 18 gates run on every pull request, and `tests.yml` carries 39 jobs: each gate, a mutation control that breaks the property and requires the gate to go red, and one control over `make check` itself. A check that has never failed is a claim rather than evidence.

## Security

No advisory accompanies this release. What it carries is the posture, unchanged: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string, since paths and rule descriptions both reach a terminal.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too, so the script you fetch in order to read it can also be checked:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.2.0/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool — `cosign` needs the bundle downloaded alongside `checksums.txt`, `gh` fetches what it needs itself:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.2.0/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.2.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.2.0_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard
```

The provenance also travels as an asset, `spill-guard_0.2.0.intoto.jsonl`, for a consumer with no network path to the attestations API.
