**spill-guard keeps secrets and PII from reaching the API through a Claude Code session.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> **Upgrade if you are on v0.4.1.** Three `Bash` spellings read a credential file with no verdict and no coverage record: an append prefix (`LC_ALL+=C cat <key>`), a subscripted prefix (`FOO[0]=x cat <key>`), and, where Claude Code's tool shell is zsh, a `**` glob that zsh recurses and bash does not. A private key added or removed in a unified diff was not reported either. All four are closed here.

> [!NOTE]
> This is a `0.x` release and the surface carries no compatibility promise. Two environment reads are new, `CLAUDE_CODE_SHELL` and `SHELL`, and the path one of them holds is now written into a coverage record. **The surface this freezes** has the detail.

## What v0.5.0 is for

**Closing fail-opens, and reading the shell Claude Code actually runs.** No new subcommand, no new flag, no new configuration.

Every expansion here was bash's, and Claude Code runs zsh unless `CLAUDE_CODE_SHELL` or `SHELL` names bash. The two shells expand most patterns identically and a few very differently, so this release reads which shell the `Bash` tool will use and stops guessing where they disagree.

The tag was held once, on 2026-09-26. The first fix for zsh refused every glob outside bash, so on a zsh machine `cat *.env` over a key went from a block on v0.4.1 to no verdict. That shipped nowhere: the narrower fix below replaced it before the tag.

## Highlights

- **Two command prefixes no longer hide the reader behind them.** Bash peels `NAME+=value` and `NAME[sub]=value` off the front of a command and runs what follows, so `LC_ALL+=C cat <key>` and `FOO[0]=x cat <key>` both print the file. Here each prefix was read as the command name, which has no reader row, so the file was never opened and nothing was recorded. Both now block, naming the rule. A subscripted `SPILL_GUARD_OVERRIDE[0]=` does not arm the escape hatch, because as a prefix bash sets nothing from it.
- **On a zsh tool shell, a glob is expanded where zsh agrees with bash and refused where it does not.** 37 patterns were driven through both shells: 30 give the same files, and the other 7 either read nothing in either shell or read a superset here. What zsh reads differently defers with a coverage record: a `**` operand, which zsh recurses; a `(` glued to a word, such as `*(D)`, which zsh reads as a glob qualifier that can add files; and an option change anywhere in the command, such as `setopt globdots` or `set -o globdots`. Any other shell, and a machine where nothing names a shell, refuses every glob.
- **`private-key-block` steps over a unified diff's `+` and `-`.** A key added or removed in a commit reaches a session through `git diff`, `git show` and a `.patch` file, and in either direction it crossed unreported. A plain key on added lines was matched by accident, because `+` is in the base64 alphabet. An encrypted key on added lines, and any key on removed lines, was not.
- **A command bash cannot run no longer blocks.** `n=LC_ALL; $n=C cat <key>` blocked over a file bash never opens: bash decides what a word is before it expands anything, so it looks for a program literally called `LC_ALL=C` and reads nothing. This is a precision fix. Nothing crossed that should not have.
- **A scan whose budget is already spent always defers.** Before, the deadline raced the scan to the verdict, and once the race was entered the scan won it 50.2% of the time, as measured when the defect was filed, so two identical calls at an exhausted budget could get different answers.

## Upgrading

Both halves move. The binary is what changed; the plugin manifest version is what makes `claude plugin update` deliver it.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.5.0/install.sh
sh install.sh
claude plugin update spill-guard
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.5.0/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Hooks are read when a session starts, so start a new one. Then run `spill-guard selftest` and read what it says it could not establish.

**No action is required and no configuration changes.**

**Which shell you have decides what changes.** Claude Code takes `CLAUDE_CODE_SHELL`, then `SHELL`, each only where the path names bash or zsh and is executable, and otherwise tries zsh first. If you want the tool shell to be bash, set `CLAUDE_CODE_SHELL` to your bash's path in `settings.json`.

- **Under bash**, glob handling is unchanged.
- **Under zsh**, `spill-guard coverage` gains records for the shapes above, where v0.4.1 wrote nothing. Two of them cost a scan bash would get: a glob after `set` with any flag, such as `set -euo pipefail; cat *.txt`, and a glob after a command whose name is still a variable, such as `"$X" run; cat *.env`. Both defer, and the file crosses as it would with no hook.
- **Under any other shell, or none**, every glob operand defers.

**What you may stop seeing:** a block on `n=LC_ALL; $n=C cat <file>` and its spellings, which bash never runs.

## Deprecations

None. No subcommand, rule ID, environment read or output format was removed.

## What it does not read

Each item is a case where a credential can cross. The v0.4.0 list stands, with the changes below. `docs/releases/v0.4.0.md` carries it in full.

| Disclosed before | v0.5.0 |
|---|---|
| An append assignment as a command prefix (v0.4.0) | **Closed.** |
| A zsh tool shell, filed and not driven (v0.4.0) | **Globbing driven and narrowed**, as above. Everything else this hook resolves is still read as bash, and the three shapes below are what that has cost so far. |

New in this list, every one of them present on v0.4.1 too. Each was driven, and each exits 0 with no verdict and no coverage record while the shell reads the key:

- **A wrapper in front of a reader.** `command cat <key>`, `command -p cat`, `exec cat`, `nice cat` and `nohup cat`. The wrapper has no reader row, so the command behind it is never found. `time cat <key>` blocks, because `time` is a reserved word and is peeled.
- **A substituted command.** `V="cat <key>"; $V`. Bash word-splits the value and runs `cat`; here a substituted value stays one token.
- **A subscript the lexer splits.** `FOO[$((1+1))]=x cat <key>`, `FOO[a b]=x cat <key>` and two spellings with a quoted or escaped `]`. The ordinary subscripts above are closed. These four are held by a test that fails when they close.
- **Three zsh patterns the segmenter splits as bash operators.** `cat (k1|zz).env`, `cat k<1-1>.env` and `cat a.txt(P:k1.env:)`. They never reach the glob check at all.
- **A standalone `CDPATH` assignment.** `CDPATH=/elsewhere; cd sub && cat key.env` is scanned against `./sub/key.env`, while bash reads `/elsewhere/sub/key.env` when both exist. Unlike the others this one gets a verdict, but it is a verdict on the wrong file. The inline form, `CDPATH=/elsewhere cd sub`, defers correctly.
- **Two diff shapes `private-key-block` does not cross.** A hunk header (`@@ -20,3 +20,4 @@`) between a key's header and its body, and a combined diff's second marker column, such as `++` or ` -` on an encrypted key. The first is what `git diff` writes when a change sits within three lines of a key.

There is still no Homebrew tap and no Scoop bucket. Both are designed and neither is built.

## The surface this freezes

Small on purpose, and `0.x` means none of it is promised.

- **Subcommands:** `hook`, `selftest`, `version`, `coverage`. Unchanged. None takes a flag.
- **Rule IDs, on by default:** `aws-access-key-id`, `github-token`, `github-fine-grained-pat`, `slack-token`, `slack-webhook-url`, `stripe-live-secret-key`, `openai-api-key`, `google-api-key`, `private-key-block`, `jwt`. **One changed what it matches**, `private-key-block`, and its ID did not change.
- **Rule IDs, off by default:** `payment-card`, `us-ssn`, `cn-resident-id`, `ipv4-public`.
- **Environment: two new reads.** The binary now reads `CLAUDE_CODE_SHELL` and `SHELL`, beside `HOME`, `TMPDIR`, `XDG_STATE_HOME`, `CDPATH`, `GIT_DIR`, `GIT_WORK_TREE` and `GIT_CEILING_DIRECTORIES`. Neither shell is spawned, since nothing here runs a shell. `SPILL_GUARD_OVERRIDE=` is still a command-position prefix on a `Bash` command and is never read from the environment.
- **The coverage record carries a shell path.** It is the first environment value whose content reaches a record. Only the path, and only on a call that was already being recorded, because a record saying a glob went unexpanded over a shell it does not name is one nobody can act on. `PRIVACY.md` states it.
- **Reason strings: new ones, none rewritten.** Four coverage reasons are added, one per way a glob is refused over the shell: no shell names bash, the shell is neither bash nor zsh, zsh recurses `**`, and zsh reads a glued `(` as a qualifier.

## Security

No advisory accompanies this release. The four closed crossings in the banner are this project's own gaps, found in review and in its own drives. None was reported from outside, and no evidence suggests any was used.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it.

The rest of the posture is unchanged: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.5.0/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.5.0/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.5.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.5.0_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard --signer-workflow 'karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.5.0'
```

Keep the `@refs/tags/...` suffix on the `gh` command. Without it `--signer-workflow` prefix-matches and accepts that workflow at any ref.

The provenance also travels as an asset, `spill-guard_0.5.0.intoto.jsonl`, for a consumer with no network path to the attestations API.
