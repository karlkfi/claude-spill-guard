**spill-guard keeps secrets and PII from reaching the API through a Claude Code session.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> **Upgrade if you are on v0.5.0.** Eleven `Bash` shapes driven for these notes read a credential file on v0.5.0 with no verdict and no coverage record: a reader behind a wrapper (`command cat`, `timeout 5 cat`, `env A=1 cat`), a `#` that bash reads as text, a `$'…'` string ahead of the reader, a quoted `#` inside a substitution, and a `CDPATH` assigned earlier in the command, directly or through a `declare -n` nameref. A recursive `grep` sent its output unscanned, and a key beside an operand the hook could not resolve crossed too. All of them block or defer here.

> [!NOTE]
> **A recursive `grep` over a directory is now refused** unless its output runs through the new `spill-guard filter`. The refusal names the exact command to run instead, so a session applies it and nobody is prompted, but each unfiltered call costs a turn. This is a `0.x` release and the surface carries no compatibility promise. **The surface this freezes** has the detail.

## What v0.6.0 is for

**Closing the fail-opens found since v0.5.0, and scanning the output of the one search the hook could not bound.** It is a minor rather than a patch because it adds a subcommand, two `coverage` flags and four coverage-record fields.

## Highlights

- **A recursive grep is scanned through a filter on its own output.** A grep's directory operand was the largest class in the coverage log: 1,361 of 2,400 records from 2026-09-07 to 2026-10-01, by the count taken when the work was filed and not re-taken here. The hook cannot scan the files a walk would read, because grep and a walk read different file sets, but it can scan what grep prints. So `grep -rn pat dir` is now denied, and the reason carries the same command with `set -o pipefail;` ahead of it and `spill-guard filter` as its last stage. The filter writes the output unchanged when nothing matches and writes nothing when something does, exiting 3, which `pipefail` reports apart from grep's own 0, 1 and 2. `--redact` writes the output with each value replaced by the rule's name instead. `-l`, `-L`, `-c` and `-q` print no matched text and stay allowed bare. A recursive grep with no operand searches `.`, and used to cross with nothing recorded. ([#191](https://github.com/karlkfi/claude-spill-guard/pull/191))
- **`private-key-block` crosses grep's per-line prefix.** grep opens each line with `path:N:` or `path-N-`, so a PEM key printed by `grep -rn -A30 'PRIVATE KEY' .` went through the filter in full. It now blocks under every prefix grep writes. In the sweep its pull request ran, the rule matched 834 keys in the raw files, 0 of them in grep's output before the fix and 827 after it. ([#204](https://github.com/karlkfi/claude-spill-guard/pull/204))
- **A gap no longer hides a finding beside it.** When one operand could not be resolved, the hook discarded everything it had already read, so `echo <key>; cat $X` and a prompt carrying a key beside an unresolvable `@` token both exited 0 with no verdict. The walk now goes on past the gap, scans what it could read, and blocks on a match, with a notice saying part of the call went unread. A call where nothing readable matched defers exactly as before. ([#198](https://github.com/karlkfi/claude-spill-guard/pull/198))
- **A reader behind a wrapper is found.** `command`, `exec`, `nice`, `nohup`, `env`, `sudo`, `timeout`, `stdbuf`, `/usr/bin/time` and ten more run the next word as the command, and here they were looked up by their own name, which has no reader row. Nineteen wrappers are now peeled first, ported from upstream workspace-guard. `xargs`, and a wrapper whose own options cannot be read, defer, because the reader's operands are unknowable. `builtin cat` stays silent, because bash runs no reader for it. ([#202](https://github.com/karlkfi/claude-spill-guard/pull/202))
- **Six more shell readings now match bash.** A `#` inside a backtick span, inside `${…}` or straight after `$(…)` no longer starts a comment ([#206](https://github.com/karlkfi/claude-spill-guard/pull/206)). A `$'…'` word is read as the word bash decodes it to, which resolves `cat $'k.env'` and stops `echo $'it\'s'` costing every reader in the call ([#207](https://github.com/karlkfi/claude-spill-guard/pull/207)). A `"` inside a substitution inside double quotes no longer closes the outer string, which cost the call on the common `git commit -m "$(printf …)"` idiom ([#199](https://github.com/karlkfi/claude-spill-guard/pull/199)). A `cd` inside a subshell is followed for the segments inside it and dropped at its close ([#200](https://github.com/karlkfi/claude-spill-guard/pull/200)). A `CDPATH` assigned anywhere earlier in the string loses the directory, where before the hook scanned the local copy while bash read the `CDPATH` one ([#203](https://github.com/karlkfi/claude-spill-guard/pull/203)), and so does a `declare -n` nameref, which can assign `CDPATH`, `IFS` or a tracked variable under another name ([#205](https://github.com/karlkfi/claude-spill-guard/pull/205)).
- **A coverage record says which call wrote it, and which build.** Each record now carries `session_id`, `cwd`, the `operands` that could not be read, and the binary's `version`. `spill-guard coverage` reads the rotated log as well as the current one, `--since` takes a time or a version (`coverage --since v0.6.0` counts only what this release or later wrote), and `--file` reads one log. ([#189](https://github.com/karlkfi/claude-spill-guard/pull/189), [#192](https://github.com/karlkfi/claude-spill-guard/pull/192), [#193](https://github.com/karlkfi/claude-spill-guard/pull/193))

## Upgrading

Both halves move. The binary is what changed; the plugin manifest version is what makes `claude plugin update` deliver it.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.0/install.sh
sh install.sh
claude plugin marketplace update spill-guard
claude plugin update spill-guard
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.0/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Hooks are read when a session starts, so start a new one. Then run `spill-guard selftest` and read what it says it could not establish.

**No configuration changes.** One behaviour does:

- **A recursive grep over a directory is denied.** The reason names the command to run instead, with the absolute path of this binary as the filter, so the model reruns it and you are not asked. If you run such a grep yourself through `!` bash mode, the hook never sees it.
- **The hook now matches a `Grep` tool as well as `Read` and `Bash`.** No session on the machine these notes were written on has one, so this is wired ahead of evidence it exists.
- **Coverage records written by v0.5.0 carry no version.** `coverage --since v0.6.0` leaves them out and counts them on a line of their own rather than guessing which side they fall on.
- **`spill-guard selftest` no longer writes a record into your coverage log**, and passes under a relative `TMPDIR`, where 8 of its 13 checks failed. Records it already wrote stay until the log rotates or you delete it. ([#190](https://github.com/karlkfi/claude-spill-guard/pull/190))
- **`install.sh` and `install.ps1` no longer say the hook will find a binary installed with `--dir`.** It does not look there. They now print the `SPILL_GUARD_BIN` or `PATH` setting the hook needs. ([#184](https://github.com/karlkfi/claude-spill-guard/pull/184))

## Deprecations

None. No subcommand, flag, rule ID, environment read or output format was removed.

## What it does not read

Each item is a case where a credential can cross. The v0.5.0 list stands, with the changes below. `docs/releases/v0.5.0.md` carries it in full.

| Disclosed in v0.5.0 | v0.6.0 |
|---|---|
| A wrapper in front of a reader | **Closed**, as above. |
| A standalone `CDPATH` assignment | **Closed.** It defers with a coverage record instead of scanning the wrong file. |
| A substituted command, `V="cat <key>"; $V` | Still open. |
| A subscript the lexer splits, such as `FOO[a b]=x cat <key>` | Still open, and `FOO[a #b]=x cat <key>` joins it. |
| Three zsh patterns the segmenter splits as bash operators | Still open. |
| Two diff shapes `private-key-block` does not cross | Still open. |

New in this list. Every one is present on v0.5.0 as well, so none is a regression:

- **A `cd` in a piped brace group or a function body.** `{ cd w; cat x; } | cat; cat x` and `f() { cd w; }; cat x` both read `./x` in bash, and the hook scans `./w/x`. With the key in `./x` both exit 0 with no verdict.
- **A filtered grep whose output never reaches the filter.** `grep -r x d >&2 | spill-guard filter` sends grep's output to stderr, which the tool result carries, and the hook allows it silently. The shell segmentation records no descriptor duplication, so `>&2` cannot yet be told apart from the harmless `2>&1`.
- **A consumed `--context` value on BSD grep.** In `grep --context -r x`, the hook reads `-r` as `--context`'s value, while BSD grep 2.6.0 takes that value only after `=` and walks `.`. It crossed silently on v0.5.0 too.
- **A grep path holding a space.** `private-key-block` crosses grep's per-line prefix only where the path has no whitespace, so a key under a directory such as `My Keys/` reaches the filter unmatched.
- **`rg` is not offered the filter.** A recursive `rg` over a directory still gets the plain directory reason and defers.

There is still no Homebrew tap and no Scoop bucket. Both are designed and neither is built.

## The surface this freezes

Small on purpose, and `0.x` means none of it is promised.

- **Subcommands:** `hook`, `filter`, `selftest`, `version`, `coverage`. **`filter` is new.**
- **Flags, all new:** `filter --redact`; `coverage --since TIME|VERSION` and `coverage --file LOG`. No other subcommand takes a flag.
- **Exit codes, new:** `filter` exits 0 when it wrote the output and 3 when it withheld it. `coverage` exits 1 when a named `--file` does not exist and 2 on a malformed `--since`, an unknown flag or a stray argument.
- **Rule IDs, on by default:** `aws-access-key-id`, `github-token`, `github-fine-grained-pat`, `slack-token`, `slack-webhook-url`, `stripe-live-secret-key`, `openai-api-key`, `google-api-key`, `private-key-block`, `jwt`. **One changed what it matches**, `private-key-block`, and its ID did not change.
- **Rule IDs, off by default:** `payment-card`, `us-ssn`, `cn-resident-id`, `ipv4-public`. Unchanged.
- **The hook matcher:** `Read|Bash|Grep`, where v0.5.0 had `Read|Bash`.
- **Environment: no new reads.** `SPILL_GUARD_OVERRIDE=` is still a command-position prefix on a `Bash` command and is never read from the environment.
- **The coverage record gains four fields:** `session_id` and `cwd`, copied from the hook payload; `operands`, the token as written or the path that could not be read; and `version`. A record still carries no scanned value, and `PRIVACY.md` lists every field.
- **Reason strings: new ones, none rewritten.** The recursive-grep refusal and its filtered form, and the notice beside a block that says part of the call went unread.

## Security

No advisory accompanies this release. Every crossing closed here is this project's own gap, found in its own drives, its coverage log and review. None was reported from outside, and no evidence suggests any was used.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it.

The rest of the posture is unchanged: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.0/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.0/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.6.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.6.0_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard --signer-workflow 'karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.6.0'
```

Keep the `@refs/tags/...` suffix on the `gh` command. Without it `--signer-workflow` prefix-matches and accepts that workflow at any ref.

The provenance also travels as an asset, `spill-guard_0.6.0.intoto.jsonl`, for a consumer with no network path to the attestations API.
