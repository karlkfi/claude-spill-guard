**spill-guard keeps secrets and PII from reaching the API through a Claude Code session.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> **Upgrade if you are on v0.6.0.** Eleven `Bash` shapes driven for these notes read a credential file on v0.6.0 with no verdict and no coverage record: an array-subscript prefix ahead of the reader (`FOO[a b]=x cat k`), a command held in a variable (`V="cat k"; $V`), `$(<k)`, a `cd` inside a piped `{ … }` or a function body, three `grep` flag spellings, and a recursive grep whose output went to stderr past its filter. All of them block, defer with a record, or are refused with the filtered rewrite here.

## What v0.6.1 is for

**Closing the fail-opens found since v0.6.0.** It is a patch: no subcommand, flag, rule, record field or output format was added or removed. Two fixes go the other way and allow calls v0.6.0 refused, because those calls sent nothing a filter would not see.

## Highlights

- **A command spelled through a variable is read as the command bash runs.** An unquoted `$V` whose value is several words is split the way bash splits it, so `V="cat k"; $V`, `V="cat *.env"; $V` and `V="cd w"; $V; cat x` all get a verdict. ([#226](https://github.com/karlkfi/claude-spill-guard/pull/226))
- **An array-subscript prefix no longer hides the reader behind it.** `FOO[$((1+1))]=x cat k`, `FOO[a b]=x cat k`, `FOO["a]b"]=x cat k` and `FOO[a\]b]=x cat k` were each read as a command name with no reader, so the file was never opened. ([#219](https://github.com/karlkfi/claude-spill-guard/pull/219))
- **`$(<file)` is read as a read.** bash documents it as the fast `cat`, and the hook dropped the segment because it has no command word. Under zsh a bare `<file` at the top level is the same crossing and is denied too. ([#227](https://github.com/karlkfi/claude-spill-guard/pull/227))
- **A `cd` that does not move the shell no longer moves the scanner.** A `cd` inside a piped or backgrounded `{ … }`, loop, `if` or `case`, or inside a function body, changed which file the hook opened while bash read a different one. Past a function whose body moves, a relative operand now defers with a record, because a call need not name the function. ([#214](https://github.com/karlkfi/claude-spill-guard/pull/214))
- **`grep` is read as GNU, BSD and ugrep all read it.** Claude Code's Bash tool on the machine these notes were written on runs `grep` as ugrep, where `-2` means recursion and walks the working directory. `grep -2 pat` and `grep -r --context 3 pat` are now refused with the filtered rewrite. A value-taking option such as `--exclude-dir` or `--color` no longer makes the hook read the pattern as the file. ([#225](https://github.com/karlkfi/claude-spill-guard/pull/225))
- **A grep's filter counts only where grep's stdout reaches it.** `grep -rn pat d >&2 | spill-guard filter` sent the matches to stderr, which the Bash tool returns, and the filter read nothing. Seven such shapes are refused now. The same reading lets eight correctly filtered shapes through that v0.6.0 refused, such as a grep inside a piped `{ …; }`. ([#228](https://github.com/karlkfi/claude-spill-guard/pull/228))
- **A `Grep` tool call with no `output_mode` is allowed.** The tool defaults to `files_with_matches`, which sends paths and no file text, and v0.6.0 refused it as a `content` search. Driven on Claude Code 2.1.290, the tool is absent from the default tool set and `--tools Grep` exposes it. ([#216](https://github.com/karlkfi/claude-spill-guard/pull/216))

### Driven on built binaries

## Upgrading

Both halves move. The binary is what changed; the plugin manifest version is what makes `claude plugin update` deliver it.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.1/install.sh
sh install.sh
claude plugin marketplace update spill-guard
claude plugin update spill-guard
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.1/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Hooks are read when a session starts, so start a new one. Then run `spill-guard selftest` and read what it says it could not establish.

**No configuration changes.** Two behaviours do:

- **`grep` with a digit option and no file operand is refused**, offered the filtered rewrite, on every machine. On a `grep` that is GNU or BSD rather than ugrep, `cmd | grep -2 pat` only prints context, so the refusal costs one turn there. Replaying 42,448 recorded commands that mention `grep` through both binaries changed no verdict, by the count in [#225](https://github.com/karlkfi/claude-spill-guard/pull/225), not re-taken here.
- **Past a function definition whose body runs `cd`, a relative operand defers** rather than getting a verdict, and is written to the coverage log. `spill-guard coverage` counts them.

## Security

No advisory accompanies this release. Every crossing closed here is this project's own gap, found in its own drives, its coverage log and review. None was reported from outside, and no evidence suggests any was used.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it, and several shapes above are ones only a deliberate spelling reaches.

The rest of the posture is unchanged: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.1/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.6.1/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.6.1' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.6.1_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard --signer-workflow 'karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.6.1'
```

Keep the `@refs/tags/...` suffix on the `gh` command. Without it `--signer-workflow` prefix-matches and accepts that workflow at any ref.

The provenance also travels as an asset, `spill-guard_0.6.1.intoto.jsonl`, for a consumer with no network path to the attestations API.
