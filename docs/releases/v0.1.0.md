**spill-guard keeps secrets and PII from reaching the API through a Claude Code session.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> This is a `0.x` release and the surface carries no compatibility promise. Subcommand names, rule IDs, and the shape of a verdict can change in the next minor.

> [!CAUTION]
> A buffer this build cannot decode is **allowed**, not blocked, and reported in a notice. A file behind a UTF-8 byte-order mark with a NUL in its first 8 KiB crosses unscanned, and so does a binary-looking file spliced in with `@`. **What it does not read** below has the list. Nothing here is a wall against someone who means it — the escape hatch is one environment variable.

## Highlights

- **Three surfaces, each driven against a real hook rather than reasoned about.** A prompt (including the `@path` tokens that splice a file into context with no hook of their own), a `Read` call's `file_path`, and a `Bash` command — both the command string and the files its reader operands resolve to.
- **It fails closed.** The sibling guards fail silent so a hook on every call never breaks ordinary work. This one inverts that: an operand it cannot resolve, a path that is not a regular file, an internal error — each blocks with a reason. A scanner that fails quietly reports a safety it is not providing.
- **Empty supply chain.** `go.mod` carries no `require` block at all. The build graph is 116 packages, all of them this module plus the standard library, and it reaches no `net`, `net/http`, or `os/exec`. Three gates enforce that on the import graph rather than at review, because a telemetry field added in good faith is the failure mode here.
- **Precision over recall.** 14 rules, 10 on by default and the 4 PII rules off. The ruleset this replaces flagged 27.6% of real files with zero true positives, which is how a security tool trains everyone to ignore it. Every rule ships with a corpus case proving it stays quiet on clean input.
- **`spill-guard selftest` answers whether the binary actually scans.** Eight arms through the real hook path in-process, three of them allowing arms, so an over-matching rule shows up as a failure rather than as more green.

## Installing

Two halves, and neither is any use alone. The plugin is the wiring that tells Claude Code which calls to hand over; the binary is what reads them. A plugin installed without a binary blocks every call it sees and names the fix in the refusal.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.1.0/install.sh
sh install.sh
claude plugin marketplace add karlkfi/claude-spill-guard
claude plugin install spill-guard@spill-guard
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.1.0/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Two steps rather than one on purpose. The one-liner that pipes a remote script into a shell works, and for a tool whose whole pitch is that nothing leaves your machine, opening with "pipe this into your shell" undercuts the claim before you reach the second paragraph. Download it, read it, run it.

Hooks are read when a session starts, so start a new one. Then run `spill-guard selftest` and read what it says it could not establish — whether Claude Code is invoking the hook at all is not reachable from outside a session, and the report says so rather than letting a green run imply it.

## What it does not read

Every item here is measured, and each one is a case where a credential can cross. They are listed because a scanner's gaps are the only part of it a user cannot discover for themselves.

- **A UTF-8 byte-order mark ahead of a NUL.** `EF BB BF` is a declaration the decoder has no arm for, so the buffer falls through undecoded, the NUL is read raw, and the file is skipped as binary. PowerShell's `Out-File -Encoding utf8BOM`, Notepad, and Visual Studio all write that mark. The call is allowed with a notice naming the buffer. The notice reports that nothing looked; it is not coverage.
- **A binary-looking `@` target in a prompt.** `@heap.dump` arrives carrying the whole file, NUL included, and the scan pipeline skips any buffer with a NUL in its first 8 KiB. Same notice, same consequence.
- **A recursive read.** `grep -rn pat docs/` names a directory, and this reads files rather than walking them, so the call is **refused** rather than allowed. That is the fail-closed policy working, and it means recursive greps do not run while the hook is installed. Name the files instead. Whether to walk the directory is undecided pending a measurement of what Claude Code does with a hook past its 60-second timeout.
- **A secret synthesized at runtime.** `env`, and anything like it, produces bytes that exist only in the tool process. There is nothing to open at `PreToolUse` and nothing to match, and `PostToolUse` cannot withhold a result, so this is structural rather than a missing rule.
- **Readers outside the three that are driven.** An MCP server's file reader, a search tool that returns matching lines, a skill or subagent load. Each is a hook input naming a path whose result comes back as content, and none of them has been driven. The gap is stated rather than closed because the tool set is not a list anyone can enumerate once.
- **A block does not carry the unread-buffer notice.** A call with findings in one buffer and an unread buffer in another reports the findings only, so the coverage sentence in the refusal is true of the buffers it read and not of the call.

There is also no Homebrew tap and no Scoop bucket. Both are designed and neither is built, so a machine with neither `cosign` nor `gh` has no route that verifies for it — the install scripts refuse on such a machine rather than falling back to the checksum, because `checksums.txt` comes from the same place the archive did and answers corruption, not substitution.

## The surface this freezes

Small on purpose, and `0.x` means none of it is promised.

- **Subcommands:** `hook`, `selftest`, `version`. No flags.
- **Environment:** `SPILL_GUARD_BIN` tells the launcher where the binary is. `SPILL_GUARD_OVERRIDE=<reason>` downgrades a block to a confirmation, and is read only from an inline assignment prefix on a `Bash` command — never from the environment, and never from anything the model can write inside a scanned file.
- **Rule IDs, on by default:** `aws-access-key-id`, `github-token`, `github-fine-grained-pat`, `slack-token`, `slack-webhook-url`, `stripe-live-secret-key`, `openai-api-key`, `google-api-key`, `private-key-block`, `jwt`.
- **Rule IDs, off by default:** `payment-card`, `us-ssn`, `cn-resident-id`, `ipv4-public`.
- **A finding reports the rule ID, the path, and the byte offset. Never the value, and not a redacted fragment either**, because the refusal text reaches the API as well.

The verdict JSON is Claude Code's hook schema rather than this project's, so it is not ours to freeze.

## Validation

<details><summary>784 test cases across 9 packages, 17 gates each paired with a job that breaks it — and the three release steps no pull request can reach</summary>

- `go test ./...` passes 784 cases across 9 packages, 190 top-level tests.
- 17 gates run on every pull request, and `tests.yml` carries 35 jobs: each gate, a mutation control that breaks the property and requires the gate to go red, and one control over `make check` itself. A check that has never failed is a claim rather than evidence.
- The precision corpus: 13 clean files producing 0 findings, 12 planted files producing exactly one finding each. Forced on, the PII family reports 0 findings on the clean corpus.
- `govulncheck` reports no known vulnerability the build graph calls.
- All five shipped targets cross-compile from one runner: `darwin/arm64`, `darwin/amd64`, `linux/amd64`, `linux/arm64`, `windows/amd64`.
- Both install scripts run on Linux, macOS, and Windows on every pull request, against the archives that same pull request built, and each is required to refuse a corrupted archive, an unlisted archive, and a machine with no verifier.
- **What no pull request reaches:** cosign signing, the provenance attestation, and the asset upload live behind the tag. A prerelease rehearsal exercised them before this tag; the verification step pins `--certificate-identity` to this workflow at this tag, so a signature minted from a branch is rejected.
- **The launcher's line endings are load-bearing and split** — CRLF down to the `CMDBLOCK` terminator, LF after it. LF throughout makes cmd.exe lose its file position and the call runs unscanned; CRLF throughout kills the POSIX half. A `windows-latest` job reproduces both failures.

## Security

No advisory accompanies this release, and there is no prior version to patch from. What it does carry is the posture: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string, since paths and rule descriptions both reach a terminal.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too, so the script you fetch in order to read it can also be checked:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.1.0/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool — `cosign` needs the bundle downloaded alongside `checksums.txt`, `gh` fetches what it needs itself:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.1.0/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.1.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.1.0_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard
```

The provenance also travels as an asset, `spill-guard_0.1.0.intoto.jsonl`, for a consumer with no network path to the attestations API.
