**spill-guard is a Claude Code hook that blocks secrets and US Social Security numbers before a call sends them to the API.** It scans at the boundary between your filesystem and the model's context — the one a git secret scanner never sees, because a file read into a session is never committed.

> [!WARNING]
> **Upgrade if a Claude Code OAuth token or a claude.ai session key could be in a file a session reads.** On v0.7.0 a token behind `sk-ant-oat01-`, `sk-ant-ort01-`, `sk-ant-sid01-` or `sk-ant-ccsr-` crossed in a `cat`, a `Read` and a prompt with no verdict and no record. v0.7.0's notes listed this as a known limit. It now blocks on all three surfaces.

## What v0.8.0 is for

**Blocking Anthropic OAuth tokens and session keys, no longer blocking placeholder Social Security numbers, and closing a dozen shell and prompt shapes where a key crossed unread.** It is a minor rather than a patch because a new rule ID ships. Nothing was removed.

## Highlights

- **Anthropic OAuth tokens, session keys and session git credentials are blocked.** `anthropic-token` matches `sk-ant-oat`, `sk-ant-ort` or `sk-ant-sid` with two digits, or `sk-ant-ccsr`, then a hyphen and 20 to 1,000 bytes of `[A-Za-z0-9_-]`. No real token of these kinds was on the machine the rule was written on, so a real one under 20 bytes would go unreported. ([#257](https://github.com/karlkfi/claude-spill-guard/pull/257))
- **A placeholder Social Security number no longer blocks a read.** Under an `ssn` label, a value SSA never assigns — area 666, group 00, serial 0000 — a run of one repeated digit, or one of the well-known published example numbers is now dropped before the label check. On v0.7.0 each of these denied a `cat` of a test fixture. Whether anyone now holds one of the listed example numbers cannot be checked from here, since SSA assigns areas at random since 2011, so those two entries are a recall cost that cannot be measured. ([#266](https://github.com/karlkfi/claude-spill-guard/pull/266))
- **A prompt naming `.env`, `~/.aws/credentials`, `~/.netrc`, `~/.git-credentials`, `~/.docker/config.json` or a kubeconfig with `@` is blocked on the path alone**, as `cat` and `Read` of those files already were. On v0.7.0, `@.env` got only the content scan, so a password or an AWS secret access key in it reached the model. ([#267](https://github.com/karlkfi/claude-spill-guard/pull/267))
- **An override prompt names every rule match in the call.** `SPILL_GUARD_OVERRIDE=why cat key.txt .env` asked about `.env` and named no rule on v0.7.0, so approving it sent a key the prompt never mentioned. The prompt now names the match. ([#255](https://github.com/karlkfi/claude-spill-guard/pull/255))

### Where a key used to cross and now blocks

- **A recursive grep is refused when its output is copied around `spill-guard filter`.** A `tee /dev/stderr`, a `cat >&2` stage, or a file the same command reads back sent the matched lines to the model while the filter withheld its own copy. Those were allowed with no verdict. ([#254](https://github.com/karlkfi/claude-spill-guard/pull/254))
- **A recursive grep with its patterns in `-f FILE` or `--file=FILE` and no directory is refused** like the other spellings. On v0.7.0 the pattern file was read as the operand, so the call was allowed and grep searched the working directory unscanned. ([#268](https://github.com/karlkfi/claude-spill-guard/pull/268))
- **A file named beside something the hook cannot read is now scanned.** `echo plain.txt | xargs cat key.txt`, `timeout $T cat key.txt`, and a `for` list mixing a literal with `$(...)` got a coverage record on v0.7.0 (a line in a local log saying what the hook could not read) and nothing else. So did a key inside the list handed to `file -f`, `wc --files0-from` or `sort --files0-from`. All of them now deny. ([#261](https://github.com/karlkfi/claude-spill-guard/pull/261))
- **A scan that runs out of its 45-second budget partway through a file keeps what it already found there**, so `head -5 big.log` over a large log with a key near the top is refused rather than deferred. ([#258](https://github.com/karlkfi/claude-spill-guard/pull/258))
- **A file read behind zsh's `noglob`, `nocorrect`, `repeat N` or `-`, or behind `coproc` in either shell, is now scanned.** Each crossed with no verdict and no record. ([#259](https://github.com/karlkfi/claude-spill-guard/pull/259))
- **Four `time` and `case` shapes are read as bash reads them.** `time -- -p FOO[a;cat key.txt;b]=x true`, a quoted `time` option, and a `case` after `case a in esac then` crossed silently and now deny. ([#273](https://github.com/karlkfi/claude-spill-guard/pull/273))

### Where the hook read the wrong file and now says so

These moved from a silent allow to a deferred call with a coverage record. None of them blocks, because the hook cannot follow the shell there. What changed is that the gap is now recorded instead of a different file being scanned in its place.

- **A `cd` run through `eval`, `source`, `.`, a trap, a `mapfile -C` callback or a bash 5.3 `${ …; }` substitution.** The hook went on resolving later files in the old directory, so `eval 'cd w'; cat k.txt` scanned `./k.txt` while bash opened `w/k.txt`. ([#265](https://github.com/karlkfi/claude-spill-guard/pull/265))
- **An assignment inside a `case` arm reached through braces, `!`, `then` after a closer, or `time -p`.** `P=.; { case a in b) P=w;; esac; }; cat $P/key.txt` scanned `w/key.txt` while bash opened `./key.txt`. ([#253](https://github.com/karlkfi/claude-spill-guard/pull/253), [#263](https://github.com/karlkfi/claude-spill-guard/pull/263))
- **An `esac` that is an argument or quoted inside a `case`.** It closed the clause early, so a `cd` in an arm bash never ran was followed. ([#273](https://github.com/karlkfi/claude-spill-guard/pull/273))

### Reported more accurately

- **On macOS, `sed -i '' 'script' file` no longer records the script as a file operand.** BSD sed reads the `''` as the backup suffix. The file was always scanned, so this removes a coverage record and changes no verdict. The same PR measured this shape as 117 of 252 operand-bearing `Bash` coverage records in one week on one machine. ([#256](https://github.com/karlkfi/claude-spill-guard/pull/256))

### Tested on built binaries

v0.7.0 built from its tag, against `main` at `33e9eda`, the commit this tag is cut from. Each payload went to `spill-guard hook` in a fresh directory with an AWS key or Anthropic token generated at the time. `key.txt` holds an AWS key unless a row says otherwise. A deferred call and a clean allow both exit 0 with no verdict, so "defer, recorded" is read off the coverage log rather than off the exit status. The hook was configured for bash through `CLAUDE_CODE_SHELL` unless a row says zsh.

## Upgrading

The binary is the whole of this release. `hooks/hooks.json`, the launcher and the install scripts are byte-identical to v0.7.0, and the plugin manifests change only their version string.

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.8.0/install.sh
sh install.sh
```

Windows, in PowerShell:

```
curl.exe -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.8.0/install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

`claude plugin marketplace update spill-guard` and `claude plugin update spill-guard@spill-guard` bring the plugin's version string to 0.8.0 and change nothing it runs. Unlike v0.7.0, updating one half without the other leaves no gap.

Then run `spill-guard selftest` and read what it says it could not establish.

**No configuration changes.** Three behaviours do:

- **A file holding an Anthropic OAuth token, session key or session git credential is denied**, in a `cat`, a `Read` or a prompt. A `Bash` read can take `SPILL_GUARD_OVERRIDE=<reason>`, which turns the deny into a confirmation prompt. A `Read` has no override.
- **A prompt that `@`-names one of the six guarded credential paths is blocked**, whatever the file holds.
- **Some calls that were allowed with nothing recorded now defer with a coverage record.** They are under **Where the hook read the wrong file and now says so**. `spill-guard coverage` counts them. Over one machine's 240,454 distinct `Bash` commands, [#265](https://github.com/karlkfi/claude-spill-guard/pull/265) measured 4 that gained a record and none that changed verdict. A later pass over 246,901 found 16 more, each with a `${` inside quotes.

## Deprecations

None. No subcommand, flag, rule ID, environment read or output format was removed.

## Known limits and costs

The README's [**What it does not catch**](https://github.com/karlkfi/claude-spill-guard/blob/v0.8.0/README.md#what-it-does-not-catch) has the standing list. The items below are new in this release or newly stated here.

- **An Anthropic OAuth token or session key shorter than 20 bytes after its prefix is not matched.** No real one was available to bound the length. A hyphen-free token longer than 1,000 bytes is reported on its first 1,000. ([#257](https://github.com/karlkfi/claude-spill-guard/pull/257))
- **Dropping the two published example numbers is a recall cost nobody can measure.** If someone has since been issued one of them, it no longer blocks under a label. ([#266](https://github.com/karlkfi/claude-spill-guard/pull/266))
- **Reading literals beside an unsettled list can over-block.** `timeout $T foo cat f` blocks over a file `foo` was handed, and with `T` unset `timeout` reads `cat` as the duration. On macOS `xargs` runs nothing on empty input, so `xargs cat key.txt` can deny a call that would print nothing. Over 240,454 distinct `Bash` commands on one machine the first shape appeared 0 times. ([#261](https://github.com/karlkfi/claude-spill-guard/pull/261))
- **A `${` inside quotes now records a coverage gap**, because the hook reads no backslash as an escape when it looks for a bash 5.3 `${ …; }` substitution. It costs a record and no verdict. ([#265](https://github.com/karlkfi/claude-spill-guard/pull/265))
- **The budget fix works per rule, not per byte.** A key that only the rule still running when the budget ends would recognise still defers. ([#258](https://github.com/karlkfi/claude-spill-guard/pull/258))

These v0.7.0 limits are closed: other `sk-ant-` prefixes crossing, the override prompt that named no rule, no placeholder validator for `us-ssn`, and `xargs cat key.txt` deferring a key it could have read. The false blocks from a wrapper whose grammar is lost are not closed, as the list above says. The intermittent `TestTheDeadlineFiresWhileTheMatchLoopIsRunning` failure is reworked by [#264](https://github.com/karlkfi/claude-spill-guard/pull/264), which times the test's own control and asserts the ratio, and how often it now fails has not been counted. Still open from v0.7.0: some substitution shapes that let a key cross ([Q225](https://github.com/karlkfi/claude-spill-guard/blob/v0.8.0/docs/queue/Q225.md)), files a `PowerShell` command opens ([Q237](https://github.com/karlkfi/claude-spill-guard/blob/v0.8.0/docs/queue/Q237.md)), and the reliance on Claude Code refusing a NUL in a command ([Q246](https://github.com/karlkfi/claude-spill-guard/blob/v0.8.0/docs/queue/Q246.md)).

There is still no Homebrew tap and no Scoop bucket.

## The public surface

Small on purpose, and `0.x` means none of it is promised.

- **Subcommands:** `hook`, `filter`, `selftest`, `version`, `coverage`. None new, and no flag changed.
- **Rule IDs, on by default:** `aws-access-key-id`, `github-token`, `github-fine-grained-pat`, `slack-token`, `slack-webhook-url`, `stripe-live-secret-key`, `openai-api-key`, `anthropic-api-key`, `anthropic-token`, `google-api-key`, `private-key-block`, `jwt`, `us-ssn`. **`anthropic-token` is new**, and covers all four prefixes under one ID.
- **Rule IDs, off by default:** `payment-card`, `cn-resident-id`, `ipv4-public`.
- **`us-ssn`** runs a new `ssn-placeholder` validator ahead of its label check.
- **The hook matcher, command and 60-second timeout** are unchanged from v0.7.0.
- **Environment: no new reads.** The coverage record gains no field.
- **`spill-guard selftest`** still runs 15 arms.

## Security

No advisory accompanies this release. Every crossing closed here is this project's own gap, found in its own testing and review. None was reported from outside.

The threat model is the accident — `cat .env`, a `grep -r password`, a stack trace carrying a bearer token. It is not a defense against a user who means it.

The rest of the posture is unchanged: no network capability in the build graph, no third-party runtime dependency, no in-band bypass tag, and control characters escaped in every emitted string.

## Verifying this release

Every archive is listed in `checksums.txt`, which is signed keylessly into the Sigstore bundle `checksums.txt.sigstore.json`, and each archive carries a SLSA build provenance attestation. `install.sh` and `install.ps1` are listed in `checksums.txt` too:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.8.0/checksums.txt
sha256sum --ignore-missing -c checksums.txt
```

`--ignore-missing` is the load-bearing flag: without it `sha256sum -c` fails on every asset you did not download, which reads as a verification failure.

To check authenticity rather than integrity, with either tool:

```
curl -fsSLO https://github.com/karlkfi/claude-spill-guard/releases/download/v0.8.0/checksums.txt.sigstore.json
cosign verify-blob --bundle checksums.txt.sigstore.json --new-bundle-format --certificate-identity 'https://github.com/karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.8.0' --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' checksums.txt
gh attestation verify spill-guard_0.8.0_linux_amd64.tar.gz --repo karlkfi/claude-spill-guard --signer-workflow 'karlkfi/claude-spill-guard/.github/workflows/release.yml@refs/tags/v0.8.0'
```

Keep the `@refs/tags/...` suffix on the `gh` command. Without it `--signer-workflow` prefix-matches and accepts that workflow at any ref.

The provenance also travels as an asset, `spill-guard_0.8.0.intoto.jsonl`, for a consumer with no network path to the attestations API.
