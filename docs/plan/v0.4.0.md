# What v0.4.0 is for

**Three things: close the edges the v0.3.0 notes added to the list, put a
control on the release path, and stop the scanner blocking reads of this
repository's own tests.** Decided 2026-09-07, the day v0.3.0 was tagged.

[The v0.3.0 notes](../releases/v0.3.0.md) resolved four operand shapes and,
under *What it does not read*, named the edges a resolver that resolves more
acquires. Those are published, so they are the commitment a reader can hold
this project to without a checkout, and they are the first theme. The second is
the `accruing` row in the store: the release job carries ten named steps and
seven of them assert something no pull request can reach, and v0.1.0 cost four
tag cycles finding that out. The third is friction this repository meets every
session — the hook refuses a `grep` over its own test files, which this groom
hit twice while reading rows — and it is a precision question rather than a
convenience, because thirteen of the twenty-two files that trip it are supposed
to.

The instrument that ranks inside the first theme is new since v0.3.0 and is the
reason v0.3.0 exists: `spill-guard coverage`. It was reset on this machine on
2026-09-07 when the v0.3.0 binary was installed, so its first week of dogfood
runs to about 2026-09-14. On the day it was reset it held 21 records, 15 on the
run-time-operand arm and 6 on the directory arm. **Re-read it before
dispatch**, because the order inside the first table below was set against one
day of that log and the v0.3.0 transcript sweep, not against a week of it.

## The second wave, decided 2026-09-07 after the first eleven merged

**The first eleven closed two edges off the published list, and that is not a
release.** Five of them ship in an artifact at all; the other six are CI and
test infrastructure, which is real value for the project and invisible to a
user. So the tag waits for a second set, chosen along the two axes a reader of
this scanner would actually feel: the gap list `docs/releases/v0.3.0.md`
published, and the one measured performance cliff.

| Row | What it buys |
|---|---|
| `Q127` | the MCP file reader, the last undriven member of the reader class. Closes a gap disclosed in three places since v0.1.0 |
| `Q150` | whether a `shopt` restored from an rc file changes what a glob sends. Bounds a disclosed gap, or closes it |
| `Q133` | `jwt` costs 16.1 of the shipped set's 31.2 ns/byte — over half of what is left. Scoping session first; the fix is whatever that picks |
| `Q148` | three pages still call the escape hatch an environment variable. The v0.3.0 notes corrected the word in their own banner, so a third release shipping the error is one a reader can see |
| `Q162` | the prompt-oracle floor failing also prints fourteen lines saying the grammar moved |

**One row is left, added 2026-09-07 after the second wave merged.** `Q164`
removes the recall ceiling `Q133` bought, by splitting a JWT's detection from
its extent — the bound is Go's `regexp` refusing a repeat above 1,000 rather
than a measurement of how long a token gets, and shipping a known recall
regression in the product's core claim is worse than holding the tag for it.
Measured before filing: a two-segment head rejects 95.1% of `eyJ` keyword hits
over 0.46 GB, so the extent walk runs on a twentieth of what the bound pays
for at every hit.

**Five rows gated the second wave and all five merged.** `Q156` was the sixth and is
done in this change: the row IDs above are code spans because every row named
here is one a merge deletes. Two are `M` — Q127 and Q133 —
and Q133 may end in a scoping row rather than a shipped fix, which is a real
answer and not a failure: its obstacle is an unbounded repeat measured at
29.8s against 12.2ms on a pathological buffer.

**Two more rode along and did not gate**, because closing them honestly meant
changing another repository first. `Q147` and
`Q92` both needed a fix in `claude-workspace-guard` ported by
inspection, and the rule this file already states held: a tag cannot wait on
another repository's merge. The upstream work was dispatched in parallel —
`Q100` is the report that started it. It landed before the tag for one of the
two: `claude-bouncer` #110 merged 2026-09-09 and `Q92` closed by porting it,
so that row leaves the disclosure list. `Q147` goes to v0.5.0 and stays on it.

## The rest of the cluster, labelled and not gating

One row still carries the label without gating, and the reason it does not is
the one the second wave above did not overturn. The other three named here
originally — Q133, Q150 and Q148 — are gates now; their entries are kept below
because the reason each was *excluded* is the reason each is now scoped the way
it is, and deleting that would lose why Q133 is a scoping session rather than a
work item.

- **`Q147`** — a substitution body after a followed `cd` is
  still recorded. The honest route the row names is a fix upstream in
  `claude-workspace-guard` first, ported by inspection, and a tag cannot wait on
  another repository's merge. 11 of 137 `cd` records in the measured week.
- **`Q133`** — `jwt` is over half of what the scan still
costs.
  Routed `**Measure:**`: the shapes are named and none is measured, so the row
  is a scoping session and not a work item until one of them is.
- **`Q150`** — the glob table is one machine's options. Routed
  `**Measure:**` for the same reason: whether a snapshot's `shopt` lines track
  the rc file, and whether a hook can find its session's snapshot, both have to
  be driven before there is anything to build.
- **`Q148`** — the design line still calls the escape hatch an
  environment variable. One word, taken by whoever next opens that section; the
  release-notes half was done in v0.3.0's banner.

## What is out, and why it is named rather than dropped

- **The directory arm** stands on its own argument, in the design under *A
  directory operand is refused rather than walked*. It is the second-commonest
  record in the log and the answer to it is *name the files*, which v0.3.0's
  notes already say.
- **Q100** — the filing that starts the upstream work. It did: the report
  became `claude-bouncer`'s Q139, and the fix for it merged there as #110 on
  2026-09-09, which is what let `Q92` close here by porting rather than by
  diverging the segmenter. Q100 itself is the row for the *filing*, so what it
  still owes is a groom rather than a code change.
- **Q127**, the MCP file reader, and **Q15**, `!` bash mode. The first is
  undriven and needs a server stood up here; the second needs a person at a
  keyboard. Neither is a code change this release can promise.
- **The scheduled prerelease** half of Q59, now `Q154` and deferred. It
  publishes on a timer and its cost is unpriced. The negative control that
  landed does not price it — it proves the verifier discriminates, which is a
  different claim from the pipeline working — so the trigger is the next
  rehearsal somebody runs by hand, with what it cost written down.

## How this file retires

When `v0.4.0` is tagged. A plan doc naming a release that already exists is the
staleness this arrangement is meant to avoid, so cutting the tag deletes this
file and drops the label from any row still carrying it —
[`release-process.md`](../development/release-process.md) carries that step,
under *Publishing the draft*, and Q119 has shipped the gate that checks it:
`release-scope`. Its mutation control writes its own stale record rather than
planting this file, so nothing in here is load-bearing for CI.
