# What v0.4.0 is for

**Close the edges the v0.3.0 notes added to the list, and cut what the ruleset
cannot source.**

[The v0.3.0 notes](../releases/v0.3.0.md) resolved four operand shapes and, under
*What it does not read*, named the edges a resolver that resolves more acquires:
a `for` loop's variable is poisoned, a `case` arm is read as unconditional, a
substitution body after a followed `cd` is still recorded, and the glob table is
one machine's shell options. Those are published, so they are the commitment a
reader can hold this project to without a checkout. The same notes also carry a
recall gap that has nothing to do with the resolver — a whitespace-only line
between a PEM header and its body defeats the rule — and the rules README
carries three prefix arms that no document sourced until this groom read AWS's
own table.

The instrument that ranks inside this scope is new since v0.3.0 and is the
reason v0.3.0 exists: `spill-guard coverage`. It was reset on this machine on
2026-09-07 when the v0.3.0 binary was installed, so its first week of dogfood
runs to about 2026-09-14. On the day it was reset it held 21 records, 15 on the
run-time-operand arm and 6 on the directory arm. **Re-read it before dispatch**,
because the order inside the table below was set against one day of that log
and the v0.3.0 transcript sweep, not against a week of it.

## The rows the tag waits for

Labelled `v0.4.0` in `docs/queue/`, in the order they rank.

| Row | The disclosed case, or the gap |
|---|---|
| [Q149](../queue/Q149.md) | a `for` loop's variable is poisoned, so `for f in a b; do cat "$f"; done` records both. Upstream resolves it already; this is a port |
| [Q151](../queue/Q151.md) | a `case` arm is read as unconditional, so the resolver scans a path bash never used. Bounded, and a segmenter change stated at the site |
| [Q142](../queue/Q142.md) | the AWS unique-ID table names `ABIA` and `ACCA` and does not name `A3T`. Cut the one arm, and say the other two are sourced |
| [Q143](../queue/Q143.md) | a whitespace-only separator line defeats the PEM body clause. Recall, and the rule's own corpus case has to stay quiet |

**Four rows gate the tag.** Each is `S`, each names its mechanism, and none
waits on anything outside this repository.

## The rest of the cluster, labelled and not gating

Four more rows carry the label so that `render --label v0.4.0` shows the whole
of what the release is about, and so cutting the tag drops the label from them.
None of them is a gate, for four different reasons:

- **[Q147](../queue/Q147.md)** — a substitution body after a followed `cd` is
  still recorded. The honest route the row names is a fix upstream in
  `claude-workspace-guard` first, ported by inspection, and a tag cannot wait on
  another repository's merge. 11 of 137 `cd` records in the measured week.
- **[Q133](../queue/Q133.md)** — `jwt` is over half of what the scan still costs.
  Routed `**Measure:**`: the shapes are named and none is measured, so the row
  is a scoping session and not a work item until one of them is.
- **[Q150](../queue/Q150.md)** — the glob table is one machine's options. Routed
  `**Measure:**` for the same reason: whether a snapshot's `shopt` lines track
  the rc file, and whether a hook can find its session's snapshot, both have to
  be driven before there is anything to build.
- **[Q148](../queue/Q148.md)** — the design line still calls the escape hatch an
  environment variable. One word, taken by whoever next opens that section; the
  release-notes half was done in v0.3.0's banner.

## What is out, and why it is named rather than dropped

- **The directory arm** stands on its own argument, in the design under *A
  directory operand is refused rather than walked*. It is the second-commonest
  record in the log and the answer to it is *name the files*, which v0.3.0's
  notes already say.
- **Q92 and Q100** — a quoted assignment arms the override where bash would
  not. Blocked on the same upstream as Q147, and Q100 is the filing that starts
  it; both stay where they rank.
- **Q127**, the MCP file reader, and **Q15**, `!` bash mode. The first is
  undriven and needs a server stood up here; the second needs a person at a
  keyboard. Neither is a code change this release can promise.
- **Q59**, the release path's missing rehearsal. `accruing`, and routed
  `**Ask:**` in this groom: a scheduled prerelease publishes on a timer, which
  is the maintainer's call. The cheaper negative control could land inside this
  release without the answer, and does not need the label to do so.
- **Q125 and Q121** — the scanner blocks reads of this repository's own test
  files, which this groom met twice. Real friction on every session here, and
  a design question about where an allowlist lives, not a v0.4.0 gate.

## How this file retires

When `v0.4.0` is tagged. A plan doc naming a release that already exists is the
staleness this arrangement is meant to avoid, so cutting the tag deletes this
file and drops the label from any row still carrying it —
[`release-process.md`](../development/release-process.md) carries that step,
under *Publishing the draft*, and [Q119](../queue/Q119.md) is the gate that
does not yet exist for it. This file is the first instance that gate would have
had since v0.2.0's, because v0.3.0 shipped with no record at all.
