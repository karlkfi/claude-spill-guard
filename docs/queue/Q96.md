# What a hook that exceeds its timeout does is unmeasured

`hooks/hooks.json` sets `"timeout": 60` on both entries, matching
branch-guard's. The number was picked without knowing what happens when a hook
runs past it, which leaves the one question that matters here open: **does
Claude Code treat an expired hook as a block, or does the call go through?**

If expiry allows the call, the timeout is a fail-open with no reason attached
and nothing in the transcript — the same silence the launcher's deny exists to
replace, arriving through a different door. This project's whole exit-code
contract was settled by driving that class rather than reading about it, and
this member of it has not been driven.

60 was chosen in the direction that cannot make the unknown worse. If expiry
allows, a longer timeout is strictly safer; if it blocks, a longer timeout only
ever costs a stall. That is a hedge and not an answer.

**Measure:** a hook that sleeps past its timeout, on `PreToolUse` and on
`UserPromptSubmit`, with the control beside it — the same hook sleeping under
the timeout, and blocking, so the probe can show the opposite. Read the
transcript under `~/.claude/projects/` rather than the hook's own return, for
the reason [the `PostToolUse` measurement](../design/README.md) gives: the
return value proves nothing about what was sent.

**One of those two arms is cheaper than the other, measured 2026-09-01 while
driving [Q94](Q94.md).** Claude Code resolves a prompt's `@` tokens and fires
`UserPromptSubmit` *before* it makes its first API call, so that arm can be
driven with no working credential at all — established under a clean `HOME`
with no credential of any kind, against 24 of 24 recorded oracle cases, with a
control that moved the harness's answer from three files to two when one token
was dropped. The `PreToolUse` arm has no such route: a hook there fires only
once the model has chosen a tool call, which needs the API. Across 25
unauthenticated runs `PreToolUse` fired zero times.

So this row splits by cost rather than by event. Take the `UserPromptSubmit`
arm whenever; the `PreToolUse` arm waits on a session that can reach the API.

Then either state the timeout's semantics in
[`docs/design/README.md`](../design/README.md) beside the exit-code table, or —
if expiry allows — say what the scanner does about a buffer too large to finish
in the budget, which is the only way to hit it in practice.

Belongs to the class [Q94](Q94.md) names: a fail-open with no symptom and no
reporter, invisible to every gate that reads the tree.
