# Plugin manifests and hooks.json

`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` and
`hooks/hooks.json` are deliberately absent from the repo until there is a hook
that fires. Shipping them earlier makes the repo installable as a security tool
that scans nothing, which is the failure the design indicts the predecessor
for — installed, silent, enforcing nothing.

So this is the item that makes the plugin real, and it lands with or after the
launcher rather than before it.

Copy the manifest shape from the sibling guards: eight keys in `plugin.json`,
a single-plugin `marketplace.json` pointing at this repo, versions kept
identical between the two. Nothing else in the repo encodes the version.

Wire the `PreToolUse` matcher against the tools the design's hook-surface table
settles on. That table is settled: `PostToolUse` cannot withhold a result, so
every tool this guard actually stops has to be matched at `PreToolUse`.

**The matcher has to name exactly what `internal/hook` scans, which is `Read`
and `Bash` and nothing else.** A matcher wider than the scanner delivers calls
the hook returns clean on without having looked at them, and a hook that runs
and scans nothing is the failure this repo indicts its predecessor for — it is
also indistinguishable, from outside, from a hook that checked. `ToolRead` and
`ToolBash` are exported from that package so this can be held to them rather
than kept in step by hand.
