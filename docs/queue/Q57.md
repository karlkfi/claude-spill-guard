# Pin the GoReleaser CLI by digest, not by release tag

`action-pins` requires every `uses:` in every workflow to name a 40-character
commit SHA, on the argument that a tag is mutable by whoever owns the action and
an action runs in a job holding the repository token. The release job satisfies
that gate and still fetches a tag: `goreleaser/goreleaser-action` is pinned by
SHA, and the binary it downloads is chosen by `GORELEASER_VERSION: v2.18.0` in
`.github/workflows/release.yml`, which is a git tag on `goreleaser/goreleaser`
resolved at run time.

The pin is real — the action's default is `~> v2`, and naming an exact release
is what stops the tool moving between one release and the next. It is a weaker
pin than the one this repository requires everywhere else, and it sits on the
job with `contents: write` and `id-token: write`.

GoReleaser publishes a `checksums.txt` for its own releases and signs it the
same way this project signs its own. Closing this means fetching the archive,
verifying it against a digest committed here, and running that binary — which
is the same shape as `scripts/check-vendor.py`, so the mechanism already exists
in the tree.

`action-pins` cannot see this. It reads `uses:` values, and a tool version
passed as an input to an action is not one — worth deciding whether that gate
grows a second reading or whether a separate check owns tool versions.
