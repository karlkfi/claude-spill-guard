# The selftest subcommand that proves the hook is live

Blocked by [Q50](Q50.md). The launcher landed with Q8 and the hook entry
did not, so there is no hook path to drive end to end yet.

`spill-guard selftest` feeds a canary secret through the full hook path and
asserts a block. Not a unit test of the scanner — the whole path, including the
launcher, so it answers "is this thing actually running" rather than "does the
matcher work".

The question it exists to answer has a real wrong answer available. The
predecessor was installed on machines where it enforced nothing and reported
nothing, and no amount of reading its config would have shown that. Nothing
short of driving the live path can distinguish an inert hook from a clean run,
because both produce silence.

Document it in the README's install section as the verification step, the way
the sibling guards tell you to run a command and watch it get denied.
