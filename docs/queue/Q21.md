# A coverage baseline floor that only moves up

Record per-package coverage into a tracked `coverage-baseline.txt`, fail CI
when a package drops below its recorded number, and provide the target that
re-records it so raising the floor is a deliberate diff.

A percentage target picked up front is arbitrary and gets argued down. A floor
derived from what the tests already cover cannot be argued with — it only ever
says "this got worse", which is the claim worth gating.

## Why this repo in particular

The failure mode here is a scanner that misses a secret, and an untested branch
in a validator or the prefilter fails exactly that way: silently, reporting a
clean result identical to a real one. There is no user who notices. Coverage is
a weak proxy for correctness in general and a much better one when every
uncovered branch is a path that can only fail by staying quiet.

Pair it with the mutation controls the gates already carry. Coverage says the
line ran; a mutation control says the assertion would have caught it changing.
