# A reader operand naming a fifo hangs the hook instead of scanning

`internal/hook/bash.go` resolves a reader's file operand and calls
`os.ReadFile` on whatever it landed on, with no check on what that is. So does
the `Read` arm of `toolTargets` in `internal/hook/hook.go`, on the `file_path`
the tool sends. A fifo opens and then blocks until something writes, and
nothing here has a deadline, so `cat some.fifo` does not produce a finding, a
refusal, or an error. It produces a hook that never returns, on a call that
never completes.

That is worse than either direction this project usually chooses between. A
fail-open lets the call through and a fail-closed blocks it; a hang does
neither, and the transcript carries no record of a decision because no decision
was reached.

`internal/hook/prompt.go` already refuses the class — anything that is not a
regular file or a directory blocks with a fixed reason naming neither the token
nor the path — and `TestAPromptNamingSomethingThatIsNotAFileBlocks` drives it
against `/dev/null`, which is a character device on every unix and needs no
`mknod`. The work is the same guard at the two older sites, on the same reading:
a device or a socket sends nothing this can scan, so opening one buys nothing
and can cost the session.

Two things to decide rather than assume while doing it:

- **Whether a character device should block or be skipped.** `/dev/null` sends
  nothing, so blocking on it is an over-block; a fifo is the shape that hangs.
  prompt.go blocks both because one rule is cheaper than two and neither is a
  file a prompt means to name. The Bash surface has more traffic and a
  `cat /dev/null` in a real command is not exotic, so the answer there may
  differ, and it should be taken deliberately at each site rather than copied.
- **Whether `os.Stat` is the right reading.** It follows symlinks, which is
  what the tools do, so a symlink to a fifo is caught. `os.Lstat` would report
  the link and miss it.

There is no measurement owed here. The hang follows from `open(2)` on a fifo
with no writer, and a test can drive it with `syscall.Mkfifo` behind a build
tag or with a symlink to a device, which is how prompt.go's does it without
leaving the portable set.
