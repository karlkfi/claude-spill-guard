# `CLAUDE.md` names one branch-weak gate and there are two

The paragraph under *Running the gates* says the exception is singular —
`CLAUDE.md:826:One gate is weaker on a branch than on the trunk` — then names
`queue` alone, and closes by calling `make queue MERGED=true` *the only local
command that sees what the push to `main` will see*.

`release-notes` is the second, by the same mechanism and through the same
variable. Its recipe in the `Makefile` reads:

```
$(PYTHON) scripts/check-release-notes.py $(if $(filter true,$(MERGED)),--merged)
```

The flag is not a severity dial. `check-release-notes.py` returns 0 on a branch
and 1 on `main` over the same divergence, and writes to stdout rather than
stderr while it is reporting —
`scripts/check-release-notes.py:151:return 1 if args.merged else 0`. The
workflow supplies the variable the same way `queue`'s job does, passing
`MERGED` on anything that is not a pull request.

The Makefile comment above that target argues the split at length and is
correct about it: a notes edit that is still an open pull request *is* the
proposal, and no pull request can repair the divergence either way, because the
repair is `gh release edit`. So this is not a defect in the gate. It is a
sentence in the document sessions are told to read, undercounting the class by
one and naming the wrong command as the only one.

## Why it is worth fixing rather than noting

The last clause is the load-bearing half. A session that takes `make queue
MERGED=true` as *the* trunk-view command runs it, reads green, and still has
not seen what the push will see — `make release-notes MERGED=true` is a second
one, and nothing in the document says so. The failure is the shape this
repository already indicts by name: a check reporting no verdict reads
identically to one that passed.

## What it is not

Not the gap between a local gate and CI in general. `release-claims` had one of
those — the target read the machine's real release state while the workflow
required three arms — and it was closed by making the target run all three,
because nothing about that class was event-dependent. This one is
event-dependent, correctly, and the fix is prose.

The count is also worth generating rather than hand-keeping if a third ever
appears. Two is under the threshold where that pays, and `gate-drift` has no
reader for *which* gates take `MERGED` — it reconciles names, descriptions and
the job list, not the variables a recipe passes. Widening it is a separate
decision from correcting the sentence.
