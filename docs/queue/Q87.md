# Enumerate the reader class by payload shape, not by tool name

The design defines what gets scanned as *any hook input naming a filesystem
path whose result comes back as content*, and covers the three members that
have been driven: a `Read` path, a `Bash` reader's resolved operands, and an
`@path` in a prompt. Q77 closed the third and wrote the rest of the class into
[*What it is not*](../design/README.md#what-it-is-not), which states the gap
rather than closing it. This is the closing.

**The obvious shape of the work is the one to refuse.** A list of tool names in
`internal/hook`, matched the way `ToolRead` and `ToolBash` are matched today,
goes stale in silence: a tool installed after the list was written is waved
through, and nothing anywhere reports that a call was not scanned. The
measurement that says so was taken while driving Q77 on 2026-08-28. One
`claude -p` session in a bare directory announced nineteen deferred tools in a
single `deferred_tools_delta`, none of which appears in the design; a run asked
to search file contents reached `ToolSearch` twice and issued no search call at
all. A tool set that differs per machine and per session is not something a
constant can track.

So the member test is the payload rather than the name: a `tool_input` field
whose value is a filesystem path, under a `PreToolUse` matcher of `*`. Three
questions that decides, and each is a decision rather than a lookup:

- **Which field names a path.** `file_path`, `path`, `notebook_path`, `file`,
  `paths` are all plausible spellings and an MCP server chooses its own. A
  value that merely looks like a path is not one — `internal/readers` had this
  problem for shell tokens and answered it with a table over a closed set,
  which is exactly what is not available here.
- **What to do with a field that cannot be settled.** This is the fail-closed
  question, and answering it wrong in the safe-looking direction blocks every
  call of every tool nobody has a rule for. The `Bash` surface's answer — an
  unknown command contributes no operands, and an unresolvable operand of a
  *known* one blocks — is the shape to argue from, not to copy: there the
  closed set is a table this repo authored, and here there is no set.
- **Whether the hook can bound what the call would return.** A path-naming
  field is not enough on its own. A search tool takes a pattern and a root and
  returns matching lines from files it chooses, so bounding it means scanning
  the tree, which is not a thing a `PreToolUse` hook can do per call. Such a
  member stays out with the reason written down, rather than being covered
  badly.

Two members are worth driving first, because they are the ones a default
install reaches without any MCP server: a skill or subagent load, which puts a
file in front of the model the way `@path` does, and whatever the environment's
own search tool turns out to be. Drive them the way Q77 was driven — a hook
wired to `PreToolUse` with a `*` matcher, logging raw stdin, and the answer
read from the session transcript rather than from what the model says happened.
