# `TestTheShippedFileLoads` re-asserts what `loadFrom` already fataled on

Two of the test's three assertions cannot report. `loadFrom` records into the
`recorder`, the test fatals on any recorded failure, and the two assertions
after that fatal are the same two checks `loadFrom` just ran:

- the fatal: `internal/testvec/vectors_test.go:40:if len(rec.failures) != 0 {`
- the floor again: `internal/testvec/vectors_test.go:43:if len(set) < minVectors {`
- the values again: `internal/testvec/vectors_test.go:47:if got := set.Get(t, id); got == "" {`

Any file that would satisfy line 43's condition made `loadFrom` record the
floor failure, so line 40 aborts first. Any file that would satisfy line 47's
made it record the empty-value failure, and line 40 aborts first there too. The
only way to reach either assertion is for both to be false.

The floor arm is driven; the empty-value arm is the argument above and nothing
more. Driven 2026-09-17 by raising `minVectors` above the population and
running the test alone:

```
exhibit:vectors_test.go:41: loading the shipped file failed: [...credentials.json holds 11 vector(s), want at least 99]
--- FAIL: TestTheShippedFileLoads
```

That pointer carries the `exhibit:` marker because it is quoted `go test`
output rather than a citation this row relies on.

Line 44's message — `the shipped file holds %d vector(s), want at least %d` —
is not in that output and cannot be: a file under the floor is the only thing
that produces it, and such a file aborts at line 40 first.

## Why it is worth a row rather than a deletion in passing

It is the shape this store already has two rows about — Q158, an assertion that
cannot fail for the check it names, and Q66, a mutation control aimed at a true
equivalence. This one is the strongest form: an assertion no input reaches. It
reads as coverage, and a reader counting what the suite checks counts it twice.

## What it does not settle

Whether the repair is to delete the two assertions or to make them the only
ones — dropping the `recorder` and letting `loadFrom` fail through a real
`*testing.T`, so the test asserts the shipped file loads and nothing else. The
second is smaller and loses the `rec.failures` message, which is the one place
a reader sees *what* went wrong rather than *that* it did. Decide it at the
row.

## Provenance

Found 2026-09-17 while lowering `minVectors` for Q159, by asking what else in
the package reads the floor. Line 47's arm has no cheap drive: the test reads
the shipped file through `find`, so making it carry an empty value means
mutating tracked corpus data. The `%d vector(s), want at least %d` text appears
twice — once in `loadFrom`, once here — and only the first can print.
