# Two credential shapes that are published as documentation

Eight of the ten shipped rules end in a check that a documentation example
cannot pass — an entropy floor drops `AKIAXXXXXXXXXXXXXXXX` at 1.0219 bits per
byte against 3.6842 for a real key. Two rules have no such check, and for both
of them the documented example is byte-identical to the real thing.

**`private-key-block`** matches the PEM header and nothing else, because the
header is a fixed string and a floor over a constant is not a check. A page
that quotes `-----BEGIN RSA PRIVATE KEY-----` to explain what one looks like is
a false positive with no mechanism standing between it and the output.

**`jwt`** matches three base64url segments with the first two opening `eyJ`, at
a floor of 3.5 bits. The sample token on jwt.io clears that comfortably, and it
is pasted into a very large number of READMEs. A real JWT and a sample JWT are
the same object; only the signing key differs, and the scanner cannot see it.

Neither has a case in `testdata/corpus/`, so the `precision` gate is currently
silent about both. That is the first thing to fix: plant the two documents in
the clean half and read what happens, which will be two findings and a red
gate. What to do about it is the decision.

Three answers, and the corpus is what chooses between them.

- **Require more than the header.** A private key is a header plus a base64
  body plus a footer; requiring the body line makes a bare quoted header quiet
  and costs nothing real, since a key without its body is not a key. RE2 has no
  lookaround but does have `\n`, so this is expressible.
- **Fold in a placeholder denylist**, as `card-placeholder` already does for
  payment cards. For `jwt` that is a handful of published sample tokens; the
  argument against is `card-placeholder`'s own — see [Q33](Q33.md) — that a
  vendor's list has no boundary.
- **Drop the rule.** `jwt` is the weaker of the two: a JWT in a transcript is
  usually already expired, and the rule's recall is bought at a precision cost
  nothing else in the ruleset pays.

What is not an answer is an exception in the corpus. A rule that needs one is a
rule to drop, which is the whole argument for pinning the clean count at zero.
