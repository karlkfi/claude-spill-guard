# Under zsh, `time`'s options are peeled as though the shell were bash

Q252 peeled one `-p` then one `--` after `time`, in that order and unquoted,
which is bash's grammar and upstream's `strip_sh_keywords`. The peel does not
ask which shell it is. With the hook configured for zsh, `time -p cat <key
file>`, `time -- cat <key file>`, `time -p -- cat <key file>` and `time -p
FOO=1 cat <key file>` deny and zsh 5.9 prints no key, driven 2026-11-05. That
is a false deny, and zsh's class rather than the port's.

Q223's own two readings are gone from this row. The segmenter now keeps command
position across the same options, so `time -p case …` is the keyword and `time
-p f () { … }` a definition, and the lexer's wider `afterTime` is
[Q259](Q259.md), upstream-first. Neither of those changes this one: under zsh
5.9 `time -p case x in y) …` is a parse error and `time -p f() { cd w; }; cat
f` prints the key, and the hook defers on both.
