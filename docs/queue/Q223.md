# `time -p` and `time --` hide the command behind them

`time -p cat <key file>` and `time -- cat <key file>` exit 0 with no verdict
and nothing on stderr, while `time cat <key file>` blocks. bash 5.3.15 runs
`cat` in all three: driven 2026-11-01 under `env -i bash --norc --noprofile
-c`, each printed the file. The hook side was driven the same day through
`hook.Run` by a throwaway test on the Q185 branch, whose change does not touch
the head peel, so this reads the same on `main` by inspection rather than by a
drive there.

`ShKeywordPeel` strips `time` as a reserved word and stops, so `-p` or `--`
becomes the command name, no reader row matches, and the segment contributes
no operands.

This is a port. Upstream's `strip_sh_keywords` peels `time`'s own options as
its Q241: one `-p`, then one `--`, in that order and unquoted, measured there
on bash 5.3 -- `time -p -- cat f` runs `cat`, while `time -- -p cat f`, `time
-p -p cat f` and `time "-p" cat f` each run a program named `-p`. Read at
claude-bouncer `00c94bc`, `lib/bouncer_parse.py`. Port it with its rows,
including the three that must stay unpeeled. The Q185 lexer already skips
`-p` and `--` after `time` when it decides command position, so the two
readings would agree once this lands.

The same stop hides a definition. `time -p f() { cd w; }; cat x` reads `x` in
bash 5.3.15, but the Q212 change reads the header only behind a bare `time`,
so here `f` is a call and its body runs as the current shell. The port should
let the definition reader take `time`'s options too.
