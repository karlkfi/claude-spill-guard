# `time`'s options hide a definition, and the lexer peels them too far

Q252 peeled one `-p` then one `--` after `time`, in that order and unquoted, which
is upstream's `strip_sh_keywords` grammar, measured there on bash 5.3 as its Q241
and read at claude-bouncer `00c94bc`, `lib/bouncer_parse.py`. So `time -p cat <key
file>` and `time -- cat <key file>`, which crossed silently, now deny, and `time --
-p cat <key file>`, `time -p -p cat <key file>` and `time "-p" cat <key file>` stay
unpeeled, as bash runs a program named by that word and prints no key. Two
readings are left.

**A definition stays hidden.** `time -p f() { cd w; }; cat x` reads `x` in bash
5.3.15, but the Q212 change reads the header only behind a bare `time`, so here
`f` is a call and its body runs as the current shell. With a key in `x`, the call
gets no verdict. The definition reader should take `time`'s options too.

**The lexer's `afterTime` is wider than the peel.** It never clears on `-p` or
`--`, so it reads command position past any number of them. That decides only
whether `time -- -p FOO[a b]=x` is read as a subscript, and it is not driven here.

The peel also does not ask which shell it is. With the hook configured for zsh,
`time -p cat <key file>`, `time -- cat <key file>`, `time -p -- cat <key file>`
and `time -p FOO=1 cat <key file>` deny and zsh 5.9 prints no key, driven
2026-11-05. That is a false deny and zsh's class rather than this row's, so it is
stated here and not owed by the port.
