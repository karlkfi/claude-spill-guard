# CI gate for the backlog store, and a test that no index is committed

The store under `docs/queue/` has its own format rules — frontmatter, order
keys, filename agreeing with `id`, a title cap, blocked items opening with what
they wait on — and nothing currently checks them. `scripts/queue.py lint` is
vendored here already; this wires it into CI so the rules hold outside sessions
that happen to run the skill.

Two halves, and the second is the one that decays without a gate.

## The index must stay uncommitted

A rendered, rank-sorted index is the obvious thing to add the first time
someone finds that a directory listing sorts `Q1, Q10, Q11, Q2`. It is also the
one file every completing session would have to edit, which is the contention
the per-item layout exists to remove. Two sessions deleting adjacent rows
conflict; git needs one unchanged line between two changes and adjacent rows
leave none.

So gate the **absence**: a test that fails if a committed index reappears. It
costs one grep and holds the rule against the next reasonable person.

Render on demand instead — `python3 scripts/queue.py render`, and
`--format table --all` into the CI job summary so the ordered backlog is
readable from the Actions tab without a checkout.

## Also worth wiring

`queue.py claims` over the branch's added IDs, with `--strict` under CI where a
network is guaranteed. It fails an ID that holds no reservation on the remote,
which turns hand-picking an ID into a failure at the commit that files the row
rather than at the rebase that collides. The CI checkout needs `fetch-depth: 0`
— a shallow one has no merge base, which under `--strict` is a failure rather
than a skip.
