# Hook entry: payload decode, verdict encode, and the `hook` subcommand

The version-skew decision in
[`distribution.md`](../design/distribution.md#version-skew-settled-by-removing-it-not-by-detecting-it)
compiles the shipped set into the binary, so the `go:embed` of
`rules/spill-guard.json` lands here. The ruleset it embeds exists; nothing
imports it yet.

## Why this row exists at all

Q8 was titled "Hook entry and the launcher that denies when the binary is
gone" and its body specified only the launcher: the 127 and 126 measurements,
the deny object on stdout, the resolution order, the two packaging rules, and
the version-skew question. Nothing in it asked for payload decode, verdict
encode, or a `hook` subcommand. The launcher shipped; the other half of the
title did not, and the row went with it.

`internal/hook` appears exactly once in the repository, in the proposed tree in
[`docs/design/README.md`](../design/README.md#repo-layout). No row owned it
before this one, so without this file the gap would have to be inferred later
from a completed row's title — which is the shape that reads as covered.

## What it has to do

`spill-guard hook` reads a Claude Code payload on stdin, decides what of it is
scannable, runs `internal/scan` over that, and writes a verdict.

- **Decode.** The events that can actually withhold content are
  `UserPromptSubmit` and `PreToolUse`; the design's hook-surface table settles
  that, and it is settled by measurement rather than by reading —
  `PostToolUse` cannot withhold a result, so nothing is catchable after the
  fact. What each event carries differs, and a decoder that silently accepts a
  shape it does not understand is the fail-open direction.
- **Choose what to scan.** For `PreToolUse` on `Read` this is the file at the
  path, opened locally. For `Bash` it is the command string plus the resolved
  file operands of the common readers. Splitting the command into its simple
  commands is `internal/bash`, which has shipped; deciding which of a segment's
  tokens is a path is [Q62](Q62.md), and neither is this row. What counts as
  human-typed is still open in the design.
- **Encode.** A `deny` decision object on stdout, which blocks whatever the
  process exits with. Not exit 2 with the reason on stdout: there stdout is
  discarded and the model is told the hook errored. The measured table is in
  [`docs/design/README.md`](../design/README.md#the-exit-code-contract-measured).
- **Emit nothing that carries a secret.** Rule id, path and byte offset, and no
  fragment — everything a hook writes reaches the API. Control characters get
  escaped before anything is written, because a path and a rule description
  both reach a terminal.
- **Say which files were not read.** `scan.Result` carries a `Skipped` reason
  beside the findings, and a hook that reports the findings alone tells a user
  a buffer nothing opened is clean. Binaries and UTF-16 with no byte-order
  mark both land there, so this is not a rare path.

## The part that is easy to get wrong

Every internal error blocks with a reason. That is the whole inversion this
project makes against its sibling guards, and the hook entry is where it either
holds or does not: a decoder that shrugs at a payload it cannot read, and lets
the call through, reports a safety it is not providing and leaves nothing in
the transcript to say so.
