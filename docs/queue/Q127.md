# Drive an MCP file reader against the reader-class test

Q87 drove the rest of the reader class and settled three of the four members
the v0.1.0 notes disclose under *Readers outside the three that are driven*: a
subagent load is covered, because a subagent's own tool calls fire the same
hooks; a search tool stays out, because nothing a `PreToolUse` hook opens can
bound a walk over a tree; a skill load stays out, because the payload is
`{"skill": "<name>"}` and resolving that back means reproducing a search order
nothing here has driven.

The fourth is an **MCP server's file reader**, and it is undriven. This row is
where that lives now that Q87's is gone — the gap is disclosed in three places
(the release notes, *What it is not*, and the design's
[reader-class section](../design/README.md#the-rest-of-the-class-driven)) and
until this was filed nothing in the store scheduled the measurement.

## The method is already written, and it is the row's whole content

The design section numbers three readings, in an order where each is cheap only
if the one before it came back yes. Take them against a real hook, and read
every answer from the session transcript the payload's own `transcript_path`
names rather than from what the run printed:

1. **Does the hook see the call at all?** A `PreToolUse` matcher of `*` and a
   stdin logger. Q87's drive established that a `*` matcher does deliver tools
   this repo has no case for — `Skill`, `Agent`, `ToolSearch`, `WebFetch` all
   arrived — so the expected answer is yes, and an MCP tool arriving under a
   name like `mcp__<server>__<tool>` is what would confirm it.
2. **Has the content crossed already?** Only a payload the hook can open for
   itself is stoppable. The control is a deny: plant a marker in the file, deny
   the call, and check the marker is absent from the transcript. Q87's skill arm
   is the shape — 1 occurrence allowing, 0 denying, same prompt and directory.
3. **Can the hook bound what the call would return?** One file is bounded. A
   tree walk is not, and neither is a name the harness resolves by an
   unpublished rule. This is the reading that decides coverage rather than
   membership, and it is where the search tool and the skill load each stopped,
   for two different reasons.

A member that fails 3 stays out **with the reason written down**. That is an
outcome and not a gap, and saying so is the point: the release notes name the
member, so the next set of notes has to say which of these three it failed and
why, rather than repeating that it has not been driven.

## What is not known, and what would revive this if it cannot be run

**Whether an MCP file reader is installable and drivable on this machine has
not been checked.** Q87's drive ran in a throwaway project with no MCP server
configured, so the whole class was out of reach of that instrument by
construction. If a server carrying a file reader cannot be stood up here, this
row's honest outcome is to say so and name the trigger instead: it revives when
one is installed, or when someone reports the shape from a session where one is.

Do not close it by reasoning about what an MCP payload probably looks like.
Q87's own finding is that the guessable answer was wrong in both directions —
the payload-shape test this repo proposed misses `Skill`, whose `tool_input`
names no path at all, and admits a search root it cannot bound. An MCP server
chooses its own field names, so the guess is worth less here than anywhere else
in the class.

## What it is not

**Not a matcher change.** Q87 settled that neither a list of tool names nor a
payload-shape test closes the class, and that membership is an argument about
what the call returns, which is per tool. `hooks.json` and the set-equality test
in `internal/hook/manifest_test.go` stay as they are until a member is driven
and turns out to be both stoppable and boundable.

**Not a v0.2.0 gate.** It was not one, and v0.2.0 has shipped:
[the notes](../releases/v0.2.0.md) record the MCP reader as the one member of
the reader class still undriven, under *What it does not read*. The gap is
disclosed with this row behind it.
