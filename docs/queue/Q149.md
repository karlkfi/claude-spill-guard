# Bind a `for` loop variable to its literal list

`for f in docs/queue/Q135.md docs/queue/Q145.md; do cat "$f"; done` is the
first of the three shapes Q134 measured, and the one the resolver in
`internal/hook/vars.go` still records: `for` is in `argAssignerCmds`, so the
header poisons `f`, and `cat $f` is an operand that expands at run time. The
other two shapes -- a literal `cd` target and a literal assignment -- are
followed now, so this is the remainder of Q134's class.

Upstream has it: `for_loop_binding` and `literal_for_item` in
`bash-workspace-guard.py` (its issue 70) record the loop variable's candidate
set when every item is a literal, and `expand_loop_candidates` expands a token
using it into one path per candidate, capped at `MAX_LOOP_CANDIDATES` (256) and
poisoning over the cap rather than truncating. A glob item is kept as the
pattern itself (its issue 99), a brace item poisons the variable, and a nested
loop's inner list expands over the outer variable's candidates.

What the port has to decide before it is written: a candidate set is a set of
files, and a reader over `$f` then reads every one of them -- which is exactly
what bash does, so scanning all of them is the file set the command sends,
not a walk. That is the reading the directory refusal turned on, and it holds
here. The cap is the scanner's own budget in `internal/hook/deadline.go`
rather than a count, unless driving it says otherwise.

**Measured 2026-09-04** in Q134: one of the four hard blocks in one session was
this shape; since #117 it is a coverage record rather than a block. The rate on
this arm alone has not been taken -- take it before ranking this above Q135.
