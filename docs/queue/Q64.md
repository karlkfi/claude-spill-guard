# A dotfile path cannot be cited, and the exhibit marker cannot waive it

`CITATION_RE` in `scripts/vendor/claude-skills/queue.py:60:CITATION_RE` opens
with `\b`, and a word boundary cannot sit between a space and a dot. A citation
into a dotfile directory therefore matches from the first word character
instead: a pointer at the workflow under `.github/workflows/` is read as
`github/workflows/...`, which resolves from neither the store's parent nor the
repository root. The reported message is `which does not resolve from <store
parent>; re-point or drop it`, sending a reader to check a path that is
correct.

**The `exhibit:` marker does not rescue it, which is the half worth knowing.**
`lint` waives a citation when the text immediately before the match is
`exhibit:`. The match starts *after* the dropped dot, so the preceding text
ends with `.` instead, and the waiver never applies. Measured 2026-08-26 by
running the real regex over three inputs:

| input | match starts on | waiver applies |
|---|---|---|
| `exhibit:` then a dotted workflow path with a line | `github/workflows/…` | no |
| `exhibit:scripts/gates.py:40:import os` | `scripts/gates.py` | yes |
| `exhibit:` then the same workflow path with the dot removed | `github/workflows/…` | yes |

So a dotfile path is uncitable and unwaivable together. A row that needs to
discuss one has no legal way to write it — this row is the instance: it
describes the failing form in prose because quoting it reddens the gate, and
that is the whole evidence. Three earlier drafts of this file failed
`--strict stale-citation` on their own subject.

**Q45 is what makes this cost something.** Before it, an unresolvable citation
was a note at exit 0 on every pull request. The class now binds on every event,
so a row citing a workflow reddens the branch that files it. This repository's
workflow is the file a row is most likely to want to cite: every gate and every
mutation control lives in it.

The fix is in vendored code, so it is upstream work in `session-backlog` plus a
`make vendor` refresh rather than a local patch — `scripts/README.md` pins the
file by digest and the `vendor` gate fails an edit in place. Anchoring on
`(?<![\w.])` rather than `\b` is the shape to check, together with whether
allowing a leading dot lets the pattern match ordinary prose ending in a
sentence, and whether it then swallows a leading `../` of the kind
`docs/queue/README.md` uses for its own relative links.
