# The Bash tool shell can be zsh, and every port here assumes bash

`internal/bash` is a port of `claude-workspace-guard`'s segmentation, and
`internal/hook/glob.go` expands against bash 5.3.15's rules. Both assume the
Bash tool runs bash. On this machine it does, because
`~/.claude/settings.json` sets `CLAUDE_CODE_SHELL=/opt/homebrew/bin/bash` --
and that is a setting rather than a property of the harness. The hook's own
environment carries `SHELL=/bin/zsh` beside it, which is what the setting is
overriding.

Measured 2026-09-07 while driving Q150: 1 of the 63 snapshots under
`~/.claude/shell-snapshots/` is `snapshot-zsh-1786953866950-kxpd9a.sh`, and it
carries no `shopt` line at all -- it restores zsh functions and options
instead. It predates the setting, so it is evidence the harness will snapshot a
zsh shell rather than evidence one is running now.

What a zsh tool shell would change is not only the glob options Q150 measured.
zsh's `nomatch` is on by default, so `cat nomatch*` is an error and reads
nothing where bash passes the literal through and this repo follows bash --
`docs/design/README.md`'s expansion table has that row, and under zsh it is
wrong in the direction that scans a file the command never opened. Word
splitting, `$(...)` handling and the `[[ ]]` forms differ too, so the
segmentation port is the larger surface.

**Measure:** what Claude Code does with no `CLAUDE_CODE_SHELL` set -- whether
it takes `SHELL`, and so how often a tool shell is not bash -- before deciding
between refusing to expand when the shell is not bash, porting the differences,
and stating the assumption. The hook cannot read the snapshot (Q150), but
`CLAUDE_CODE_SHELL` and `SHELL` are both in its environment, which is a cheaper
instrument than the one Q150 went looking for.
