# A skipped buffer is reported as a clean one

`scan.Buffer` returns no findings for a buffer it skipped and no findings for a
buffer it scanned and found nothing in. The two are the same value, so
`internal/hook` cannot tell them apart, and it allows the call either way — a
file nothing opened goes to the model with the hook having said nothing, which
is the state this whole project is built around refusing.

`IsBinary` is the skip that exists today: a NUL in the first 8 KiB, which the
design chose for throughput after one PNG turned out to be 55% of the benchmark
corpus. So `spill-guard hook` on a `Read` of a binary file returns silence, and
silence from this hook is supposed to mean checked.

## Why it is not simply "block a binary"

A PNG is not a spill and denying every image read makes the tool unusable, so
the skip is right and the reporting is what is missing. What the hook needs is
the reason, so a skip it can defend is separable from one it cannot.

Two skips, and they are not alike. A binary is a deliberate throughput
decision. Text this repo happens not to decode is not — a UTF-16 file with no
byte-order mark carries a NUL in its first 8 KiB and is skipped as binary while
being exactly the readable text a secret sits in.

## What it depends on

[Q47](Q47.md) is the UTF-16 half and it is in flight: the pull request against
it adds a `scan.Result` with a `Skipped` reason beside the findings, which is
the shape the answer here wants. That change also moved a requirement into
Q50's body — "a hook that reports the findings alone tells a user a buffer
nothing opened is clean" — and Q50 was completed and deleted, so this row is
where that requirement now lives.

So the order is Q47 first, then this: give `internal/hook` the reason, decide
per reason whether it blocks, and pin both arms. `internal/scan` growing a
`Skipped` field that no caller reads would leave this exactly where it is.
