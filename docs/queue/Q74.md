# A skipped buffer is reported as a clean one

`scan.Buffer` now says which buffers it did not read — Q47 shipped `Result`
with a `Skipped` reason beside the findings — and `internal/hook` reads the
findings and nothing else. So a buffer the pipeline declined still contributes
none, the call is allowed, and a file nothing opened goes to the model with the
hook having said nothing. That is the state this whole project is built around
refusing, and it is now one field away rather than unreachable.

Two reasons exist on the trunk: `SkippedBinary`, a NUL in the first 8 KiB,
which the design chose for throughput after one PNG turned out to be 55% of the
benchmark corpus; and `SkippedUTF32`, a byte-order mark the decode stage names
rather than guesses at. `spill-guard hook` on a `Read` of either returns
silence, and silence from this hook is supposed to mean checked.

## Why it is not simply "block a binary"

A PNG is not a spill and denying every image read makes the tool unusable, so
the skip is right and the reporting is what is missing. What the hook needs is
the reason, so a skip it can defend is separable from one it cannot.

Two skips, and they are not alike. A binary is a deliberate throughput
decision. Text this repo happens not to decode is not — a UTF-16 file with no
byte-order mark carries a NUL in its first 8 KiB and is skipped as binary while
being exactly the readable text a secret sits in.

## What it depends on

Nothing, any more. Q47 has merged and carried the mechanism with it, so what is
left is entirely on this side: give `internal/hook` the reason, decide per
reason whether it blocks, and pin both arms.

That row also moved a requirement into Q50's body — "a hook that reports the
findings alone tells a user a buffer nothing opened is clean" — and Q50 was
completed and deleted, so this row is where it lives.

The decision is not the same for both reasons, which is why this is a row
rather than a one-line change. A binary is a deliberate throughput choice and
denying every image read makes the tool unusable; text the repo happens not to
decode is not, and is exactly the readable content a secret sits in. So the
answer is per reason, and `internal/scan` carrying a field no caller reads is
what this row exists to end.
