# Two readings the port shares with claude-bouncer, which fixes them first

Blocked on claude-bouncer. Both readings below match upstream line for line, so
the fix lands in claude-bouncer first and is ported here; a local fix would
diverge silently from the port. Since 2026-11-09 a claude-bouncer session owns
both halves there, `_scan_dollar_paren` and `_after_time`, so this row is
completed by porting that change once it merges. Neither has a driven verdict
difference here yet.

**A substitution ends at a `case` pattern's `)` after `!` or after a closer.**
`scanDollarParen` opens a `case` only where `cmdPosKeywords` puts a word in
command position, and its character arm adds `{`, `&` and `|`. `!` is not in
that set, nor is a `then` behind a `}`, so the pattern's `)` is read as the end
of the substitution. bash 5.3.15 prints `in` for `echo $( ! case a in a) echo
in;; esac )`. Driven against the Go scanner at `4256207` and against
upstream's `_scan_dollar_paren` at claude-bouncer `c1e1f81`
(`lib/bouncer_parse.py`, keyed on `_CMD_POS_KEYWORDS`), the two return the
same thing:

| Input | Body both scanners return | End |
|---|---|---|
| `$( ! case a in a) echo in;; esac )` | ` ! case a in a` | 17 of 34 |
| `$( if { :; } then case a in a) echo in;; esac; fi )` | ` if { :; } then case a in a` | 30 of 51 |
| `$( { case a in a) echo in;; esac; } )` | the whole body | 37 of 37 |

Q217 fixed the segmenter's half of this, which is this repo's own code, and
left the scanner alone. One verdict-level reading has been taken, by Q217's
reviewer: `echo $( ! case x in y) SP=…;; esac ); cat $SP/f` defers before and
after it. No shape has been driven that crosses.

**The lexer's `afterTime` reads command position past any number of `-p` and
`--`.** It never clears on either, so `time -- -p FOO[a b]=x cat x` is read as
a subscripted assignment prefix. bash 5.3.15 runs a program named `-p`, prints
`-p: command not found`, and opens nothing. The peel Q252 ported takes one
`-p` then one `--`, and since Q223 so does the segmenter's command position,
through `timeOptionPeel` in `internal/bash/lex.go`, so the lexer is the one
reading of `time` still wider. It decides only whether that word is a
subscript, and no verdict difference was driven.
