# Two readings the port shares with claude-bouncer, which fixes them first

Blocked on claude-bouncer. Both readings below match upstream line for line, so
the fix lands in claude-bouncer first and is ported here; a local fix would
diverge silently from the port. The two halves wait on different things.
`_scan_dollar_paren` is claude-bouncer #322, open on 2026-11-10. `_after_time`
was accepted by a claude-bouncer session on 2026-11-09 and has no PR or queue
row there yet, so its port is separate from #322's. The `afterTime` half lets a
key cross with no verdict and no record, driven below; the `scanDollarParen`
half has no driven verdict difference.

**A substitution ends at a `case` pattern's `)` after `!` or after a closer.**
`scanDollarParen` opens a `case` only where `cmdPosKeywords` puts a word in
command position, and its character arm adds `{`, `&` and `|`. `!` is not in
that set, nor is a `then` behind a `}`, so the pattern's `)` is read as the end
of the substitution. bash 5.3.15 prints `in` for `echo $( ! case a in a) echo
in;; esac )`. Driven against the Go scanner at `4256207` and against
upstream's `_scan_dollar_paren` at claude-bouncer `c1e1f81`
(`lib/bouncer_parse.py`, keyed on `_CMD_POS_KEYWORDS`), the two return the
same thing:

| Input | Body both scanners return | End |
|---|---|---|
| `$( ! case a in a) echo in;; esac )` | ` ! case a in a` | 17 of 34 |
| `$( if { :; } then case a in a) echo in;; esac; fi )` | ` if { :; } then case a in a` | 30 of 51 |
| `$( { case a in a) echo in;; esac; } )` | the whole body | 37 of 37 |

Q217 fixed the segmenter's half of this, which is this repo's own code, and
left the scanner alone. One verdict-level reading has been taken, by Q217's
reviewer: `echo $( ! case x in y) SP=…;; esac ); cat $SP/f` defers before and
after it. No shape has been driven that crosses.

**The lexer's `afterTime` reads command position past any number of `-p` and
`--`, and a key crosses through it silently.** It never clears on either, so
after `time -- -p` or `time -p -p` the next `NAME[` is read as a subscripted
assignment prefix, its subscript taken from the raw text up to `]` as Q185
ported. `Segments` at `f669269` returns `time -- -p FOO[a;cat k.sh;b]=x true` as
one segment with `FOO[a;cat k.sh;b]=x` a single token, where `echo -p
FOO[a;cat k.sh;b]=x true` is three. bash runs a program named `-p` instead, so
the word after it is an argument, the `;` inside the brackets is a separator,
and the command between them runs. The peel Q252 ported takes one `-p` then one `--`, and since Q223 so
does the segmenter's command position, through `timeOptionPeel` in
`internal/bash/lex.go`, so the lexer is the one reading of `time` still wider.

Driven with `k.sh` a copy of `testdata/corpus/planted/github-token.sh`, bash
5.3.15 under `env -i bash --norc --noprofile -c`, and binaries built at
`f669269` and `c57b333` given each command as a `PreToolUse` `Bash` payload,
which read the same:

| Command | bash | Hook |
|---|---|---|
| `cat k.sh` (control) | rc 0, prints the key | deny |
| `time -- -p FOO[a;cat k.sh;b]=x true` | rc 127, prints the key | exit 0, empty stdout, empty stderr |
| `time -p -p FOO[a;cat k.sh;b]=x true` | rc 127, prints the key | exit 0, empty stdout, empty stderr |
| `time -p FOO[a;cat k.sh;b]=x true` | rc 0, `not a valid identifier`, no key | exit 0, empty stdout, empty stderr |

The middle two are the fail-open: no verdict and no coverage record, while the
command prints the key. The last is correct, since one `-p` is `time`'s and the
word after it is the assignment bash refuses. The session orchestrator
measured the same rows on `7f89929` and on Q223's `0eff7fb`, before the merge.
