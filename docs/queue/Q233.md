# A tee to stderr ahead of the filter sends grep output unfiltered

`grep -rn x d | tee /dev/stderr | spill-guard filter` is allowed, on `main`
and on #228's head alike. The filter is the last stage, so the rewrite test
counts the grep as filtered, but `tee` writes every matched line to stderr
before the filter sees it, and the `Bash` tool returns stderr to the model. A
key the filter would withhold crosses through the copy.

Reviewer A found it while re-driving 93 shapes against bash 5.3.15 for #228,
on 2026-11-01, and called it pre-existing rather than introduced by Q208.
That reading is the reviewer's; this row has not re-driven it.

The class is any stage between the grep and the filter that writes its input
somewhere other than its stdout: `tee` to `/dev/stderr`, `/dev/fd/2` or a
file the model later reads, and any stage with `2>&1` reversed or `>&2`.
#228's `StdoutAway` already answers where a stage's stdout goes; this asks
where its *copies* go.

**Done** when such a pipeline is refused with the plain recursive-grep
reason, `tee` to a regular file named elsewhere in the string is decided the
same way or recorded, and a test row pins each arm alongside a `grep -rn x d
| tee out.log | filter` control whose answer is stated.
