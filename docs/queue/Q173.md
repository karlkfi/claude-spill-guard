# The design doc still says every scan starts a goroutine

[`docs/design/README.md`](../design/README.md), under *A deadline is available
even though nothing here takes a `context`*, says "the scan runs on its own
goroutine, the verdict is written by the one waiting on it". That is the
mechanism for a deadline that fires mid-scan, and it is still true of the arm
the paragraph drives.

It is no longer true of every arm. A budget already spent when `within` is
entered returns before the goroutine exists, so there is one path where no
scan is started and no goroutine is waited on. The paragraph reads as a law
over the whole function.

## Why it is small, and why it is not nothing

No gate catches it and none should: the budget table in the same section is
unchanged, `CLAUDE.md` puts the deadline argument in
[`internal/hook/deadline.go`](../../internal/hook/deadline.go), and that file
carries the spent-budget case at its own site. So the doc is stale in one
clause rather than wrong about the mechanism it exists to explain.

What makes it worth a row anyway is the direction it is stale in. The
paragraph's subject is *a deadline does not have to interrupt the work*, and
the spent-budget path is the one case where there is no work to interrupt —
a reader tracing why a deferral happened would look for a goroutine that was
never started.

## What a fix is

One clause, saying the goroutine is what a budget with time left does. Raised
by the independent reviewer on the pull request that introduced the case, as
an unmeasured note rather than a holding finding; the worker that wrote it
kept to the two files its brief scoped, which is why this is a row.
