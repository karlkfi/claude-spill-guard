# The plan doc links rows it outlives, so completing one reddens the tree

`docs/plan/v0.4.0.md` names every row the tag waits for as a live markdown
link into `docs/queue/`. Completing a row deletes that file, so the link
dangles, and `check-doc-links.py` is a gate rather than a note. Measured
2026-09-07 at 04a1ba7, deleting the two rows one session was dispatched to
complete:

```
$ git rm -q docs/queue/Q115.md && python3 scripts/check-doc-links.py
broken link: docs/plan/v0.4.0.md:47: ../queue/Q115.md

1 broken link(s)
```

Exit 1, for one row. The same probe over the two rows that session was
dispatched to complete reported **four** broken links when it was first taken
that morning, at 04a1ba7 — two in this file and two in rows citing the deleted
one. It is not re-quoted here because two of those four files have since been
deleted by their own completions, which is the failure mode rather than an
aside: evidence about this table goes stale as the table's subjects are removed. So every session completing a v0.4.0 row has to edit the plan doc to go
green, and the eleven rows the tag waits for are eleven adjacent lines of one
table. Two of them sat two lines apart in that session's own pair of pull
requests, with a third session's row between them.

## The repo already has the convention this file is not following

`docs/queue/README.md` fences its own example reference and says why: *As a
live link it would dangle the day Q7 is completed.* An inline code span is
skipped by the link checker for the same reason. The plan doc's table is
exactly that situation — a reference to something designed to be deleted — and
it uses live links.

Writing the IDs as inline code spans costs the navigation, which is the thing
worth weighing rather than assuming: a reader of the plan doc wants to open the
row. Two answers that keep it are linking `docs/queue/` once at the head of each
table, or having the check tolerate a link into `docs/queue/` specifically,
which is a wider change to a gate and needs its own control.

## Not the same as retiring the record

Q119 shipped the `release-scope` gate in #132, which deletes
`docs/plan/<tag>.md` when the tag is cut. That is the file outliving its
release. This is the file contending *during* it: the links break while the
plan doc is still correct and still wanted, so retiring it at tag time leaves
every completion between now and then paying for them.

Both halves were measured on the same afternoon. #132 had to mark its own row
in that table to go green, and the session completing the two rows above hit a
content conflict on the same four lines an hour later — the two marker forms
had diverged and were reconciled by hand. Two of eleven rows, and the two that
happened to be worked first.
