# A zsh tool shell defers every glob, so a `*` v0.4.1 blocked now crosses

Q163's fix refuses **every** glob operand where the tool shell is not bash, and
the call defers. That closed the silent `**` fail-open and opened a recorded one
on the common case: `cat *.env` over a planted key was a deny on v0.4.1 and is
no verdict on `main`, so the file crosses with only a coverage record behind it.

Driven 2026-09-26 on binaries built from `v0.4.1` and from `abe6cf5`, payload
`cat <pattern>` with `cwd` at `testdata/corpus/planted/` (four `.env` files,
each carrying a key), `CLAUDE_CODE_SHELL` unset:

| `SHELL` | command | v0.4.1 | `abe6cf5` |
|---|---|---|---|
| `/bin/zsh` | `cat *.env` | deny | **no verdict**, 1 coverage record |
| `/bin/zsh` | `cat aws-access-key-id.env` -- control | deny | deny |
| Homebrew bash | `cat *.env` -- control | deny | deny |
| Homebrew bash | `cat aws-access-key-id.env` -- control | deny | deny |

The named-file control says the scanner still reads the file under zsh, and the
bash control says the glob path still works there, so the no-verdict row is the
refusal and nothing else. Q163's PR drove its table under bash only and priced
the change as a count of affected calls, so this row was not in front of the
merge.

**Who it reaches is not measured.** Claude Code runs zsh unless
`CLAUDE_CODE_SHELL` or `SHELL` names bash, and zsh is the default login shell
for macOS accounts created since 10.15. That is a reason to expect the exposed
population to be large, not a size for it.

## The fix the maintainer chose

Refuse only the globs whose zsh expansion can differ from bash's, and expand the
rest as today. Q163's PR named this as the preferred fix and set it aside
because it "rests on the rest of the expansion agreeing, which is unmeasured"
-- that measurement is this row's first step, scoped to globbing alone, which
is a narrower slice than [Q184](Q184.md) asks for.

Shapes to drive under zsh 5.9 against bash 5.3.15 before writing the refusal,
each under zsh's default options:

- `**` and `***` -- recursive in zsh. The known divergence, stays refused.
- A trailing parenthesised group, `*(.)` -- a glob qualifier in zsh by default,
  a syntax error in bash.
- A word beginning `=`, `=cat` -- command-path expansion in zsh.
- An unmatched pattern -- an error in zsh, so nothing is read; bash passes the
  word through. Over-scanning here costs precision only.
- `^`, `~`, `#` -- inert unless `EXTENDED_GLOB`, which the snapshot residual
  already says this hook cannot read.
- A leading `.` and bracket classes -- expected to agree; drive rather than
  assume.

Whatever the table says, a pattern in the agreeing set has to scan under zsh
and deny on the fixture above, and one outside it has to keep deferring. Both
arms need a test.

**v0.5.0 is held for this**, by the maintainer's decision on 2026-09-26:
[`docs/plan/v0.5.0.md`](../plan/v0.5.0.md) has the scope.
