# Twelve mutation controls cannot be driven locally on macOS

`CLAUDE.md` names one instrument for a workflow step: extract its `run:` block
verbatim from the YAML and run it under `bash -e`, because re-running the
repo's gate over the final tree never enters a `run:` block's shell. Twelve
steps in `.github/workflows/tests.yml` open with `sed -i 's/…/…/' <file>`, and
that spelling is GNU's. BSD `sed`, which is what macOS ships, takes `-i`'s next
word as the backup suffix and the filename as the script, and dies:

```
sed: 1: "PRIVACY.md
": extra characters at the end of P command
```

Under `-e` the step exits there, before its own precondition runs, so a
control driven locally reads as failing for a reason that is about the host
and nothing about the tree. Measured 2026-09-06 while landing Q130: 6 controls
extracted and driven, 4 red on the message each asserts, 2 dead on the `sed`
line — and the two were only settled by re-writing each mutation as a Python
edit and driving that instead. Q103 met the same thing on 2026-09-01 and
recorded it as a caveat on its method ("verbatim except that BSD `sed -i`
needs the suffix argument"), which is a note about the reader's workaround
rather than about the file.

`git diff --quiet` preconditions do not reach this. They catch a `sed` that ran
and matched nothing; a `sed` that refused to run has already ended the step.

## What to build

Make the twelve steps drive on both hosts. Two spellings already in the file do:
the Python heredoc edits the newer controls use, and `sed -i.bak … && rm
<file>.bak`, which both seds accept. Whichever is chosen, drive every changed
step under `bash -e` on a Mac and on `ubuntu-latest` before merging, since the
step that is portable in the shell is the one whose assertion has never been
observed on the runner. A `macos-latest` leg over the control jobs is the
version that keeps this from coming back, and Q42 already argues the runner
minutes are free on a public repo.

## Not the same row as Q103

Q103 is a control whose mutation stops biting and blames the gate. This is a
control that cannot start on one host. Different mechanism: a Q103 fix asserts
the mutation had its effect, and does nothing for a step that died before the
assertion.
