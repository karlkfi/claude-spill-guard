# The resolver reads a `case` arm as unconditional

`case x in y) P=/case;; esac; cat $P/f` resolves `/case/f`, and bash 5.3.15
ran no arm: `x` does not match `y`, P stays at the environment's value, and the
cat reads `/env/f`. The segmenter sees the arm's `)` at paren depth 0 and the
assignment after it as a plain segment reached through no operator, so `andOr`
in [`internal/hook/vars.go`](../../internal/hook/vars.go) opens a new list,
settled, and applies it. `TestThePortNeverResolvesToALiteralBashWouldNotUse`
pins the divergence beside the three Q92 spellings, so a fix here is a decision
rather than a surprise.

Bounded the way Q92's is: the unresolved form proceeds with a coverage record
since #117, so the guess trades that record for a scan of a path bash never
used, and the same bytes cross either way. What is wrong is the claim, and the
pin is what keeps the claim honest.

**Measured 2026-09-06** over a week of this machine's Bash calls: 25,195 calls,
95 with a `case` statement, 19 whose arm assigns a variable, 14 of those a
literal, and 9 expanded later in the same string. Against 655 assignments
reached through `&&` or `||` in the same week, which `andOr` now reads
correctly.

**The fix is in the segmenter, and it is not a one-liner.** A `)` at paren
depth 0 with no `(` open is a case pattern's close; from there to `esac` --
a word, not a separator, so it arrives as a segment's first token -- every
segment is conditional on a pattern match nothing here evaluates. Marking those
segments `Conditional` with an operator of their own and having `andOr` poison
what they assign, as it does for `||`, closes it, and `;;` needs recognising as
a list boundary too. Upstream has the same reading and no case handling, so this
is a divergence to state at the site the way `Inputs` and `Conditional` are.

**Two neighbours are not defects and are noted so nobody files them.** A
command whose exit status the resolver cannot know -- `true`, `:`, `test`, and
every reader -- unsettles its list, so `true && P=/lit; cat $P/f` records where
bash resolved; that is the fail-closed direction, and the cost is the 234
conditional assignments in the week preceded by something other than an
assignment or a followed `cd`, most of them `$(…)` values that were never
literals. And `if …; then P=/x; fi` stays unresolved because the keyword keeps
the segment out of the assignment group.
