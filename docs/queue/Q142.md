# Nobody here has checked which AWS key-ID prefixes the vendor issues

`aws-access-key-id` matches five: `A3T[A-Z0-9]`, `AKIA`, `ASIA`, `ABIA` and
`ACCA`. The ruleset was inherited rather than written, so where that list came
from is unrecorded, and this repository has never read AWS's own.

Q81 settled the half that could be settled here — it is completed and gone
from the store, so that reference is to `git log` and carries no link. Every
arm is now reachable by a test and each deletion is red, and the cost of
keeping an arm nobody can justify was measured: the four non-`AKIA` arms
compiled alone over `~/go/pkg/mod`, 220,674 files and 3,540 MiB of third-party
Go source, give 5 regex matches and 2 surviving the validators — both `ASIA`,
both the same
`golang.org/x/oauth2` test file in two versions. `A3T`, `ABIA` and `ACCA`
produce nothing over that population. So the arms stay: cutting one AWS does
issue costs a missed credential and keeping one it does not costs no measurable
precision.

What that argument cannot do is decide whether an arm is *real*, and the
measurement is why it is worth asking anyway — an arm with zero matches over
3.5 GiB has nothing behind it but the predecessor's word.

**It needs a reading this build graph cannot take.** `no-network` forbids
`net`, `net/http` and `os/exec` across the module, and nothing in the gate
fetches a page, so the answer comes from a person opening [AWS's IAM
identifiers reference][iam-ids] — the page
[`testdata/corpus/README.md`](../../testdata/corpus/README.md) already cites
for a different question — and writing down which prefixes its unique-ID table
names.

What to do with the answer: a prefix the table names gets a sentence in
[`rules/README.md`](../../rules/README.md) saying so, and one it does not gets
cut, with `TestEveryAWSPrefixArmIsReachable` and the vectors behind it dropped
in the same edit. Either way the paragraph Q81 left in `rules/README.md` under
"All five prefixes stay" is what gets deleted, because it says outright that
this reading is the thing that would reverse it.

**Do not settle this from another scanner's ruleset.** This set was inherited,
and [`docs/design/brief.md`](../design/brief.md) names gitleaks as a ruleset to
borrow rules from — so a prefix list that agrees may be the same list arriving
twice rather than two sources agreeing. Nobody here has traced which upstream
this rule's five came from, and that is a second thing this row could record if
it turns out to be cheap. The authority is AWS's own documentation either way.

[iam-ids]: https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html
