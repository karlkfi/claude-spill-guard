# Three of the five AWS key-ID prefixes are sourced to nothing

`aws-access-key-id` matches five: `A3T[A-Z0-9]`, `AKIA`, `ASIA`, `ABIA` and
`ACCA`. Two of them are sourced. `rules/README.md`,
[`internal/validate/aws.go`](../../internal/validate/aws.go) and
[`testdata/corpus/README.md`](../../testdata/corpus/README.md) all cite
`AKIAIOSFODNN7EXAMPLE` on AWS's IAM pages and `ASIAIOSFODNN7EXAMPLE` on its STS
ones — AWS printing a key on each of those two prefixes, which is as good as
this repository needs.

**`A3T`, `ABIA` and `ACCA` are traced to nothing.** The ruleset was inherited
rather than written, so where those three came from is unrecorded, and nobody
here has read AWS's own list.

Q81 settled the half that could be settled here — it is completed and gone
from the store, so that reference is to `git log` and carries no link. Every
arm is now reachable by a test and each deletion is red, and the cost of
keeping an arm nobody can justify was measured, each arm compiled alone over
`~/go/pkg/mod`, 239,671 files and 5.05 GiB of third-party Go source:

| Arm | regex matches | surviving the validators |
|---|---|---|
| `A3T` | 0 | 0 |
| `AKIA` | 56 | 0 |
| `ASIA` | 5 | 2 |
| `ABIA` | 0 | 0 |
| `ACCA` | 0 | 0 |

So the arms stay: cutting one AWS does issue costs a missed credential, and the
three unsourced arms — `A3T`, `ABIA` and `ACCA` — add no match at all to a 5
GiB population, dropped or surviving. Read that as being about those three and
not about `ASIA`, which is sourced and has 2 surviving.

**Do not read that table as evidence about which arms are real, which is what
this row is for and what an earlier draft of it got wrong.** `AKIA` is the arm
nobody disputes and it survives nothing here either, so a zero says nothing
about whether a prefix is issued. Nor does the raw count: a module cache is
published source, so it holds placeholders and fixtures rather than issued
credentials, and it reports which prefixes people write down. A prefix AWS
issues that nobody puts in a test file would read exactly like a dead one.

**It needs a reading this build graph cannot take.** `no-network` forbids
`net`, `net/http` and `os/exec` across the module, and nothing in the gate
fetches a page, so the answer comes from a person opening [AWS's IAM
identifiers reference][iam-ids] — the page
[`testdata/corpus/README.md`](../../testdata/corpus/README.md) already cites
for a different question — and writing down which prefixes its unique-ID table
names.

What to do with the answer: a prefix the table names gets a sentence in
[`rules/README.md`](../../rules/README.md) saying so, and one it does not gets
cut — dropping its row from `arms` in
[`awsprefix_test.go`](../../internal/scan/awsprefix_test.go), its vector, and
its arm from the pattern in the same edit, since
`TestTheArmTableIsTheShippedAlternation` holds those two as a set and will
redden if only one moves. What gets deleted in `rules/README.md` is the
paragraph opening **All five prefixes stay** and the one closing that section;
the per-arm table between them survives, because it is about what the arms cost
rather than about why they are kept.

**Do not settle this from another scanner's ruleset.** This set was inherited,
and [`docs/design/brief.md`](../design/brief.md) names gitleaks as a ruleset to
borrow rules from — so a prefix list that agrees may be the same list arriving
twice rather than two sources agreeing. Nobody here has traced which upstream
this rule's five came from, and that is a second thing this row could record if
it turns out to be cheap. The authority is AWS's own documentation either way.

[iam-ids]: https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_identifiers.html
