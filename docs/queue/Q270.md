# A spent budget defers a call refused on its shape

A call that would be refused on its shape goes through unrefused when the 45-second budget runs out before the refusal is settled.
There are five such refusals: an `env` dump, a `Read` or `Bash` read of a guarded credential path, a guarded path behind a prompt's `@` token (`splicedRefusal`), an unfiltered recursive grep, and the `Grep` tool in `content` mode over a directory (`grepToolRefusal`).
None of them needs a buffer read to decide.

There are two arms, and both end on the deferring `!finished` branch (`internal/hook/hook.go:155`) with no error, so the `refusal` branch above it never fires.
When the budget is already spent, `within` returns an empty result without starting the scan (`internal/hook/deadline.go:122`).
When it expires while `targets()` is still running (glob expansion, operand stats, `@` resolution, the variable walk), `within` also returns empty, because `scanCall` publishes nothing until `targets()` and `rules.Load` have both returned.

Found by reading during the 2026-11-26 batch review, and confirmed by a second reading at review; not driven.
The budget clock starts before stdin is read, so the first arm needs a payload that takes about 45 seconds to arrive, and the second needs a `targets()` walk that long; no harness run has been seen to do either.
The reach is narrow, and the miss is silent.
[Q268](Q268.md) is the same shape from another cause: a gap that defers a call a shape refusal would have blocked.

The fix is to settle the shape refusals before the budget check rather than inside the scan, which closes both arms.
A test through `run` with `start` set a budget in the past, over an `env` dump and a `cat .env`, asserting a block, drives the first arm and is its failing case.
The second arm needs a way to end the budget inside `targets()`, and `runPaced`'s `pace` callback is the existing hook to check first; a test of the first arm alone would pass against a fix that leaves the second open.
