# A spent budget defers a call refused on its shape

A call that would be refused on its shape — an `env` dump, a read of a guarded credential path, a recursive grep with no filter — goes through unrefused when the 45-second budget is gone before scanning starts.
`within` answers a budget already spent with an empty result and no error (`internal/hook/deadline.go:122`), so the `refusal` branch after it never fires and the call reaches the `!finished` branch, which defers with a coverage record (`internal/hook/hook.go:125`).
The refusals are decided inside `scanCall`, which never runs on that path, and none of them needs a buffer read to decide.

Found by reading during the 2026-11-26 batch review and not driven.
The budget clock starts before stdin is read, so the case needs a payload that takes about 45 seconds to arrive, which no harness run has been seen to do; the reach is narrow and the miss is silent.
[Q268](Q268.md) is the same shape from another cause: a gap that defers a call a shape refusal would have blocked.

The next step is a test through `run` with `start` set a budget in the past, over an `env` dump and a `cat .env`, asserting a block.
That drives the miss and is the failing arm for the fix, which is to settle the shape refusals before the budget check rather than inside the scan.
