# Differentially fuzz the capture-length bound against real captures

`maxCaptureBytes` in `internal/rules/capture.go` may over-estimate and must never
under-estimate: an over-estimate leaves a dead rule loaded, and an
under-estimate refuses a live rule at startup, which takes the scanner down over
a rule that works. The walk's own doc comment says so and the unit tests pin
about twenty patterns by hand, which is a sample rather than a property.

A differential harness turns that into one: for each pattern, compare the bound
against the longest group-1 capture `FindAllSubmatch` actually produces over a
corpus, and fail on `bound < observed`. The assertion is one-sided on purpose —
over-estimates are the design, so a two-sided check would fail on the intended
behaviour.

Run once during the review of the change that added the walk, over roughly
400 KB with about twenty adversarial patterns: zero under-estimates. That result
is why this is hardening rather than a defect, and it is not in the tree.

## What the corpus and the patterns have to hold

Build the corpus from random runes over a set that mixes plain ASCII with the
fold and width traps, with a **fixed seed** — a fuzz corpus reseeded per run is
a flake generator, and this is a gate. The set that earned its place:

    a z A Z 0 9 - space é ß ſ K İ ı Ω ω 𐍈 \n x

The patterns worth carrying are the ones where trouble was expected and not
found, since those are what a future edit to the walk would break first:

| Pattern | What it probes |
|---|---|
| `(?U)([a-z]{2,6})`, `(?i)([a-z]+?)` | non-greedy, where the longest match is not what the engine returns |
| `((?:a*){3})` | a repeat over a star |
| `([^a]{2})` | a negated class |
| `([\x{10000}-\x{10FFFF}]{1,2})` | astral ranges, four bytes a rune |
| `(\p{L}{1,4})`, `(\p{Greek}{2})` | Unicode classes |
| `(?i)(straße)`, `(?i)(SS)` | folding that changes encoded width |
| `([\x{0130}\x{0131}i]{1,3})` | the dotted/dotless I pair |
| `(?i)([\x{017F}\x{212A}s k]{1,2})` | long s and Kelvin, the two cases the fold walk exists for |

Folding is the half most likely to rot. `syntax.Parse` expands a class's folds
into its ranges but leaves `FoldCase` on a literal, so the two arms of `maxBytes`
reach the same answer by different routes, and only one of them walks
`unicode.SimpleFold`. A refactor that unifies them is exactly the edit this
catches.
