# Publish the rendered backlog index

**Demand:** somebody other than the maintainer needs to read the backlog
without a checkout.

`docs/queue/` has no front page by design — the index is rendered, never
committed, because a tracked index is the one file every completing session
would have to edit. That leaves a reader browsing the repository with a
directory listing sorted `Q1, Q10, Q11, Q2`.

Three ways out, in descending order of what they cost:

- The CI job summary — `render --format table --all >> "$GITHUB_STEP_SUMMARY"`
  — needs nothing and works today, but a reader has to know to look in Actions.
  [Q18](Q18.md) should do this much regardless.
- A GitHub Pages deploy. Available: this repo is public, so Pages needs no paid
  plan. It is also the option that commits the repo to having a site.
- Render on demand to a gitignored path and open it locally. Survives
  everything, costs a command.

Deferred rather than queued because the maintainer has a checkout and the CI
summary covers the rest. The trigger is a real second reader.
