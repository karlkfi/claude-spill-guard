# A budget overrun discards the findings it had already made

When a call's scan runs past the 45-second budget, the hook defers with no
findings at all, including findings from buffers it had already scanned. The
branch is `internal/hook/hook.go:120:return abstain(stdout, stderr, call, event, overran(budget), nil)`:
`within` hands back nothing unless the whole call finished. A prompt naming one
large file and one small file that holds a key therefore lets the key into the
model's context, with only a coverage record to show for it. That breaks the
rule `CLAUDE.md` states under *Block on a finding; defer on a gap*: "A gap does
not hide a finding beside it".

**Driven 2026-11-01 on a build of `main` at `162fcf9`, shipped budget.** The run
used `claude -p` 2.1.290 under a clean `HOME`, with the binary as the only
`UserPromptSubmit` hook at `timeout: 60`, at a load average of 115. The prompt
was `summarise @part0.txt … @part5.txt and @notes.txt`: six 400 MiB real-text
fixtures, plus `notes.txt`, a copy of
`testdata/corpus/planted/aws-access-key-id.env`. Results:

- Wall time was 49.702s and the prompt proceeded to `Not logged in`.
- The coverage log got one budget record.
- The transcript holds a `file` attachment for `notes.txt` whose content matches
  `AKIA[0-9A-Z]{16}`. The fixtures were not attached, because they are over the
  harness's splice limit.
- Control: the same binary on that file alone blocks, naming
  `aws-access-key-id`.

PR #220's reviewer found this first and drove it with the budget set to 1s.
Claude reproduced that run before taking the one above.

**Reaching the budget depends on load as well as on size.** On this machine the
budget was reached by 2.4 GiB of real text at load 96–130. A single 400 MiB file
reached it on all three runs at load 58–119. On a quiet machine the same text
runs at about 60–73 MiB/s of CPU, so it needs roughly 2.7–3.2 GiB, which is a
composed figure. The six-file shape is simply what reached the budget here.
Anything that pushes the scan past 45 seconds, combined with a small secret in
the same call, gives the same result.

## What is owed

A fix that keeps findings already made when the budget fires. Blocking on them
is a finding, and a finding blocks. Only the unread remainder should defer. The
scan runs on its own goroutine, and the verdict is written by the goroutine
waiting on it (`internal/hook/deadline.go`). So the shape is probably findings
published as each buffer finishes, rather than only at the end. That is a guess
and nothing has measured it.

**Every surface is in scope.** `Read` carries one buffer, so it reaches this
only through the order of the decode and the raw pass. `Bash` with several
operands, and `Grep` over a file, add up the same way a prompt does. Only the
prompt surface has been driven.

**The test this needs:** a call whose first buffer holds a key and whose second
exhausts a short budget. Assert that it blocks naming the rule. Then invert the
fix and watch the test go red.
