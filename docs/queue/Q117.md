# The removal verb lands in the body, and metrics reads the subject

A deleted row looks identical in the diff whether it shipped or was abandoned,
so the convention is that the deleting commit names the reason with a fixed
verb — `complete QN`, `prune QN`, `merge QN into QM`, `defer QN`. That is what
lets flow metrics separate throughput from garbage collection.

The convention is being followed. The reading is broken anyway:

```
$ python3 scripts/vendor/claude-skills/queue.py metrics
filed        115
completed    6
pruned       0
open         62
prune ratio  0%
```

`metrics` prints no count of the removals it could not classify, so the
number that carries the finding comes from the event stream instead — and
re-reading it is what dated this row's own figures:

```
$ queue.py metrics --events | awk -F'\t' 'NR>1 && $3!="" {r[$5]++} END {...}'
removed 47
complete 6
```

**The verb is on `main`. It is in the body, and the extractor reads the
subject.** `allow_merge_commit` is `false` here and
`squash_merge_commit_message` is `COMMIT_MESSAGES`, so a squash builds its
subject from the pull request title and its body from the branch's commit
messages, under `*` bullets. The `docs(queue):` commit carrying the verb is
one of those bullets. Measured on `7163d08`, the merge of Q105:

```
$ git log -1 --format='%B' 7163d08 | grep -i 'complete Q'
* docs(queue): complete Q105, and answer the question it left open
```

`queue.py` asks git for `%s` alone —
`scripts/vendor/claude-skills/queue.py:711:--pretty=format:C\t%H\t%ad\t%s` —
so every verb this repository has ever written is outside the field the check
reads.

**So `prune ratio 0%` is unreadable rather than reassuring**, and that is the
half worth fixing. A store that has pruned nothing and a store whose verbs the
extractor cannot see report the same number, and the groom's staleness step
treats that number as evidence about which items are being abandoned. 47 of 53
removals are unclassifiable as of 2026-09-03 — 89% of the store's whole
history, and 45 of 51 when this row was filed two days earlier. The ratio is
what holds steady: every removal since has been unclassifiable too.

The change is to match the verb anywhere in `%B` rather than in `%s`. It
belongs upstream in `claude-skills` rather than in the vendored copy, which
[Q70](Q70.md) already covers for a different missing subcommand; filing it
there is a separate act from this row, on the pattern [Q92](Q92.md) and
[Q100](Q100.md) set.

**Same boundary as [Q93](Q93.md), opposite side, and that row owns the
configuration measurement.** Q93 is about a pull request body that reaches
`main` by no strategy this repository allows. This is about text that does
reach `main` and is not read. Neither implies the other, and a reader who
knows only Q93 would reasonably conclude the verb was lost too.

Found while grooming after the five-item release batch of 2026-09-01, whose
own five deletions are among the 47.
