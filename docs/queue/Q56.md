# `scripts/*.py` is split between executable and not

Measured 2026-08-25 on `main` at `e01ebb9`, from `git ls-files -s scripts/*.py`:
eight files at `100755`, five at `100644`.

```
100755  check-doc-links.py   check-githooks.py   check-go.py
100755  check-queue-index.py check-supply-chain.py check-vendor.py
100755  cross-compile.py     gates.py
100644  check-action-pins.py check-launcher.py   check-status.py
100644  check-vulns.py       workflow_model.py
```

Every one of the thirteen carries `#!/usr/bin/env python3`, and every one the
Makefile invokes runs as `$(PYTHON) scripts/<name>.py`. So the mode is
decorative: nothing executes any of them directly, and the shebang is the only
thing suggesting otherwise.

## Why this is worth a row rather than a `chmod`

The split is not random and it is not a convention either. It tracks *when*
each file was written — the recent gate scripts are `644`, the older ones `755`
— so a contributor reading the tree for the rule finds two answers and no way
to tell which is current. That is the shape of a convention nobody can state,
and the cheapest moment to settle it is before there are twenty files rather
than thirteen.

Settling it is one decision, not a preference:

- **Drop the modes to `644` and keep the shebangs.** Consistent with how they
  are actually invoked, and the shebang stays useful to anyone running one by
  hand with `python3 scripts/x.py` — which does not need it either.
- **Raise them all to `755`.** Makes the shebang mean what it says and lets a
  script be run directly. Costs a `git update-index --chmod=+x` per file and an
  ongoing rule that new scripts get the bit.
- **Drop the shebangs from the `644` ones** so the file does not advertise a
  way of running it that the mode refuses.

## What it is not

Not Q8's packaging rule — Q8 shipped in #24 and its row is gone, so this names
it rather than linking it. That rule is about `hooks/run-spill-guard.cmd` and is
load-bearing: that file *is* invoked directly, by Claude Code, and a
launcher at mode `644` passes every other gate while the guard never fires. The
`launcher` gate asserts its index mode for that reason. Nothing here is
load-bearing, which is the whole difference and the reason this is `S` and near
the tail.

Whether the answer deserves a gate is part of the decision. `hooks-check` scopes
to `.githooks/` and `launcher` to the one launcher, so a third check over
`scripts/` would be a new gate for a property that currently affects nothing.
