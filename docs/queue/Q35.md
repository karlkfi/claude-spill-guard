# The errexit prologue gate has to allow bash 3.2, in one script

A constraint on [Q22](Q22.md) rather than a separate defect, filed as its own
row because this was measured somewhere else and Q22 was blocked at the time.
Q22 is ready now and names this row as one of the three constraining it, so the
two are visible from each other; fold this in when Q22 is worked.

Q22 requires `set -euo pipefail` **and** `shopt -s inherit_errexit` in every
executable script, gated rather than trusted to review. The second half is
bash 4.4+, and macOS still ships **bash 3.2.57** as `/bin/bash` — measured
2026-08-22 on darwin 25.5. An unguarded `shopt -s inherit_errexit` under that
shell prints `invalid shell option name` and exits 1 before the script does
anything.

For most scripts here that is harmless: they run under CI's bash or under a
developer's Homebrew bash 5, both of which have the option. `scripts/check-tools.sh`
is an exception, and it is one for a structural reason rather than an
incidental one. Its whole job is to run on a machine with nothing set up,
which is exactly the machine whose `#!/usr/bin/env bash` resolves to 3.2. The
prologue meant to protect it was, briefly, the thing that broke it.

**There are two such scripts, not one.** This row said "the exception" when it
was filed; [Q39](Q39.md) then found `.githooks/pre-commit` carrying the bare
form and dying the same way, which is worse because it blocks `git commit`
outright rather than one gate. Both are reached from a fresh clone by following
the setup instructions, so whatever this row settles has to cover `.githooks/`
as well as `scripts/`. Assume the census is still incomplete rather than that
it is now two.

So it carries `shopt -s inherit_errexit 2>/dev/null || true` and a comment
saying why. A gate that demands the bare form will fail that file, and
"just take the guard off" reintroduces the defect on every fresh Mac.

## What the gate should assert

Not `shopt -s inherit_errexit` as a literal. Either:

- allow the guarded form as well, and require the comment that justifies it; or
- require the bare form and exempt scripts on a named list, the way Q22 already
  exempts anything under `lib/`.

The second is stricter and says which files are special in one place. The first
scales without a list. Either beats a literal match, which is what a
hand-rolled grep will end up being.

**Settled in grooming, on [Q22](Q22.md)'s own precedent: require the bare form
and exempt a named list.** Q22 already carries exactly that shape — *"Scripts
under a `lib/` directory are exempt if any appear"* — so the repo has picked
the named-exemption pattern once and a second gate inventing a comment-parsing
convention beside it would be two mechanisms for one job. The list starts with
`scripts/check-tools.sh` and `.githooks/pre-commit`, and [Q39](Q39.md) is the
live instance of the second. Assume the census is incomplete rather than that
it is now two.

The shebang question is separable and stays open: whether the fresh-machine
scripts want `#!/usr/bin/env bash` at all, or a POSIX `sh` shebang that
sidesteps the version question and gives up `[[`, arrays and `local`. That is
work for whoever takes Q22, not a blocker on this.

Worth deciding at the same time whether the repo wants `#!/usr/bin/env bash` at
all for the fresh-machine scripts, or a POSIX `sh` shebang that sidesteps the
version question and gives up `[[`, arrays and `local`.
