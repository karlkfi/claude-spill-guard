# Track a literal `cd` target instead of refusing every relative operand

A segment naming `cd`, `pushd` or `popd` sets `movedCwd`
(`internal/hook/bash.go:108:if movesCwd[filepath.Base(tokens[0])] {`), and
every later relative operand is then refused
(`internal/hook/bash.go:297:if movedCwd {`). The comment above it says the port
does not carry the tracker the upstream guards key on, and that is the whole
reason: the refusal is a stand-in for a tracker, not a decision that the
destination is unknowable.

**Measured 2026-09-04** across this machine's transcripts: **79 of 393**
spill-guard denials land on this arm — 20.1%, the third largest. The shape is
ordinary repo reading:

```
cd plugins/workspace-guard && wc -l scripts/bash-workspace-guard.py … \
  && sed -n '855,905p' scripts/bash-workspace-guard.py
```

A literal relative target after a payload that names a working directory is a
path this process can compute exactly.

## Upstream returns the three answers this needs

`classify_cd` in `bash-workspace-guard.py` answers `('arg', path)` for a
resolvable literal target, `('subst', kind)` for the two whitelisted
substitutions (`$(git rev-parse --show-toplevel)`, `$(pwd)`), and
`('unknown', None)` for everything else — bare `cd`, `cd -`, `popd`, `pushd
+N`, a `~user` or `$`-bearing target. The third answer is today's behaviour, so
porting it keeps every case currently refused refused, and converts only the
ones with a literal.

Two cautions the port has to carry rather than drop. `popd` is `unknown` at
upstream because the stack is not tracked, and this repo already drove the
`pushd elsewhere && cat rel.env` case into a fail-open once — the comment at
`internal/hook/bash.go:99:resolved the operand against the` records it. And tracking has to be per-segment in
order, since `cd a && cat x && cd b && cat y` resolves the two operands against
different directories.

## What decides it

Smaller than [Q136](Q136.md) in count and in code — one classifier and a cwd
that advances through the segment loop — and it shares that row's test surface,
so the two are cheaper together than apart. Rank them adjacent for that reason
rather than merging them: the failure directions differ, and a single row would
hide which half a regression came from.
