# The install scripts ship as release assets with nothing signing them

`release.extra_files` in `.goreleaser.yaml` uploads `install.sh` and
`install.ps1` alongside the archives, because the documented install form
fetches `install.sh` from `releases/latest/download/` and the launcher's deny
message tells a user with no binary to do exactly that. Uploading is all it
does. GoReleaser adds an extra file at the publish stage, after the checksum
stage has run, so neither script is in `checksums.txt` and the cosign
signature over that file does not reach them.

So the two things a user can do with `install.sh` have different guarantees
and look identical. Downloading it to read is fine — reading is the check, and
it is why the documented form is two steps. Piping it into a shell, which
works and which the README deliberately does not lead with, verifies nothing
at all: the script that verifies everything else is itself the one artifact of
the release that arrives unverified.

**The fix is two edits, and the second one is the interesting half.**
`checksum.extra_files` would put both scripts in `checksums.txt`, which the
existing cosign signature already covers, so the signing side asks for
nothing new. But `scripts/check-release-artifacts.py` reports every name in
`checksums.txt` that the run did not archive as *a stale file signed as though
current* — which is a check whose whole purpose is catching exactly that
shape, so widening it needs an argument rather than an edit. The narrowest
version is to let it know which non-archive names a release is supposed to
carry, from the same `.goreleaser.yaml` that puts them there.

Filed alongside Q12, which added the scripts and the upload.
