# A directory operand blocks every recursive grep

`grep -rn pat docs/` and `rg pat docs/` name a directory, and `internal/readers`
returns it as a read operand because it is one. `bashTargets` then has nothing
to do with it: a directory is not a regular file, so the call is refused and the
command never runs.

This is not new and it is not Q86's. Before the fifo guard the same operand
reached `os.ReadFile`, which returned `is a directory`, and that error blocked
too — the verdict was identical and only the reason has changed. What Q86 did
was make the refusal deliberate where it had been a side effect.

## What it costs

Measured 2026-08-31 over this machine's session transcripts, driving the real
`bash.Segments` and `readers.Files` rather than a regex: of 129,180 `Bash` tool
calls, 70,480 yield at least one reader operand, and **5,036 of those — 7.1% —
carry an operand ending in `/`, or the bare `.` or `..`**. That is a floor
rather than a rate: `grep -rn pat docs` with no trailing separator is a
directory operand too and is not in the count, and nothing here resolves a path,
so a plain filename that happens to be a directory is missed as well.

For scale, the inherited ruleset this project was built to replace flagged 27.6%
of real files with zero true positives, and that number is the reason
**precision is the product**. A hard block on 7.1% of the calls that carry an
operand is the same failure arriving through the operand resolver instead of
through a regex.

It bit nobody while `hooks.json` did not ship. Q10 shipped it, so it bites
everybody now, and `grep -r` is not a shape a user will work around quietly.

## The decision, which is why this is M rather than S

Three answers, and none is free:

- **Walk the tree.** Honest — `grep -r dir` really does read every file under
  `dir`, and those contents really do cross — but it turns one hook call into an
  unbounded directory walk on the session's critical path, and the walk has no
  deadline any more than the fifo open had.
- **Scan the listing, the way `internal/hook/prompt.go` does for an `@`
  directory token.** Cheap and wrong here: a listing is what the *prompt*
  surface sends, and it is not what `grep -r` sends. Reporting clean after
  scanning names alone would be a fail-open over every file in the tree.
- **Refuse, and say so.** What happens now, and the half already taken: the
  PR that closed Q86 gives a directory its own reason naming the case and the
  remedy — *name the files instead* — rather than reporting the mode class.
  That was a maintainer decision, taken so Q10 could ship this batch
  with the block legible, and `TestADirectoryOperandSaysSoAndSaysWhatToDoInstead`
  pins the wording. It does not make the refusal correct; it makes it readable.

So the row is now only the first-versus-second question, and the third is the
status quo it is measured against. Deciding needs a measurement nobody has: how
long a walk of a real repository takes against the budget a `PreToolUse` hook
has, which [Q94](Q94.md) is the vehicle for taking on the live harness.

The reason deliberately does not name `SPILL_GUARD_OVERRIDE=`, and that is not
an oversight to correct here. `internal/hook/verdict.go` argues it: a deny's
reason is read by the model, so naming the hatch there hands it the bypass.
*Name the files instead* is the other kind of remedy — it says what to read,
not how to skip reading — and `TestADrivenRefusalDoesNotNameTheOverride` holds
the line.

Whichever wins, it also settles the same question for the `Read` surface, where
a directory `file_path` takes the identical branch.
