# StripComments lags upstream by three fixes, each a silent allow

`StripComments` starts a comment at a `#` that bash reads as text, so the
command after it is stripped before anything segments it, and the file that
command reads is never opened. Each of these reads `k.env`, a copy of
`testdata/corpus/planted/aws-access-key-id.env`, under bash 5.3.15, and each
exits 0 here with no verdict and nothing on stderr. Driven 2026-10-25 on the
Q202 branch, which ports Q257's double-quoted arm and none of these:

| Command | bash reads the file | Verdict here | Upstream fix |
|---|---|---|---|
| ``echo `true # c` ; cat k.env`` | yes | none | Q254, `e82fe12` |
| `echo ${x:- #} ; cat k.env` | yes | none | Q254, `e82fe12` |
| `echo $(true)#b ; cat k.env` | yes | none | Q264, `ea64a90` |
| `FOO[a #b]=x cat k.env` | yes | none | Q217, `a3c9052` |

The upstream column names the `claude-bouncer` row whose fix in
`lib/bouncer_parse.py`'s `strip_comments` covers the shape: a backtick span
and a `${…}` copied whole outside double quotes (Q254), the `)` closing a
substitution joining the word after it (Q264), and an assignment's subscript
copied whole (Q217). All three are on upstream `main` at `784fc36` and absent
here, so this is a port rather than a design question, and the package doc in
`internal/bash/bash.go` now names all three as unported.

The `$'…'` arm of the same function is Q211's, because it travels with
`requote`'s decode, and it defers rather than allowing.

Q63 is the harness that would have caught this drift as it happened.
