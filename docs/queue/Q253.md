# A subshell opening a substitution is read as arithmetic

`Segments` reads `$(` followed by a second `(` as arithmetic, which is one word
whatever it holds. A substitution whose body opens with a subshell has the same
tokens and can become several words, so the record an unquoted substitution owes
at a pattern or a flag's value is not written. Driven 2026-11-05 on bash 5.3.15,
with `key.txt` holding a key:

| Command | Hook | bash prints the key |
|---|---|---|
| `grep $(echo deploy key.txt) plain.txt` | no verdict, one record | yes |
| `grep $( (echo deploy key.txt) ) plain.txt` | no verdict, no record | yes |
| `grep $((echo deploy key.txt) ) plain.txt` | no verdict, no record | yes |

The third is the spelling where bash tries arithmetic, finds no `))`, and falls
back to a command substitution. The test is `tokens[i+1] == "("` in
`internal/bash/bash.go`, and shlex has already dropped whether the two parens
touch, so telling the first form from `$((` needs the lexer. The third needs the
closing parens read as well.

A literal operand beside one is still read, so what is lost is the record and not
a verdict. `\$\(\s+\(` matches 62 of the 35,011 real commands holding a
substitution on this machine, and `\$\(\([^()]*\)\s+\)` matches none. Both are
rough regexes with no positive control beyond the rows above, and neither says
which of the 62 sit where the record would fire.

**Done** is both spellings writing the record, with `head -n $((1+1)) plain.txt`
still silent.
