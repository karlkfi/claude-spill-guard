# A queued body's variables and glob options come from the string's end

Q147, merged and deleted from this store, gave a queued body its
**directory** by position: each
substitution is marked in the string, the tracker walks the marked tokens, and
the marker records the directory in force where it sits. Two other pieces of
state the same walk carries are still taken from the wrong point in the string,
and each is the same defect with a different subject.

**The variable map is empty.** `substDirs` builds a fresh `newVars()` for its
own walk and the queue hands each body a pass that does the same, so `SP=/x;
echo $(cat $SP/f)` records where `SP=/x; cat $SP/f` resolves. Not seeding it
was a decision rather than an oversight: upstream seeds its recursion with
`stable_vars`, the names holding one literal at every point in the string, and
a stale value there only ever adds a prompt where here it picks which file gets
opened.

**The glob options come from the end of the string.** `bashTargets` passes the
`globsAltered` its whole segment loop settled on, not the value in force at the
marker, so `echo $(cat *.env); shopt -s dotglob` records a pattern the shell
expanded under the default options.

## What closes it

The position that closed Q147, consumed the way upstream consumes it:
**positionally, not whole**. `substitution_bodies` in `bash-workspace-guard.py`
folds `stable_vars` in through a `usable` set as its walk passes each
assignment, and says why the whole map is wrong for a `cd` target -- resolving
one *removes* prompts, so an assignment written after the substitution must not
reach it. The same argument holds here for an operand, where it decides which
file is opened rather than whether one is asked about.

`substDirs` already runs a `vars`/`andOr` pair over the marked string's segments for the
`cd` targets, so what it records at each marker widens from a `substDir` to the
walk's state at that point. Both halves land in one place.

## What is not known

The population. Q147 measured 11 coverage records for the directory half over a
week of this machine's transcripts and nothing here has counted either of
these, so the sweep is the first step rather than a formality -- a `$(…)`
carrying a `$NAME` the same string assigns, and a `$(…)` written before a
`shopt`/`set -f`/`GLOBIGNORE` in the same string. Both directions are
conservative today, so what a fix buys is coverage and never precision.
