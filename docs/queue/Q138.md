# Resolve an in-root literal glob operand instead of refusing it

`grep -ln pat docs/queue/*.md` blocks. `resolve` refuses any operand containing
`*?[` before it reaches the filesystem, with *a file operand is a glob, so which
files this command would read is not settled here* —
[`internal/hook/bash.go`](../../internal/hook/bash.go), the `ContainsAny` arm.

A glob is how anyone greps a directory of one file type, so this is the shape a
session reaches for immediately after the directory refusal ([Q95](../design/README.md),
settled) has told it to name files instead. Both refusals landing on the same
task is what makes it worth a row: the remedy for one is the other's refusal.

## Why this is not the directory case

Q95 refuses a directory because **a walk reads a different file set from the one
the command would send** — ripgrep honours `.gitignore`, `grep -r` does not, and
matching each reader's traversal means re-implementing it. None of that applies
here. A literal glob is expanded by the shell before any reader sees it, so the
file set is the shell's and not the reader's, and `filepath.Glob` computes it
without running anything. The refusal is a resolution gap rather than a
traversal one.

## What has to be settled before it can be written

The expansion has to agree with what bash would do, and it is the disagreements
that decide whether this is worth having:

- **`nullglob` is off by default**, so a glob matching nothing is passed to the
  reader literally. `filepath.Glob` returns an empty slice, which reads as *no
  operands* — an allow where bash hands `grep` a filename with a `*` in it.
- **`dotglob` is off by default**, so `*` skips dotfiles; `filepath.Glob`
  matches them the same way, but this needs driving rather than assuming.
- **`globstar` is off by default**, so `**` is not recursive. If it were on, an
  expansion here would land back in the walk problem Q95 refuses.
- **Ordering and `LC_COLLATE`** do not matter, since every match is scanned.
- **Cost is unbounded**: `*` in a large directory expands to every entry, and
  each match is a file this then reads. The scan budget
  ([`internal/hook/deadline.go`](../../internal/hook/deadline.go)) already
  covers the overrun, so this is a note rather than a blocker.

The fail-closed direction is available throughout: where the expansion cannot be
made to agree, keep refusing. What must not happen is an expansion that reads
*fewer* files than the command would, which is the silent under-report this
project is built around refusing.

Scope to a literal in-root glob — no `$`, no backtick, no `~user`, nothing
above the payload's `cwd` — which is the same boundary `workspace-guard`
resolves literal in-root paths at.

## What not to do

Do not close it by recommending `git grep` in the reason. `git grep` has no row
in [`internal/readers`](../../internal/readers/), so it is allowed silently —
driven 2026-09-04, `git grep -n pat sub` exits 0 with both streams empty while
`grep -rn pat sub` denies. A refusal that routes the model to an unscanned
reader is this hook recommending its own bypass.

## Where it came from

A friction report on 0.2.0, from a session in `~/workspace/claude-bouncer` on
2026-09-04 that hit the directory refusal, retried as a glob, hit this, and fell
back to `git grep` — which is the bypass, reached by following the hook's own
advice.
