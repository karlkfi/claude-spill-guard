# Under bash, `builtin shopt -s dotglob; cat *` changes globbing unseen

`altersGlobbing` reads a segment's command name after the reserved-word and
env-prefix peels, and neither peel takes `builtin` or `command`. So `builtin
shopt -s dotglob; cat *` reads its name as `builtin`, counts nothing, and
expands `*` without dotfiles while bash puts `.secret` in it.

Driven 2026-09-26 with `SHELL=/opt/homebrew/bin/bash`, over a flat directory
holding a key in `.secret` beside `a.txt` and `b.txt`: bash 5.3.15 prints the
key for that command, and a binary built from `21297e4` (Q194's first head)
writes no verdict and nothing to stderr. The review of #181 found it, and
reports `main` at `af5b29a` answering the same. It is not Q194's regression,
because Q194 changed only what zsh reads.

The same drive shows `f() { shopt -s dotglob; }; f; cat *` **deferring** under
bash, 341 bytes of coverage record, so the function-body half the review also
named is covered on this head by something else. Which check covers it is not
established -- read that before assuming this row needs a function-body arm.

Q194 closed the zsh half by reading option changes as whole tokens anywhere in
the string (`ChangesZshOptions` in `internal/bash/zsh.go`), rather than at a
segment's head. The bash half could take the same shape, over `shopt`, `set`
with an `f` flag, and a `GLOBIGNORE` assignment. Whether that costs precision
on bash machines is unmeasured, since `shopt` and `set` are common in real
commands and this tree's own worktrees run bash. Take that measurement over the
transcripts before choosing between it and peeling `builtin` and `command`.
