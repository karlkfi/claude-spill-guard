# Nothing re-checks a published release body against its notes file

[`docs/releases/README.md`](../releases/README.md) states the invariant in one
line: "The invariant is that this file matches the published body — so an edit
to the notes lands as a PR and is then republished, never typed into the
Release."

One thing checks it, and it runs only on a tag. `release.yml`'s *The published
body is the notes file, byte for byte* step compares the two after GoReleaser
publishes the draft, which [Q59](Q59.md) counts among the assertions no pull
request can reach. After that tag, nothing reads the pair again. A notes file
edited and merged sits diverged from the published body for as long as nobody
runs `gh release edit`, and no gate, no job and no lint has an opinion.

That is not hypothetical. The pull request correcting v0.1.0's coverage claim
merged a notes file that does not match what a reader sees on the Releases
page, and the only thing standing between that and a permanent divergence is
the maintainer remembering the republish. Measured before that edit: `gh
release view v0.1.0 --json body --jq .body` returned 12,100 characters against
the file's 12,098, identical after stripping trailing whitespace. So the pair
was exact, and the drift starts at the merge.

**It is the `release-claims` shape, and that gate is the precedent rather than
the home.** The answer lives off this machine, so a check needs the network,
which this repository already accepts for `release-claims` and `vulns` — both
of which report an unreadable state as the check failing rather than as an
answer about the tree. What it cannot be is a comparison against
`gh release list` alone: the question is per tag and about the body, not about
whether a release exists.

The shape is a walk over every published release, `gh release view <tag> --json
body` against `docs/releases/<tag>.md`, failing on any pair that differs and
refusing to answer when the read fails. A tag with no notes file in the tree is
the same defect from the other side and the walk sees it for free.

## What to settle before writing it

- **Where it runs.** A gate on every pull request makes the correcting PR
  itself red, which is the wrong signal: the divergence is correct until the
  maintainer republishes, and a PR cannot republish. A scheduled job, or the
  `MERGED=true` tier the `queue` gate already uses for classes a branch cannot
  satisfy, both fit. This is the decision the row turns on.
- **The digest amendment.** `docs/releases/README.md` says digests land as an
  amendment after the publish goes green, so the tagged copy of a notes file
  stays one section behind the published body by design. The invariant is
  stated against the published body rather than the tag, so a walk over the
  working tree is right and a walk over the tag's tree is not.
- **Prereleases.** `v0.1.0-rc.1.md` is in the tree and its draft was deleted,
  so a tag with notes and no release is a legitimate state the walk must not
  fail on.
