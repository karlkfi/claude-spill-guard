# A mutation control that stops biting blames the gate

**The instance is fixed and the class is inventoried.** The Windows LF control
**rebuilt** the failing arm from whichever launcher was in the tree instead of
transplanting it, so it landed on the measured artifact only while the launcher
was `main`'s:

| launcher the step patched | result |
|---|---|
| `origin/main` | 7,214 bytes, sha256 `d28a64b3…` — the measured arm exactly |
| the Q10 branch, four deny strings shortened | 7,824 bytes, 610 off |
| the same, block padded to forty lines | 8,304 bytes, further off |

It now drives `testdata/launcher/lf-uniform-failing.cmd`, hash-asserted before
it is used, so it depends on the launcher's bytes not at all.

**The rule, which nothing enforces:** a mutation is only valid against the
artifact it was measured on, and a precondition asserting the mutation
*happened* is not one asserting it had its *effect*. A control that stops
biting then reports the **gate** as broken rather than itself, which sends the
reader to audit a gate that is working.

## What the audit found

Inventoried 2026-09-01 over `.github/workflows/tests.yml`: 16
`*-mutation-control` jobs, 55 named steps. The three the audit ranked highest
are hardened; each new precondition was driven in both directions by extracting
the step's `run:` block from the YAML and running it under `bash -e` — verbatim
except that BSD `sed -i` needs the suffix argument GNU `sed -i` does not.

| Control | How the mutation could stop biting | What it now asserts |
|---|---|---|
| `doctor` / *no module cache and no proxy* | green-demanding, and the only such step in the file with no positive control: doctor not reaching `tools/` and the environment never having made `tools/` unreachable both exit 0 | `go -C tools list -deps ./...` must fail in that same environment before doctor is run |
| `test` / *exit zero on a bad command* | `return 2` is written twice in `main.go`, and the guard was a repo-wide `git diff --quiet` — a refactor of either arm leaves the sed landing on the other one | the built binary must exit 0 on an unknown command |
| `vulns` / *a dependency with a called advisory* | the oracle is a database off this machine, so the advisory can reclassify with nothing in the tree changing | govulncheck must name `GO-2021-0113` before `make vulns` is asked about it |

The `test` one is the sharper measurement, because its drift is silent rather
than loud. Refactoring the unknown-command arm to a named constant and running
the pre-change step: `make test` exits 2, the log carries `failed: go test`,
and the control **passes** — having quietly moved onto the no-args arm while
keeping its name. The other two fail loudly and blame the gate.

## What was left, and why

- **A pre-mutation green baseline per control.** Already bought, and not
  worth buying twice: every `*-mutation-control` job has a sibling job running
  the same gate unmutated on the same commit, so the baseline is measured.
  `check-mutation-control` is the one exception — no job runs `make check`
  unmutated — and there the gates it loops over are each covered by their own
  job.
- **A lint requiring a pre-gate precondition in every control step.** Costed
  and rejected. Counted mechanically, 22 of the 55 steps abort on nothing
  before their first gate invocation — and the count overstates, because
  several of those hold a positive control *after* it instead, which no
  position-based rule can see. Most of the rest are mutations that cannot
  silently no-op: an append, a `git mv`, a `printf` to a new file, each of
  which aborts the step under `bash -e` if it fails. So the lint is mostly
  false positives, which is the shape that gets overridden and then means
  nothing. The property that matters — whether an absorbing layer sits between
  the edit and the symptom — is not mechanically detectable.
- **Checked-in hashed artifacts beyond the launcher.** One earns its cost only
  where the mutation is sensitive to something other than its own edit. That
  was true of the launcher and is not obviously true of anything else here, and
  a fixture nobody checks drifts — `CLAUDE.md` carries that measurement.
- **Five remaining unscoped `git diff --quiet` guards** — in gate-drift's *a
  gate job that does not invoke its make target* and *a stale generated
  table*, hooks-check's *a hook with no shebang*, action-pins' *a ref pinned
  to a tag*, and vulns' *a database it cannot read*. Each passes on any dirt
  in the tree rather than on the file its own `sed` targeted. Vacuous today,
  because every step restores what it mutated; real the first time one
  forgets. Mechanical to scope, and off the class the rest of this row is
  about.
- **The 52 steps left alone.** Every one was read and classified by whether an
  absorbing layer sits between its edit and its asserted symptom. None was
  re-driven, so the classification is a reading of the file rather than a
  measurement of the runner.
