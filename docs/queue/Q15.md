# Capture the payload a `!` bash-mode turn produces, if it produces one

Blocked on an interactive terminal. The measurement needs a pty, and the
attempt was refused by the auto-mode classifier on 2026-09-04 — the third
refusal on record for this row, after the two it was already carrying. Nothing
in this repo can lift that; a human at a keyboard can take it in about a minute,
and the recipe is below.

## What is already answered, so nobody re-takes it

**`!` bash mode is not a tool call**, so `PreToolUse` never sees it. Measured
2026-09-04 over 1,661 session transcripts, 2026-07-26 to 2026-09-04: 62 entries
whose content opens with `<bash-input>`, of which **0** carry a `toolUseID` or
`toolUseResult` and **0** are preceded by an assistant `tool_use`, against a
positive control of 143,678 model-issued `Bash` tool calls found by the same
walk. 58 of the 62 carry their own `<bash-stdout>`, so the command had run
before anything was recorded — and that output sits in the entry's own
`message.content`, which is what puts it in the model's context. `isMeta`
corroborates rather than carries that: all 62 are false where the same corpus
has 3,022 typed entries that are true, which shows the field varies and not
what it means. The design says so under
[`!` bash mode is not a tool call](../design/README.md#-bash-mode-is-not-a-tool-call-so-pretooluse-never-sees-it)
and discloses it in *What it is not*.

**The `toolu_` prefix is not the observable**, and this row used to say it was.
Over every `tool_use` in that corpus, 185,221 ids begin `toolu_` and 6 begin
`call_` — and those six are ordinary model work, so the prefix names the code
path that issued a call rather than who composed it. A probe reading its absence
as *not composed by the model* misreads all six. Whatever this row measures, it
may not rest on the prefix.

## What is left, and why the transcripts cannot close it

Two questions, and only the second decides anything:

1. **Does `UserPromptSubmit` fire for a bash-mode turn?** The transcripts say
   both. The chronos hook on this machine has fired on every `UserPromptSubmit`
   since 2026-08-19T04:11Z and Claude Code records each firing as an attachment,
   so a transcript answers this per turn — and over the 22 bash-mode turns in
   that window it fired for 7 and not for 11, with per-session controls
   disagreeing: one session runs an ordinary-prompt control of 2 of 2 with 0 of
   2 bash-mode turns firing, two run 1 of 1 with the bash-mode turn firing. The
   obvious mechanism, that the output rides on the next submission, is refuted
   by the same data — 18 of the 22 are followed directly by an assistant turn,
   and the split there is 7 to 11.
2. **If it fires, does the payload's `prompt` field carry the
   `<bash-stdout>`?** This is the one that matters, because the output is the
   only thing a rule could match, and no transcript records a payload. A firing
   whose `prompt` holds only what the human typed leaves the file's contents
   crossing unscanned exactly as they do today.

## How to take it

A throwaway project, hooks on `UserPromptSubmit`, `PreToolUse` and `PostToolUse`
appending raw stdin to a log, then an interactive `claude` in that directory.
Type `!cat marker.txt`, then an ordinary prompt as the positive control, then
read the log: the control's payload must be there, or the bash-mode silence is a
broken harness rather than a finding. Read the `prompt` field, not just the
event.

The 2026-08-27 drive under
[`@path` is an operand](../design/README.md#path-is-an-operand-not-a-hop) is the
same shape and is the thing to copy.

## What the answer changes

If the payload carries the output, spill-guard already covers this and the
design's disclosure should say so. If it does not — or if no hook fires —
`!` bash mode is a route into the model's context that this tool cannot reach
at all, which is a *What it is not* entry rather than a gap to close: the bytes
have crossed by the time anything is recorded, and unlike `@path` there is no
operand left to resolve.

Either way it does not change what the hook entry scans today. The `Bash`
command string stays scanned: the design's exception for it now rests on nothing
having enumerated the routes rather than on the `toolu_` reading, which this
row's measurement retired.
