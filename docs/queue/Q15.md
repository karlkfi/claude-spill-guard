# Measure whether a hook input can carry bytes the model did not compose

The question this row opened with — what counts as human-typed when choosing
what to scan — is settled in
[`docs/design/README.md`](../design/README.md#what-gets-scanned-is-the-crossing-not-the-hop).
The answer is that authorship was the wrong axis. What decides whether a payload
field is worth scanning is whether its bytes have crossed the
filesystem-to-context boundary yet, and for everything the model composed they
have: the model emits the `tool_use` block, so a `Write` body, an `Edit`
replacement and a heredoc are all API output before the `PreToolUse` hook is
called. Denying that call stops a file being written and unsends nothing. The
middle case the row was filed over — a `Write` body assembled from a file the
model read — is therefore not a crossing at all; it is a re-emission of bytes
that crossed at the `Read`, which is the hop where the deny does work.

That leaves a scan set of two things, neither of which needs any state: the
prompt, and any file the hook opens for itself off a `Read` path or a resolved
`Bash` read operand. The design's other half of the answer — dedup on the
content hash — is refused there for three reasons, of which the sharpest is that
a 64-bit digest of a US SSN is the SSN.

## What is left, and why it is not Q50's

The rule rests on a premise the measurement could not close: **that every tool
call a hook sees was composed by the model.** Every `PreToolUse` in the drive
carried a `tool_use_id` beginning `toolu_`, so every one of them was, and no
probe has yet put a command into a session by any other route.

One route is known to exist in the product and was not measured: **`!` bash
mode**, where the human types a command directly. If that reaches
`PreToolUse:Bash`, the command string is a crossing and the design's decision to
scan it is a control rather than a hedge. If it reaches no hook at all,
spill-guard has no surface there and the gap belongs in *What it is not*.

It needs an interactive terminal, so it needs a pty harness, and that is this
row. Two attempts failed differently and neither is evidence about the answer:
one was refused by the auto-mode classifier as terminal automation, and one hit
first-run onboarding before reaching a prompt.

The other route this row used to carry, `@path` expansion, **is measured** and
is not a residue any more. It reaches no hook at all, the prompt carries the
token unexpanded, and denying at `UserPromptSubmit` suppresses the splice — so
it is an operand to resolve rather than a hole, and the design says so under
[`@path` is an operand, not a hop](../design/README.md#path-is-an-operand-not-a-hop).
Resolving it is [Q77](Q77.md).

The design's conservative branch is already written and fails closed, so nothing
downstream is blocked on the answer: the `Bash` command string is scanned even
though a model-composed one has already crossed, on the grounds that its
authorship is the one thing the measurement did not settle. A result here either
retires that exception or widens the scan set. It does not change what the hook
entry scans today: Q50 shipped that, so the bare ID above is a mention of
history rather than a reference, and carries no link for the same reason.

## How to take it

Wire a hook logging raw stdin to `UserPromptSubmit`, `PreToolUse` and
`PostToolUse` in a throwaway project, the way the 2026-08-27 drive did, then
reach it from an interactive session rather than `-p`. The observable is whether
a payload arrives at all, and if one does, whether it carries a `toolu_` id.
Absence and presence are different findings and only one of them is a hole, so
run a known-positive command through the same harness first — a model-issued
`Bash` call — and confirm the log fires before reading a silence.
