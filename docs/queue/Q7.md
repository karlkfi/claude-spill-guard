# The v1 credential ruleset and the precision corpus gate

Blocked by [Q4](Q4.md). Needs the schema to express rules in. The validators
the rules name landed with Q6, unlinked here because completing an item deletes
its file.

**Ten precise rules, not seventy noisy ones.** The inherited ruleset's defect
was precision, not coverage, so v1 does not aim at gitleaks-level breadth.
Borrow from gitleaks — its `go.mod` carries no PCRE or `regexp2` dependency, so
it is RE2-clean by construction — and take the credential rules with strong
literal anchors first: AWS, GitHub, Slack, Stripe, OpenAI, Google API keys,
private key blocks, JWTs.

**The numeric PII family ships `enabled: false`.** All 5,679 inherited false
positives came from it. Shipping it off is not deferral; it is the finding.

## The corpus gate is the deliverable that matters

`testdata/corpus/` holds clean real-world files that must produce zero
findings, plus a small set of planted secrets that must produce exactly one
each. CI pins the false-positive count.

Recall regressions get reported by someone who missed a secret. Precision
regressions are invisible until the noise has trained everyone to ignore the
tool, which is how the predecessor reached 5,679 matches and zero true
positives. This gate is the only thing that sees them.

Source the clean half from real heterogeneous infrastructure files —
Kubernetes manifests with NodePorts, driver version strings, buffer constants.
The three worked examples in `docs/design/language-choice.md` §3 are the
regression cases to plant deliberately: `65536`, a NodePort like `30443`, and
the amdgpu DKMS string `1:6.16.13.30300400-2341068` that was flagged 268 times
as a Chinese phone number.

## Why this is L

Rule authoring and corpus curation are separable and both are iterative. Expect
to run the ruleset over a real repo, read every hit, and cut rules that cannot
be made quiet. A rule that needs an exception to stay quiet is a rule to drop.
