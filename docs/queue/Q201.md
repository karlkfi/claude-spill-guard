# A literal cd inside a subshell is not followed for the commands in it

`(cd w && cat a.txt)` defers with "the command changes directory first to
somewhere this cannot follow", where `cd w && cat a.txt` resolves and gets a
verdict. Driven 2026-10-01 on v0.5.0. `classifyCd` and `follow` deliberately
lose the directory on a move inside a subshell, because the move does not
outlive the subshell; that is right for the segments after it and wrong for
the segments inside it, which run in the moved directory.

Over the coverage log from 2026-09-07 to 2026-10-01, 192 of 2,400 records
(8.0%) are this reason. Of the 120 replay-confirmed, 87 carry a subshell `cd`,
typically `(cd tools && go mod graph | grep …)`. That count is a regex over the
whole command and can overcount where a string has a subshell `cd` and a
second, unrelated move.

Follow the target for the segments inside the subshell and restore the outer
directory at its close. Read `claude-workspace-guard`'s tracker first: this is
a port, kept structurally identical, so if upstream already scopes a subshell
move the fix is a port, and if it does not the row is an upstream change
before it is one here.
