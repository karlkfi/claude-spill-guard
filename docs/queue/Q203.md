# A recursive grep is scanned through a filter on its own output

A `grep -r` over a directory crosses with nothing scanned, and it is the
largest class in the coverage log by a wide margin. Of 2,400 records from
2026-09-07 to 2026-10-01, 1,364 (56.8%) are a directory operand and 1,361 of
those are `grep`. Of the 637 replay-confirmed calls whose segment parses, 636
are recursive and 305 carry `--include` or `--exclude`.

**This reopens a decision the design marks settled, on purpose.** The refusal
rests on a walk reading a different file set from the one the command sends,
and on re-implementing each reader's traversal to close that. Neither applies
to this shape, because it reads the *output*, which is exactly what crosses.
The cost accepted for it is a turn per call: decided 2026-10-01, against the
2026-09-05 measurement that made coverage failures defer.

## The shape

- A `spill-guard filter` subcommand reads stdin, runs the shipped ruleset over
  it, and writes it to stdout when clean.
- The hook denies a recursive `grep` over a directory operand unless
  `spill-guard filter` is its last pipeline stage, and the reason carries the
  rewritten command with `set -o pipefail;` ahead of it, so the model applies
  it and nobody is prompted. Position in the pipeline is the test, as for the
  `env` refusal.
- `-q`, `-l`, `-L` and `-c` are exempt. They print no matched text, and they
  are the forms whose exit status sessions test, which a pipe would replace
  with the filter's.

Scanning output is also the more precise reading. `grep -rn 'func foo' .` sends
only lines matching `func foo`, so a planted key elsewhere in this repo's
corpus does not block it, where a walk would block every recursive grep here.

## What is checked already

exit-status-guard does not fire on the filtered form. Driven 2026-10-01 on
2.1.0: `grep -rn 'func foo' . | spill-guard filter` and the `-c` form allow,
and `make check | spill-guard filter` denies, which is the positive control. Its
registry carries gates and `grep` is not one. A project-local
`.claude/exit-status-guard.json` adding `grep` would change that.

`PostToolUse` was not the alternative: it cannot withhold a result, which the
design measured. Running `grep` from the hook was not either, since `os/exec`
is forbidden across the build graph.

## Open

**Ask:** redact or block. Redacting a matched span changes output the model
asked for and keeps the search; blocking discards the whole search over one
line and tells the model why. What turns on you is what the model should see
when a search it needed hits a secret.

Also settled in the PR, not before it:

- The filter's block exit code, which has to differ from grep's 1 and 2 so
  `pipefail` reports it unambiguously.
- Whether it buffers the whole stream before writing, which a block needs, or
  streams line by line, which only redaction allows.
- `docs/design/README.md` and CLAUDE.md both state the directory refusal as
  settled, and change in the same PR.

Other recursive readers, `rg` first, fit the same filter without the file-set
argument that refused them. They are left out until the coverage log says they
are worth a turn each, which Q200's records would show.
