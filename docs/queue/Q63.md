# Nothing re-checks the segmentation port against its upstream

[`internal/bash`](../../internal/bash/) is a port, and `CLAUDE.md` states the
reason it is one: kept structurally identical, a fix in
`claude-workspace-guard` transfers by inspection. The port shipped with 114
subtests carrying the upstream suite's own cases across, and those defend the
Go against a future edit to the Go. They do not defend it against the thing the
rule is actually about — the two copies drifting apart.

## What was measured once and cannot be re-run

Agreement was established by a differential: 60,351 command strings through both
implementations, ten layers compared per case, 603,510 field comparisons, zero
mismatches, over three fuzz seeds. Ten mutation controls proved the harness
could report a mismatch, each asserted to have landed in the tree before the
comparison was read.

That harness lived in a session scratchpad and is gone. It cannot ship as it
stood, for two reasons that are the same reason: it drives the upstream Python,
which means `os/exec` and an interpreter, and the repository's build graph is
gated against `os/exec` by [`no-network`](../../scripts/check-supply-chain.py).
So the strongest evidence this package has is the evidence a reviewer cannot
reproduce and CI never re-takes.

## The shape that fits the constraint

Freeze the upstream's answers rather than the upstream. A generator, run by hand
against a named `claude-bouncer` revision, writes the corpus and the expected
output for every layer into `testdata/`; the Go test reads those and compares.
No interpreter at test time, no `os/exec` in the graph, and the goldens carry
the revision they were taken at, so a bump is a visible diff rather than a
silent divergence. Q52 was the sibling shape one package over, and it landed:
`internal/rules/differential_test.go` carries the fixed-seed and
empty-match-set arguments already worked out.

Two things the goldens have to record beyond the answers: the upstream revision
(tag, commit, and the `sha256` of each file the port was taken from), and the
seeds, since a corpus regenerated per run is a flake generator and this is a
gate.

## The control that could not fire, which belongs with the harness

One of the ten mutations reported green: removing the `<<<` here-string early
exit from `StripHeredocBodies` changed no output. It is a true equivalence
rather than a corpus gap — with the branch gone, the delimiter scan is entered
at the third `<`, and `<` is in that scan's own stop set, so it returns an empty
delimiter and arms nothing, which is exactly what the branch produces. Measured
against the upstream Python:

    >>> bp._scan_heredoc_delim("<<<EOF\nbody\nEOF\n", 2)
    ('', False, False, 2)

Both copies carry the branch and no input can discriminate it. Worth recording
because a mutation-control suite aimed there will report green and mean nothing,
which is the failure `CLAUDE.md` names — a precondition asserting the mutation
*happened* passes while the mutation does not *bite*.

## Why this is not just more unit tests

Hand-written cases are drawn from what someone thought of, and a segmenter's
failure modes are the ones nobody thought of: it fails silently in both
directions, so neither an over-split nor an under-split shows up in output. The
fuzz corpus that found nothing found nothing over inputs no one would write
down, which is the only reading that means anything here.
