# A subscript the lexer cannot keep whole is under-peeled

Four spellings of an array-subscript command prefix are read as command names
where bash reads them as prefixes, so the reader behind each one contributes no
operands and its file crosses unscanned.

```
FOO[$((1+1))]=x cat <key file>
FOO[a b]=x      cat <key file>
FOO["a]b"]=x    cat <key file>
FOO[a\]b]=x     cat <key file>
```

Driven 2026-09-19 on bash 5.3.15 as `env -i bash --norc --noprofile -c '<word>
cat f'`: every one of the four peels and prints the file. Q175 closed the
ordinary spellings and left these, and
`internal/bash/lex_test.go`'s
`TestASubscriptTheLexerCannotKeepWholeIsUnderPeeled` holds all four as rows
that fail when the gap closes.

## One mechanism, which is why it is one row

Bash scans for the subscript's closing `]` over the word **as written**.
`internal/bash` scans what the lexer left of it, and the lexer has already done
two things to the word:

- **Split it.** Whitespace and the shell punctuation in `punctChars` end a
  token, so `FOO[$((1+1))]=x` arrives as five tokens and `FOO[a b]=x` as two.
  Nothing downstream can reassemble them, because by then the brackets are in
  different tokens.
- **Removed its quotes.** `FOO["a]b"]=x` arrives as `FOO[a]b]=x` with a single
  `quotedFrom` offset saying where quoting began. `subscriptEnd` then closes
  the subscript at a `]` bash never saw as one, and `isAssignment` refuses the
  token on the offset. An offset cannot say *which* `]` was quoted, so no
  reading of the stripped token recovers it.

Both are the same defect at the same boundary: the assignment question is asked
after the lexer has destroyed what the answer depends on. Keeping `NAME[...]`
whole in the lexer -- brackets counted by depth, quotes still attached, as
bash's own `parse.y` does -- closes all four at once, which is the test for one
row rather than two.

## The direction, and why it does not block

Under-peeling, which is the fail-open side: the call is allowed with no verdict
and no coverage record, exactly as Q175's shape was. It is not a false positive
and does not cost precision.

What holds the rank down is reach rather than severity. Each spelling needs a
subscript carrying whitespace, shell punctuation, or a quoted or escaped `]` --
shapes nothing writes by accident, so the population is adversarial. Q175's
spelling was the one a session could type without meaning anything by it.

## What to establish before fixing

Whether the lexer can keep a subscript whole without diverging from upstream.
`internal/bash` is a port of `claude-workspace-guard`'s segmentation, kept
structurally identical so a fix there transfers by inspection, and upstream's
`ASSIGNMENT_RE` has no subscript arm at all -- read at `d2d54b8`, head of
`karlkfi/claude-bouncer` main on 2026-09-19, where all five plugins carry
`^[A-Za-z_][A-Za-z0-9_]*\+?=`. A chip was opened there for the Q175 half; check
what it landed before writing a lexer arm here, because a lexer divergence is
the expensive kind to carry.

The other question is what to do where the answer is genuinely unreachable. A
token whose quoting lands inside a subscript is one this cannot settle either
way, and the design has a third answer for that -- defer and record the
coverage failure -- which neither peeling nor refusing gives. It needs
`isAssignment` to return three states rather than two, threaded out to the
caller that writes the record, which is why it is not in Q175's fix.
