# A compiled-in ruleset that fails to load defers every call

`scanCall` in [`internal/hook/hook.go`](../../internal/hook/hook.go) returns `rules.Load`'s error as an ordinary error (`return nil, nil, fmt.Errorf("loading the compiled-in ruleset: %w", err)`), and `runPaced` sends any non-refusal error with no findings to `abstain`.
So a binary whose shipped ruleset does not load writes a coverage record on every call and lets every call through.
That includes an overridden shape refusal: only an override scans past a refusal, the wrapped load error is not a `refusal`, so where a working ruleset would give a confirmation this gives a deferral — the independent reviewer's reading on #283, also from the code.
Read from the code on 2026-11-26 while re-verbing Q145's comments; not driven, because the ruleset is embedded and no test swaps it.

Before 2026-09-05 the same path blocked, and `internal/selftest/selftest.go` argued from that: a broken ruleset "denies every call there is".
Q145 corrected that comment and left the behaviour alone.

## The question

Is a ruleset that will not load a coverage failure or a broken install?
`CLAUDE.md` keeps a payload that does not decode on exit 2 because it is "the signal that says a broken install is broken", and a ruleset that will not compile is the same kind of signal: no call this binary sees can be scanned, so deferring on it switches the scanner off and leaves one coverage line per call as the only trace.
Against that, the ruleset is compiled in and the `precision` and `test` gates load it on every PR, so a shipped binary reaching this branch needs a build that skipped both.
`selftest`'s blocking arms should report it, since each wants a block and would get a deferral, which is the check a user runs; that is read from the arms' wants and not driven either.

**Ask (answered):** which branch this belongs on was a posture call for the maintainer, since both readings are already argued in the tree.
Karl answered on 2026-11-27: it is a broken install, so the hook blocks on exit 2, as it does for a payload that does not decode.

## What to build

Make a ruleset that fails to load block every call on exit 2 rather than defer.
"Every call" is the part a fix inside `scanCall` misses.
The hot path loads the ruleset only there, and four kinds of call return before reaching it, read by the reviewer of #301 from the code and not driven: a call with no buffer to scan, a walk cut at the budget, a budget already spent, and an overridden refusal whose walk was cut.
The last of those confirms, which is the outcome this row rules out.
So load the ruleset in `runPaced`, straight after the payload decodes, and block there.
That reviewer proposed it; nobody has measured what the earlier load costs a call that scans nothing.

Pin it through `runPaced` rather than `scanCall`, which needs a seam for a ruleset that fails to load, since the shipped one is embedded; say in the change that the seam exists for this.
Assert all four early returns block, and that the override does not turn the block into a confirmation, since there is nothing scanned to confirm.
Then re-read `internal/selftest/selftest.go`, whose comment Q145 re-verbed to match the deferral, and `CLAUDE.md` under *Block on a finding; defer on a gap*, which lists what still blocks on exit 2.
