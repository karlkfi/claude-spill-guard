# Promote stale-citation on a pull request, not only on main

The store gate is strictly weaker on every pull request than on the trunk, and
no command the repo documents runs the stronger form. So a branch can go green,
merge, and redden `main` on the commit that lands it.

The mechanism is three lines. [`Makefile`](../../Makefile) sets
`QUEUE_STRICT_MERGED := --strict dangling-link --strict stale-citation` and
`MERGED ?= false`, and the `queue` job runs
`make queue MERGED=${{ github.event_name == 'push' }}`. On a `pull_request`
both classes are notes at exit 0; on a push to `main` both are failures.

**It has already fired once.** [Q43](Q43.md) quotes actionlint's compiler
errors, which are citation-shaped. Unmarked they were a note on the PR and
would have been a failure on the trunk. It was caught before the push because
that session ran `make queue MERGED=true` — a command named nowhere in
`CLAUDE.md`, run because a sibling item had put merged-set thinking in that
session's head. `make check` does not run it and neither does `make queue`.

## The decision, taken 2026-08-23

Promote `stale-citation` on `pull_request` as well. Leave `dangling-link`
split as it is.

The asymmetry is the point rather than a compromise. A citation is decidable
from the files in front of you — the fragment either sits near the line it
names or it does not — so a merge cannot legitimately break one, and failing a
PR on it costs nothing correct. A dangling link genuinely can be legitimate in
that window: a row filed during a parallel batch links an item a sibling PR is
still filing, and promoting that class would fail the check on exactly the
state it exists to inspect.

That leaves `MERGED` meaning one class rather than two, which is a reason to
re-read the variable's name and the comment above it in the same edit.

## What this is not

Not [Q30](Q30.md). That row picks the `--citation-window`, which decides what
counts as drift; this one decides what a note costs. Promotion cannot reach the
window — a fragment that moved nine lines emits no note under either setting,
so a clean run here is still the weaker statement Q30 describes. The two are
worth settling together and neither answers the other.

## The half worth fixing beside it

`make queue MERGED=true` is the only local command that sees what the trunk
sees, and `CLAUDE.md`'s "Running the gates" section does not name it. Whether
that section gains a line or `make check` runs the trunk strictness locally is
the open half: the second is the real fix and changes what every contributor's
gate does, and it would make a local run stricter than the PR gate, which needs
saying out loud wherever it lands.
