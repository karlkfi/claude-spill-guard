# The floor failing also prints fourteen drift lines

`scripts/check-prompt-oracle.py --compare` has two independent failures, and
when the first fires it emits the second fourteen times over.

The floor is correct and comes first:

```
prompt-oracle: the census no longer matches the harness
  - the replay saw 0 cases splice something and 0 files cross, where the
    census holds 14 and 33. A run that drove nothing agrees with every case
    that expects an empty splice, so a shortfall is a failure rather than a
    pass.
```

Then, for every non-empty case in the census:

```
  - positives: the census records ['nested/inner.txt', 'plain', 'secret.txt']
    and 2.1.261 spliced []. The `@` grammar moved under the census; re-take it
    and re-read what internal/hook resolves.
```

The grammar did not move. Nothing was observed for it to have moved *from*,
which the line above already said. A reader who starts at the top gets the
right answer and a reader who skims to the volume gets the wrong one, and the
wrong one is the expensive read: it points at `internal/hook` and at re-taking
the census, when the thing to look at is why the harness produced nothing.

## Where to see it, without running anything

**Every run of the job prints it**, in the mutation control's own output -- the
second mutant is a recording with every case emptied, which is exactly this
shape. So the evidence is in the log of the most recent
`.github/workflows/prompt-oracle.yml` run, and no reproduction is needed
before touching the code.

## The mechanism, which decides where the fix goes

`--record` ignores each case's exit status on purpose. A healthy
unauthenticated run exits 1 with `Not logged in` every time, so a non-zero exit
carries no signal and cannot separate a working harness from one producing
nothing. That is why the floor lives in `--compare` rather than in `--record`,
and it is why the fix does too: `--record` has nothing to detect this with.

## The fix

In `compare()`, when the floor fails, do not append the per-case lines. There
is no observation for them to disagree with, so they are not findings about the
grammar -- they are the absence of a replay, reported once already.

Leave the two failures independent in the other direction: a per-case
disagreement with the floor met is real drift and must still name every case.

## Why it was not fixed when it was found

Found while answering a review question on the pull request that added the job,
which was the last of eleven rows gating v0.4.0. A new head there meant a fresh
CI cycle and a fresh set of readings on a tree that was correct and complete,
to repair a second paragraph in a failure mode that has not occurred. The
maintainer's call was to file rather than to spend the cycle.
