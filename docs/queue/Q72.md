# The corpus adversarial table hand-keeps a number the gate already prints

`testdata/corpus/README.md` records what the two inherited rules match on the
clean half — `pii-postal-code` at **30**, `pii-phone-cn` at **8**, dated
2026-08-25. Measured 2026-08-27 over a `clean/` that `git diff
origin/main...HEAD` reports as unmodified, twice — once through the gate and
once through a standalone `re.findall` over the same eleven files —
`pii-postal-code` matches **31**. The floor in `internal/scan/corpus_test.go`
is 20, so nothing went red and nothing was going to.

`tls-runbook.md` is where the extra match came from. It landed after the table
was written, its prose went into the same README, and the table did not move.
Two other copies of the same figure went with it: the comment above `inherited`
in `corpus_test.go` still reads "2026-08-25 -- 30 and 8", and
[Q61](Q61.md) opens with "10 files and 8,731 bytes" against a corpus that is
now 11 files and 10,234 bytes.

## Why this is a gate rather than three edits

The gate already prints all four numbers on every run — `check-precision.py`
echoes the `t.Logf` lines on success as well as on failure, deliberately,
because "a gate whose numbers are visible only when it breaks is a gate nobody
watches move". So the README's table is a second, hand-kept copy of a
measurement the tree can take, which is the shape this repo has twice decided
against: `gates.py` derives the CLAUDE.md gate table from `GATES`, and
`check-status.py` derives the README's status block from the tree, both with a
`--check` mode that fails until they agree.

Correcting the three copies leaves the next clean file to desynchronise them
again. Either generate the table the way `make status` generates its block, or
drop the counted column and keep only the floor — the floor is what the test
enforces, and it is the part a reader needs.

Q61's numbers are its premise rather than a claim about the tree, so they are
worth correcting whenever that row is worked; they are not what this row is
for.

## What made it visible

Q47 added a planted UTF-16 fixture and touched nothing in `clean/`, so the
`precision` run over that branch reported `pii-postal-code reports 31
match(es)` beside a README saying 30. A count printed next to the document that
disagrees with it is the only reason anyone looked.
