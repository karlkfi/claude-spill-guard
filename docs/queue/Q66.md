# A mutation control aimed at a true equivalence reports green

`CLAUDE.md` states the rule as a precondition:

> A mutation control needs a precondition asserting the mutation had its
> effect, not that it happened. The two come apart.

Both cases it then gives are a mutation that fails to reach the checker's
input: `PATH=/usr/bin:/bin` hid nothing because `setup-go` links Go into
`/usr/bin`, and a Windows control asserted a block was present while the
launcher went on denying. The prescribed check follows from that reading —
compare against a case already measured, or build one.

There is a third case, and no precondition on the mutation can catch it,
because nothing is wrong with the mutation. The edit lands. `git diff --quiet`
confirms it. The code genuinely changes. The mutated site is a **behavioural
equivalence**, so the output does not move, and the control reports green while
testing nothing — reading exactly like a control that worked.

## The instance

Porting `internal/bash` (Q51), one of ten controls removed the `<<<`
here-string early exit from `StripHeredocBodies` and demanded the differential
go red. It stayed green. Not a corpus gap: with the branch gone, the delimiter
scan is entered at the third `<`, and `<` is in that scan's own stop set, so it
returns an empty delimiter and arms nothing — which is exactly what the branch
produces. Driven against the upstream Python rather than argued:

    >>> bp._scan_heredoc_delim("<<<EOF\nbody\nEOF\n", 2)
    ('', False, False, 2)

No input can discriminate the two spellings, in the port or in its upstream.
The control was replaced by two that do bite. It cost about ten minutes, and it
cost them only because the run reported nine RED beside one GREEN — a suite
where every control is aimed at an equivalence reports uniform green and reads
as a clean sheet.

## What this row is not about

**The workflow's own controls are unaffected, and that is worth stating so the
fix is not aimed at them.** Every mutation-control job in
[`tests.yml`](../../.github/workflows/tests.yml) asserts the gate goes red and
fails when it does not — `doctor-mutation-control` ends on `if [ "$rc" -eq 0 ];
then echo "::error::doctor passed with go missing…"; exit 1`. A control aimed
at an equivalence there fails the job loudly. The gap is in the stated rule,
which is what a reader applies to a control run by hand, and hand-run controls
are what [Q63](Q63.md)'s differential harness will be full of.

## The check that does catch it

Ask whether any input distinguishes the two spellings, before demanding red —
which is a question about the mutated site rather than about the mutation. The
cheap form is to drive the mutated and unmutated functions against each other
over the corpus and require the outputs to differ somewhere; where that is not
available, name the input that discriminates them and check it by hand. A
control whose author cannot name one is a control aimed at an equivalence.

`CLAUDE.md`'s mutation-control paragraph is where the sentence goes, beside the
two cases already there. Upstream `session-worker` §3 has the same gap, in the
same words, and the batch's retro is carrying that half.
