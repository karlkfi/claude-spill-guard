# Shell hygiene gates: shellcheck, errexit prologue, actionlint

Blocked by [Q8](Q8.md). The launcher is the first shell this repo ships.

Three gates over every executable script — the launcher, `install.sh`, and
anything under `scripts/` — plus actionlint over the workflows.

## The errexit prologue is the one that matters here

Require `set -euo pipefail` **and** `shopt -s inherit_errexit`, and gate it
rather than trusting review.

`set -e` does not reach inside a command substitution. `out="$(f)"` runs `f`
past its own failure and takes the status of `f`'s *last* command, so a script
that died on step one yields a truncated value and exits 0. Measured elsewhere
on a lint scope builder: with a fault injected it announced a full sweep, linted
1 of 11 modules, swallowed four 127s, and exited 0. With the `shopt` it exits
127 at the first failure.

That is precisely this project's worst failure shape wearing shell clothes. The
launcher's whole job is to deny when it cannot resolve a binary; a launcher
whose resolution step fails inside a command substitution and continues is one
that hands back empty stdout, which Claude Code reads as no objection.

Scripts under a `lib/` directory are exempt if any appear — they are sourced
rather than executed, so they run under the caller's shell options, and
declaring the option there switches it on for every caller.

## The other two

`shellcheck` over the same set. `install.ps1` needs PSScriptAnalyzer for the
equivalent coverage; decide whether that is worth a Windows runner or whether
the script stays small enough to review by eye.

`actionlint` over every workflow and composite action in the tree, not only the
ones GitHub runs — a workflow excluded from the lint scope is one that breaks
the day it is first invoked.
