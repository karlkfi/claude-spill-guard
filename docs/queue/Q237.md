# PowerShell file operands are recorded and never read

On a Windows machine with no Git Bash, shell commands go through the `PowerShell`
tool. `internal/hook/powershell.go` scans its command string and defers every
call, because `internal/bash` cannot segment PowerShell and `internal/readers`
has no table for it. Driven 2026-11-04 on Claude Code 2.1.290 on `windows-latest`,
`Get-Content planted.txt` returned the planted key to the model with no verdict
and one coverage record. `hook-harness.yml` pins that as the stated limit.

Three things are missing and share one fix, a way to find what a PowerShell
command reads:

- file operands of `Get-Content`, `gc`, `cat`, `type`, `Select-String`, `-Path`
  and `-LiteralPath`;
- the guarded-path refusal in `internal/hook/guarded.go`, so `Get-Content .env`
  is refused where `cat .env` is;
- the shape refusal in `internal/hook/shape.go`, so `Get-ChildItem env:` is
  refused where `env` is.

The override is missing too, for a different reason: `internal/hook/override.go`
reads `Bash` alone. Driven on a built binary, `SPILL_GUARD_OVERRIDE=why` ahead of a
key returns `ask` on `Bash` and `deny` on `PowerShell`, so a machine with no Git Bash
has no hatch on any surface. A reader table does not fix that, and it is small enough
to take on its own.

Nothing has measured how much of this traffic exists: no coverage log from such a
machine has been read, and every record says only that a call was deferred. Every
call writes one, of 402 and 473 bytes in two drives, so the log's two 4 MiB
generations hold about 18,000 to 21,000. At the 24,381 `Bash` calls a week this
repo's docs measured on one machine, that would rotate every other kind of record out
in five or six days. That duration is an estimate from another surface's traffic.

**Done** is `check-hook-harness.py`'s PowerShell reader arm moving to `must_block`.
