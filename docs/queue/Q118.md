# A binary-looking `@` target crosses whole and unscanned

The v0.1.0 notes list this under *What it does not read*, `CLAUDE.md` describes
the mechanism at length, and no row carries it. Five of the six disclosed gaps
have one — [Q95](Q95.md), [Q102](Q102.md), [Q108](Q108.md), [Q111](Q111.md),
[Q87](Q87.md). This is the sixth.

`@heap.dump`, a NUL in its first bytes, arrives as an attachment whose
`content.type` is `text` carrying **the whole file**, NUL included, with a
marker placed after that NUL intact. `internal/hook`'s resolver opens it and
hands it on; `internal/scan` returns `SkippedBinary` for any buffer with a NUL
in the first 8 KiB, and `internal/hook/hook.go:267:case scan.Scanned,
scan.SkippedBinary:` allows it. So a credential past that NUL is never read and
the call goes through.

Measured 2026-08-28 on a built binary, with the control beside it: the same key
without the NUL blocks and names the rule, and with it the hook exits 0. The
other arm is the one that bounds the damage — `@logo.png` arrives with
`content.type` `image` and no text at all, so nothing crosses that a rule could
match. Only the file the harness has already classified as text is exposed.

## Why it has no row, which is the part worth recording

Q84's population was two members and both were `Read`-shaped: UTF-16 with no
mark, and the UTF-8 mark ahead of a NUL. Its completion split what was left in
two — Q111 took the branch where a block carries no notice, Q102 took the
decode arm — and the prompt-splice member is in neither, because it is not a
decode question and not a verdict-encoding question. It fell between two
successors, and the notice Q84 shipped made the silence stop without making
anyone look again.

`CLAUDE.md` says as much and is worth quoting rather than paraphrasing:
`CLAUDE.md:204:It reports that nothing looked.`

## What decides it, and the trap in the obvious framing

The binary skip is a cost trade taken against a measurement: one PNG was 55% of
the benchmark corpus, and the regex pass runs at 1.0 MiB/s. That argument is
about bytes the scanner would otherwise have to open. It does not transfer
here, because on this surface the harness has already opened the file, already
decided it is text rather than an image, and already put it in front of the
model. The bytes cross whatever the scanner does; the only thing at stake is
whether anything reads them.

**The obvious fix is surface-dependent and this repository has ruled against
that once already** — *The verdict is per reason and not per surface* in
[`docs/design/README.md`](../design/README.md), measured and rejected. So a fix
that says *skip a NUL buffer on `Read`, scan it on a prompt splice* reopens a
settled decision and needs the argument rather than the instance.

**An argument, held rather than measured**, and it should be read as one: the
NUL sniff is a heuristic answering *is this text*, and on this surface the
harness has answered the same question with better evidence and sent its
answer in the payload. Deferring to a declaration where one exists is the axis
the decode stage already uses — a buffer that declared an encoding blocks,
one that declared nothing does not. If that reading holds, the change is
per-*reason* after all and the design decision stands. If it does not, the
honest outcome is a stated limitation rather than a fix.

## What nothing in the tree can see today

`internal/hook/testdata/prompt-oracle.json` pins the `@`-token grammar against
the harness across 24 cases, and every file `oracleTree` writes is short ASCII
text — no NUL, no image, no binary target anywhere in the fixture. So the
fixture cannot drift on this path because it never touches it, and neither does
any test in `internal/hook`. Whatever this row decides, a case belongs in that
tree.
