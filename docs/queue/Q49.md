# The entropy ceiling reads length but never the group's own alphabet

`entropyCeiling` in `internal/rules/capture.go` is `log2(min(maxlen, 256))`. The
256 is an alphabet term — the count of distinct byte values — and it is the
universal one rather than the set of bytes the captured group can actually
produce. Shannon's real ceiling is `log2(min(n, |A|))` for a group drawing on
`|A|` symbols, so every rule with a restricted character class is capped looser
than it should be, and a floor between the two ceilings loads on a rule that can
never reach it.

The direction is safe — a dead rule loads, a live one is never refused — which
is why this did not hold up the check that shipped in Q27. What it costs is the
rules the check was meant to catch. Measured 2026-08-24 against `Load`:

| Rule | Floor | Ceiling used | Real ceiling | Verdict |
|---|---|---|---|---|
| `([a-f0-9]{32})` | 4.5 | log2(32) = 5.0 | log2(16) = 4.0 | loads, dead |
| `([a-f0-9]{40})` | 4.5 | log2(40) = 5.32 | log2(16) = 4.0 | loads, dead |
| `([a-f0-9]{64})` | 4.5 | log2(64) = 6.0 | log2(16) = 4.0 | loads, dead |
| `(\d{16})` | 3.9 | log2(16) = 4.0 | log2(10) = 3.32 | loads, dead |
| `([A-Za-z0-9]{8,64})` | 5.98 | log2(64) = 6.0 | log2(62) = 5.95 | loads, dead |

The first row is the ordinary case rather than a constructed one. A 32- or
40-character hex API key is the second most common credential shape after
base64, and 4.5 is the base64 threshold that gets copied onto a hex rule by
exactly the author this check exists to catch. That rule is silently dead and
the loader says nothing.

## What the fix is

Compute the group's alphabet on the walk that already exists. `maxBytes` visits
every node; the same traversal can union the byte values each arm can emit —
`OpLiteral` contributes its runes' bytes, `OpCharClass` its ranges, `OpAnyChar`
everything. The ceiling then becomes `log2(min(maxlen, |alphabet|))` and the
existing comparison is unchanged.

Keep the over-estimate direction. Where an arm cannot be settled, widen to 256
rather than narrowing, for the reason `maxCaptureBytes` already documents: an
under-estimate refuses a live rule at startup, which is worse than missing a
dead one. `(?:ab){1,3}` stays loose either way — its two byte values are exact,
but the union over a repeat says nothing about which of them a given match
holds.

The design doc's account of the slack is in
[`docs/design/README.md`](../design/README.md#rule-schema), under the entropy
bound; it names this case and should lose that sentence when this lands.
