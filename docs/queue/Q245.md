# A key in a Grep pattern crosses when the path cannot be settled

A `Grep` call in `content` mode whose `path` will not resolve loses its pattern as well.
`grepToolTargets` collects the pattern and then returns `nil` beside the error, so a key
in the pattern reaches no match loop. That breaks *A gap does not hide a finding beside
it* in `CLAUDE.md`, on the one surface Q204 did not reach.

## Driven 2026-11-03

Built binaries at `a99ed37` and at Q244's head, identical on both, all with a key in
`pattern`. The reviewer of #236 found this; Claude reproduced it.

| `path`, `output_mode` | Result |
|---|---|
| a plain file, `content` | denied |
| a fifo, `files_with_matches` | denied |
| a fifo, `content` | exit 0, no verdict, one record |
| a relative path with no `cwd`, `content` | exit 0, no verdict, one record |

## What is owed

Return `targets` beside the error on the arms of `grepToolTargets` that return `nil` with
a plain error, which `scanCall` already scans and blocks on. A refusal keeps its `nil`.
That remedy has not been built. The test is a table over those arms that goes red when
the `nil` is put back. A record on those arms would then open with what was read, and
`failed()` has no arm naming a pattern, so it falls to `Part of this call`, which is true.
