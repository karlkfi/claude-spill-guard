# Go module skeleton and the four supply-chain CI gates

Nothing exists under `cmd/` or `internal/` yet. This lays the module out as
`docs/design/README.md` specifies and, in the same PR, makes the properties
the project advertises enforceable rather than aspirational.

The gates matter more than the skeleton. A zero-dependency, no-network claim
that no job checks decays the first time somebody adds a helpful import in
good faith, and review does not reliably catch it.

## The gates

- `no-deps` — `go.mod` carries no `require` block, and `go list -deps ./...`
  resolves to stdlib only.
- `no-network` — that dependency list contains no `net`, `net/http`, or
  `os/exec`.
- `cross-compile` — darwin/arm64, darwin/amd64, linux/amd64, linux/arm64 and
  windows/amd64 all build from one runner.
- `test` — `go test ./...`, `go vet`, `gofmt -l`.

Each needs a mutation control proving it can go red, following the pattern in
`.github/workflows/tests.yml` and the sibling repos: add a `require`, add a
`net/http` import, and confirm the matching job fails.

Pin every action by commit SHA. The audit named SHA-pinned actions as one of
the predecessor's strong properties.
