# The `validators` field has no names to carry

The **Rule schema** table in [`../design/README.md`](../design/README.md) says
`validators` holds "named checks from the table above". The table above is the
one in **Pipeline** step 4, and it has no names in it — its rows are
`Luhn`, `mod-11`, `Shannon entropy floor`, `Reserved-range exclusion` and
`Context label proximity`, which are English, not identifiers. A loader has to
reject a name it does not know, so it needs the set.

Two of the five carry configuration, and the design switches those two on in
opposite ways. That is the part worth deciding rather than transcribing:

- **The entropy floor is driven by a field.** The shipped example carries
  `"entropy": 3.0` beside `"validators": []`, so the check runs off the field
  and is never named. It is still a row in the validator table.
- **Context proximity is named.** `Q28` added a `labels` field and an example
  that names `context-label` in `validators`, on the fail-closed argument: a
  numeric rule whose author forgot `labels` is an ungated numeric regex, which
  is the 5,679-match failure mode, and naming the check is what turns that
  omission into a startup error. `Q27` depends on that shape — its first
  rejection is a rule naming the check with an empty label list, which is
  unrepresentable if a non-empty `labels` is what switches the check on.

Both take their configuration from a field of their own, and only one of them
is also named. Pick one rule for that, and write the names down. Whichever way
it goes, `entropy` and `labels` should agree.

Found while working `Q28`. `Q4` builds the loader and may settle this in
passing, in which case it completes this item; the row is here because a peer
reading the schema today cannot tell what a legal `validators` entry looks
like.
