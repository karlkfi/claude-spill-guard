# The install scripts are in `checksums.txt` now and no page says so

Q97 put `install.sh` and `install.ps1` in `checksums.txt`, which the cosign
signature already covers, so a user who fetches either can now check it against
the same file every other asset is checked against. Nothing tells them.

The pages that describe the fetch are all still correct, which is why this is an
addition rather than a repair. [`README.md`](../../README.md)'s install section
and [`distribution.md`](../design/distribution.md) both argue the two-step form
on the grounds that *a script you fetch in order to read is verified by reading
it* — true before Q97 and true after it. What changed is that reading is no
longer the only check available, and neither page offers the other one.

**The concrete gap is a command nobody can copy.** A reader following the
README has `install.sh` in a directory and no way to know that

```
curl -fsSLO .../checksums.txt && sha256sum --ignore-missing -c checksums.txt
```

now answers for it. `--ignore-missing` is the load-bearing flag and the reason
this is worth writing down rather than leaving to inference: without it
`sha256sum -c` fails on the five archives the reader did not download, which
reads as a verification failure.

[`release-process.md`](../development/release-process.md)'s manual install step
is the second site. It already requires the run to name a verifier; the script's
own digest is a third thing that can now be checked there and is not.

Filed from Q97, whose diff is what made this true. Sequencing note: Q105 and
Q106 hold both of those files for other reasons, so this waits on whichever of
them lands rather than racing it.
