# Hook entry and the launcher that denies when the binary is gone

Ready. The module and its gates have landed, and the exit-code contract that
decides what blocking looks like is measured, in
[`docs/design/README.md`](../design/README.md#the-exit-code-contract-measured).

`hooks.json` cannot invoke `spill-guard` directly. An absent binary exits 127,
and only exit 2 blocks, so the call goes through with nothing in the transcript
— 126 was driven the same way, with the same result. Empty stdout is not what
makes it pass; the exit code is. The hook is then installed, silent, and
enforcing nothing. That is the predecessor's Node-18 failure with a different
number on it, and exit-status-guard shipped the same class at exit 126 in its
1.0.0, where the launcher went out at mode 644 and the guard never fired once.

So the launcher resolves the binary and **denies** when it cannot find one,
naming the install command for the platform it is on. Spell that deny as a
`deny` decision object on stdout, which blocks whatever the launcher exits with
— so a launcher that writes its deny and then dies still blocks. Not exit 2 with
the reason on stdout: there stdout is discarded and the model is told `No stderr
output`. The resolution order is in `docs/design/distribution.md`:
`SPILL_GUARD_BIN`, then `PATH`, then the install-script location, then deny.

## Two packaging rules that are shipped bugs elsewhere

Anything `hooks.json` invokes ships executable, with the mode set in the git
index via `git update-index --chmod=+x` rather than `chmod` alone. And CI
drives the hook **through the launcher** on all three operating systems — a
suite that invokes the binary directly never executes the launcher at all, and
a launcher that stops working produces exactly the empty stdout a clean call
produces.

## The open question this item carries

Version skew between the launcher and the binary. A tap that upgrades
`spill-guard` while the plugin stays pinned gives a binary and a ruleset from
different releases. Checking every invocation costs latency on a path nobody
chose to be on; checking only in `selftest` catches it only when someone runs
`selftest`. Decide it here.
