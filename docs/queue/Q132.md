# No fixture reaches the 45-second budget any more

[`docs/design/README.md`](../design/README.md), *Driven end to end, on built
binaries*, is the budget's end-to-end exhibit: a 500 MiB fixture that took
68.130s before the budget existed and blocks at 45.011s with it. That row is
what says the deadline fires on a real call rather than only in a test.

[Pipeline step 4](../design/README.md#pipeline) moved the rate the fixture runs
at, so the row no longer reproduces. Driven 2026-09-04 on a binary built from
the branch, the same fixture built the same way: four consecutive runs denying
`aws-access-key-id` at 14.9s, 15.7s, 16.2s and 17.7s. The section carries that
correction; what it cannot carry is a replacement.

## What is owed

**A fixture that does reach the budget.** Composed from the in-process pair
behind that drive — 32.84 MiB/s against 5.68 for the arm with no rule anchored,
min of three in one process — 45 seconds is about **1,478 MiB** of
keyword-bearing text. Composed rather than driven, which is the whole of why
this is filed: nothing has run it.

**And the table re-taken.** Its columns are `v0.1.0`..`main` and *with the
budget*, which is now two changes back, so a reader cannot get today's crossing
out of it. Both columns want re-taking beside a third.

**The next release note takes the figure from this re-take, not from the last
one.** `docs/releases/v0.2.0.md` quotes 6.5 MiB/s three times and turns it into
a user-facing expectation — "puts the crossing near 290 MiB in one call" —
against a composed figure now near 1,478 MiB. Those notes are correct
as a record of v0.2.0 and are not to be edited; the hazard is that a release
note is usually written by adapting its predecessor, so the stale rate copies
forward into a live claim. Same measurement as the re-take above, so it closes
with it.

## What is not owed

The budget mechanism. `TestAScanThatOverrunsItsBudgetBlocks` drives it against
a budget already spent, on all three surfaces, and
`TestTheDeadlineFiresWhileTheMatchLoopIsRunning` drives the half that needs the
match loop actually running. Neither depends on a fixture size and neither
changed. What is missing is the reading that says a real call can still get
there.

## The machine

These runs were taken at a load average of 72, where the table's were taken on
a quiet machine — one run of the same fixture blocked at 45.046s under that
load, which is the measurement failing rather than a second answer. A re-take
wants a quiet machine, and 1,478 MiB of fixture wants the disk for it.
