# A block does not carry the notice an allowed skip gets

Q84 gave an allowed skip a `systemMessage` naming the buffer nothing read, so
the one verdict that neither blocked nor scanned stopped being silent. It fires
on that branch only. A call that also blocks — findings in one buffer, an
allowed skip in another — writes `found()` and nothing else, and the person
never learns a buffer went unread.

`found()`'s own sentence is what makes that a defect rather than an omission.
It reads *N rule match(es) in what this call would have sent*, which is a claim
about coverage and is true only of a call every buffer of which was read.
`unread()`'s doc comment already says so, in the course of explaining why it is
written ahead of `found()` — the argument was made and then applied to one of
the two branches that need it.

Reachable rather than theoretical: any multi-buffer call does it. A `Bash`
segment naming a `.env` and a `.png`, or a prompt carrying `@deploy.env` and
`@logo.png`, blocks on the first and says nothing about the second.

## Why Q84 did not take it

The fix is a `systemMessage` riding alongside a deny object in one JSON
object, which means adding the field to `preToolUseVerdict` and
`promptVerdict`. Those are the two encodings this repo drove rather than
reasoned about, and whether an extra top-level field leaves a deny blocking is
not something the exit-code table says. Adding it on inference is the shape
`verdict.go`'s own comment refuses.

Driving it is cheap and the arms are known: a deny object with a
`systemMessage` beside it, on both events, against the marker the exit-code
table already uses. Q84 drove the field on its own and it is honoured on both
events, so what is untested here is only whether it survives *beside* a
decision object — a narrower question than the one Q84 answered, and the
reason this is a row rather than a guess either way.

The confirmation path has the same hole and the same fix — `confirm()` writes
an ask object, and an override on a call with an allowed skip tells the human
what they are approving without telling them what went unread, which is worse
here than on a block because approving is the whole of what that prompt is for.
