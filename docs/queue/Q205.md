# Refuse an unresolved reader operand toward the output filter

A reader whose file operand cannot be settled -- a `$VAR` the string never
assigned, a relative path after a `cd` this cannot follow, a glob or brace
this cannot expand -- defers today: the call goes through unscanned and a
coverage record is written. When the reader's output reaches the model, refuse
the call instead, and name `set -o pipefail; <command> | <binary> filter` in
the reason, exactly as a recursive grep is refused. The bytes that cross are
the output, and the filter reads the output whichever file the operand turns
out to name.

## The question is settled, by Q203's precedent and a count

The row asked whether this reverses the 2026-09-05 *defer on a gap* decision
for a class. It does, and Q203 already made the same trade for the same
reason. The 2026-09-05 measurement priced a refusal the next call walked
around: 505 of 509 coverage blocks were followed by a clean call within four
attempts, reading the same tree another way, so the block cost a turn and
covered nothing. A refusal naming the filtered form costs one turn and closes
the gap, because the next call is the scanned one. CLAUDE.md records that the
turn this costs was accepted for the recursive-grep shape on 2026-10-01, at
about four times this rate. That shape produced 1,361 records in the 24 days
from 2026-09-07 to 2026-10-01, about 57 a day, against about 13 a day here.

The count was taken 2026-11-01 from `~/.local/state/spill-guard/coverage.jsonl`,
over every record that names its operand. That is Q200's field, and the
records carrying it run from 2026-10-26T07:16Z to 2026-11-02T03:56Z, under
seven days. Each record was joined to the `Bash` command that produced it in
the session's transcript by session id, time and operand text. Of the 1,670
`Bash` records from 2026-10-02 to 2026-10-26, only 33 carry `operands`, and all
33 are probe drives under session id `x`. The rest could not be joined and
were left out:

| | records |
|---|---|
| `Bash` records naming an operand | 286 |
| written by drives of `dev` builds under session id `x` | 34 |
| real, across 81 sessions | 252 |
| a BSD `sed -i ''` script read as the operand (Q215) | 117 |
| reader output reaches the model, no filter after it | 93 |
| reader output already piped to `spill-guard filter` | 10 |
| `grep -l`/`-c`/`-q`, `diff -q` and the like: no content | 20 |
| other: output to a file or `/dev/null`, unjoined, or matched to the wrong statement | 12 |

So in under seven days, 93 calls on this machine sent reader output to the
model unscanned. That is not a steady rate: 182 of the 252 records fall on
2026-11-01 and 2026-11-02 UTC, and only one of the 252 came from this run's own
sessions. Five of the 93 are not real gaps: a `diff` or `cmp` over `<(...)`
whose inner pattern is read as the outer reader's operand (Q216). That leaves
88, and this change would turn each into one refusal and one scanned call. Of
the 93, 49 are a variable or substitution, 31 a `cd` this cannot follow, 7 a
brace, and 6 a glob, directory or non-file. By reader: 27 `grep`, 17 `cat`, 16
`sed`, 10 `tail`, 8 `wc`, 5 `diff`, 4 `awk`, 3 `head`, and one each of
`strings`, `nl` and `cmp`.

The destination split is a heuristic. It splits the command on `;`, `&&`,
`||` and newlines, takes the statement where the reader precedes the operand,
and reads that pipeline's last stage for a redirect. The 12 in the last row
are where it could not answer. Reading one record in four from the
model-reads class by hand found the destination right each time, and that
reading is where the five Q216 misreads turned up. The scripts are not kept.
Re-take the count before citing it elsewhere.

## Which readers, settled by driving

The row's worry was that a reader whose exit status a session tests (`diff`,
`cmp`) loses it to the pipe. That worry does not hold under `pipefail`, which
the rewrite already carries. Driven 2026-11-01 with bash 5.3.15 and the
v0.6.0 filter, `set -o pipefail; <c> | spill-guard filter` exits with the
same status as `<c>` alone for `diff a b` (1), `diff a a` (0), `cmp a b` (1),
`cmp -s a b` (1) and `diff -q a b` (1). The filter exits 0 when the output is
clean, so the reader's status is what the pipeline reports. So status is no
reason to exclude a reader.

**Output size is a reason.** The filter holds back everything until its input
closes: `(echo first; sleep 3; echo second) | spill-guard filter` printed both
lines in the same second, three seconds in. A follow mode -- `tail -f`, `tail
-F` -- would never print anything, so exempt it, and a reader in follow mode
keeps deferring.

**A reader that prints no file content is exempt**, on the rule `grep.go`
already applies to `-l`, `-L`, `-c` and `-q`. That covers `wc`, `cmp` without
`-l` or `-b`, and `diff -q`. 8 of the 93 are `wc`.

`jq` and `yq` need no row entry of their own. They defer only on a variable
operand, and the rule here is per operand, not per reader, so they take the
same path when they appear.

## What to build

- In `internal/hook/bash.go`, where an unresolved operand of a known reader is
  `note`d today, refuse toward `filteredRewrite` when the reader is not exempt
  and its output is not already filtered. Use the same `cur.depth == 0` rule
  as the grep refusal for when a rewrite is offered, and the same `allFiltered`
  check before offering one, generalised from grep to every refused reader, so
  a rewrite this hook would refuse again is never handed to the model.
- **A call already ending in `spill-guard filter` writes no coverage record.**
  10 of the 252 did. The filter read their output, so a record that says the
  call went unscanned is false.
- A gap still never hides a finding (Q204). The walk goes on past the
  unresolved operand, and a match in what it did read still blocks before any
  rewrite is offered.
- A directory operand stays a refusal with no rewrite. The design's argument
  for that is about the file set a walk reads, and it is untouched here.

**This waits on Q208, or lands with it.** `filteredLater` asks whether a
filter stage follows the reader and not whether the reader's stdout reaches
it, so `cat "$F" >&2 | spill-guard filter` sends the file to stderr and the
filter reads nothing. Today that bypass covers only recursive grep. This row
would extend it to every reader. Q208 is where the descriptor gets recorded.
Land this one after Q208. Its descriptor fix is a change to ported code and
goes upstream first, so a combined PR would skip the order Q208 states.

**Done** is the refusal on every non-exempt reader with an unresolved operand
whose output reaches the model, a test per gap class (variable, `cd`, glob,
brace) asserting the refusal and its rewrite, a test that the rewrite passes
`allFiltered`, the `tail -f` and `wc` exemptions pinned, a `make
filter-rewrite` case for a non-grep reader, and the CLAUDE.md paragraph on the
recursive-grep exception widened to say this.
