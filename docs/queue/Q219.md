# `$(<file)` reads the file and nothing scans it

A command substitution whose whole body is an input redirect, such as
`$(<k.env)`, is bash's short form of `$(cat k.env)`. The file goes into the
command string's output. The hook returns no verdict on it and writes no
coverage record. Driven 2026-11-01 on the v0.6.0 binary with
`SHELL=/opt/homebrew/bin/bash`, over a scratch directory holding the planted
key from `testdata/corpus/planted/aws-access-key-id.env` as `k.env`. "prints"
means `env -i bash --norc -c` (5.3.15) wrote the key to stdout.

| command | bash | hook |
|---|---|---|
| `echo $(cat k.env)` (control) | prints | deny |
| `cat < k.env` (control) | prints | deny |
| `echo $(<k.env)` | prints | exit 0, silent |
| ``echo `<k.env` `` | prints | exit 0, silent |
| `x=$(< k.env); echo "$x"` | prints | exit 0, silent |
| `printf %s "$(<k.env)"` | prints | exit 0, silent |
| `<k.env` | nothing | exit 0, silent |

The last row is right for bash. In zsh, a redirect with no command at all runs
`$READNULLCMD` on the file. With `zsh -f`, `<k.env` and `< k.env | cat` both
print the key, and both pass the hook just as silently. So under zsh the
fail-open is not limited to a substitution. The same defect drives both, so it
goes in one row.

**The mechanism**, confirmed in the code by the independent review of the PR
that filed this row. In `internal/hook/bash.go` the segment's input redirects
are expanded first, at
`internal/hook/bash.go:186:inputs := v.expand(segment.Inputs)`. Then `if len(tokens) == 0 { continue }` drops a
segment with no command word before anything reads `inputs`, so its redirect
target is never opened. The fix is that a segment with no command word and an
input redirect reads its target. That holds inside a command substitution
under every shell, and anywhere under zsh.

**Traffic.** Nobody on this machine actually runs the shape: 0 of the 230,065
model-issued `Bash` calls in its transcripts, 2026-07-26 to 2026-11-02T03:30Z,
expand a `$(<file)` at the top level. Six of those calls contain the string,
and all six are inside a heredoc body that writes a script to disk, so the
shell running the call never expands them. This run's own drives and counts
come later and are excluded. The rank rests on the mechanism, a silent allow
under the default bash resolution, and not on traffic.
