# The admissible range for minVectors lives only in a merged PR body

Two measurements about `minVectors` were taken while Q159 was in flight and
exist nowhere a later reader will look: the **admissible range is 2–11**, and at
**0 with an empty vectors file every consumer reddens by name while
`TestTheShippedFileLoads` passes green**.

Both are in #167's pull request body. Q159's row was deleted by the merge that
completed it, `7b44c85`'s commit message does not carry them, and the constant
in the tree has no note beside it.

**This is [Q93](Q93.md)'s mechanism with an instance attached.** A squash here
builds its message from the branch's commits, so a body reaches `main` by no
strategy this repository allows. Q93 argues the general case; this row is one
measurement that has already fallen through the gap and can still be recovered
from the PR.

## What to write

The range and the empty-file finding beside the constant, as a comment or a test
name — whichever the host file's shape takes. The empty-file half is the more
valuable of the two: it says that the shipped-file test cannot see the failure,
which is a statement about the test's reach rather than about the constant.

Recovered from the PR body rather than re-derived; re-take both before writing
them down if the surrounding code has moved.

## How it surfaced

The author of a sibling pull request disclosed that it had edited #167's body
*after* that PR merged. The edit was accurate and was left in place — removing a
true record over timing would be the worse call — but a body edited after merge
is a record written to the one artifact guaranteed not to reach `main`, which is
what made the gap visible.
