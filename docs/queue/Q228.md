# A cd in a current-shell command substitution is not followed

Bash 5.3 added two command substitutions that run in the current shell, not a
subshell: `${ list; }` and `${| list; }`. A `cd` inside one moves the caller.
`echo ${ cd w; }; cat x` reads `w/x`, and the hook resolves `x` against the
directory the call started in, so with the key in `w/x` the call crosses with
no verdict and no coverage record. The reviewer of the Q212 change measured
this on a built binary of `main` at `162fcf9`. `x=${ cd w; }; cat x` blocks on
the same build.

Claude drove four shapes on bash 5.3.15 on 2026-11-01, and each one printed
`w/x`: `echo ${ cd w; }; cat x`, `echo ${| cd w; }; cat x`, `x=${ cd w; }; cat
x`, and `cat ${ cd w; } x`. The last is the sharpest. The move happens while
`cat`'s own words are being expanded, so the operand it changes sits in the
same simple command. None of the shapes except the first has been driven
through the hook.

The Q212 change already loses the directory past the definition of a moving
function, so `f() { cd w; }; echo ${ f; }; cat x` defers. What is left is a
funsub whose own body moves, with no function involved. Q226 is the same
reading for `eval`, and the two probably share a fix: an in-shell word that
runs a list in this shell loses the directory.
