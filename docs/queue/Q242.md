# us-ssn has no placeholder validator, so format fixtures deny a Read

`payment-card` has `card-placeholder`, `aws-access-key-id` has `aws-placeholder` and
`jwt` has a sample-token check. `us-ssn` has only `context-label`, so the format example
every SSN validator's docs reach for denies a `Read` wherever it sits under a label, and
`Read` has no override.

Read from the sweep's flags on 2026-11-03, not driven through a validator. "Dropped"
means every value in the file is flagged well-known, group 00 or serial 0000:

| Population | Files hit | Placeholders dropped | Area 000 and 666 dropped too |
|---|---|---|---|
| 17 projects where an SSN field belongs, 60,637 files | 81 | 36 | 24 |
| `~/go/pkg/mod`, 136,126 files | 10 | 0 | 0 |

So a denylist is worth having on the first row's hits and clears the second. Three
things to settle before writing it:

- Which values. The harness's list was written to label hits rather than to ship, so it
  has not been reviewed as a validator's table.
- Whether group 00 and serial 0000 are in scope. The case for it is that neither is
  issued, which is held from memory and not re-read here: the reviewer's fetch of ssa.gov
  returned Access Denied.
- Area 666. Dropping it takes 36 to 24 and takes `testdata/corpus/planted/us-ssn.txt`
  with it, because that fixture is in area 666 precisely so it cannot be anyone's number.
  The fixture and the `us-ssn` vector would move to another inert shape first.

The 24 left are mostly fixtures a list cannot reach, in `spec/` and `testdata/` trees, by
the same mechanism as `payment-card`: a fixture is labelled as a real record is. Recall on
real values stays unmeasured either way, so a listed value is a recall cost nothing here
can price.
