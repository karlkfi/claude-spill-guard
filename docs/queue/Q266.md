# A guarded name spelled in another case opens the file unrefused

`guardedClass` in `internal/hook/guarded.go` compares the path's basename and
parent directory to exact lowercase strings: `base == ".env"`, `dir == ".aws"
&& base == "credentials"`, and so on. The default macOS volume is APFS
case-insensitive, so `.ENV` opens the same file as `.env`, and the comparison
says it is not in the class.

Driven 2026-11-10 against a binary built from `main` at `939715e`. Each fixture
was created under its lowercase name and holds `PORT=3000`, which no rule
matches, so only the path can block it. Every variant resolved to the
fixture.

| Name used | `cat` | `Read` | `@` token |
|---|---|---|---|
| `.env`, `.env.local`, `.aws/credentials`, `.netrc`, `_netrc`, `.git-credentials`, `.docker/config.json`, `.kube/config`, `kubeconfig`, `staging.kubeconfig` (the control) | deny | deny | block |
| `.ENV`, `.Env`, `.ENV.local` | no verdict | no verdict | no verdict |
| `.AWS/credentials`, `.aws/Credentials` | no verdict | no verdict | no verdict |
| `.NETRC`, `_NETRC`, `.Git-Credentials` | no verdict | no verdict | no verdict |
| `.Docker/config.json`, `.docker/Config.json` | no verdict | no verdict | no verdict |
| `.KUBE/config`, `.kube/Config`, `KUBECONFIG`, `staging.KUBECONFIG` | no verdict | no verdict | no verdict |
| `.env.LOCAL` | deny | deny | block |

"No verdict" means exit 0 with nothing on stdout or stderr, so no coverage
record either. The content scan still runs on these files, so a key a rule
knows is still caught. What crosses is what the class exists for: the values
no rule matches. `.env.LOCAL` stays refused only because the check matches
the `.env.` prefix and never looks at what follows it.

The fail-open depends on the volume. The repo and the scratch directory this
was driven in are both on `/System/Volumes/Data`, whose personality
`diskutil info` reports as `APFS` rather than `Case-sensitive APFS`. A file
created as `aa` is found as `AA` there. On a case-sensitive APFS volume or
Linux ext4, `cat .ENV` opens a different file, usually one that does not
exist, so nothing crosses. NTFS is case-insensitive by default, so Windows
probably behaves like this Mac. That is not driven.

The traffic was not established. A regex over the words of 291,044 `Bash` and
`Read` calls in this machine's transcripts found 80 case variants of a guarded
name, against 1,677 exact-case ones. 58 of the 80 are `KUBECONFIG`, the
environment variable's name, and most of the rest are the drive scripts that
took the table above. So the count shows no organic case-variant read, and
it was not a segmentation, so it does not rule one out either. The threat
model is the accident, and a model writing `.ENV` for a file it listed as
`.env` is an unlikely one.

Folding case unconditionally is the simple fix. It refuses a file literally
named `.ENV` on a case-sensitive volume, which is credentials by the same
convention. Folding moves `.env.EXAMPLE` from refused to excluded, since that
spelling is the template on a case-insensitive volume.

## Done

Every variant in the table is refused on all three surfaces, on a
case-insensitive volume, with the control rows unchanged. A test drives at
least one variant of each member. The templates' exclusion still holds under
any spelling.
