# zsh short compound forms and `always` hide the command they run

zsh accepts compound commands bash has no grammar for: a short `if` with no
`then`, a `{ } always { }` block, and `repeat N { }`. The segmentation port
reads them as bash would, so the command inside lands in a segment headed by
a word with no reader row, and the file crosses with no verdict and no record.

Driven 2026-11-01 on the v0.6.0 binary with `SHELL=/bin/zsh`, as in Q220:

| command | bash 5.3.15 | zsh 5.9 `-f` | hook |
|---|---|---|---|
| `if [[ -f k.env ]] cat k.env` | no | reads | silent |
| `{ true } always { cat k.env }` | no | reads | silent |
| `repeat 1 { cat k.env }` | no | reads | silent |
| `if true; then cat k.env; fi` (control) | reads | reads | deny |

The zsh forms that already get an answer are in Q184's table: they deny, or
they defer and record. Only these three cross.

**Refuse to model them, and defer.** Q184 settled that this repo does not
maintain a zsh dialect beside the bash port, and that a shape the port cannot
model under zsh is a coverage failure, as Q163 and Q194 did for globs. So
under zsh, a string carrying `always`, `repeat`, or a word directly after a
closing `]]`, `))` or `)` in an `if`/`while` head defers and is recorded. It
is not parsed. The test reads the raw text, as Q194's qualifier check does,
so it is not the hand-rolled parsing CLAUDE.md refuses.

`repeat 1 cat k.env` is Q220's, because it needs no block and the peel closes
it exactly. If Q220 lands first, `repeat 1 { cat k.env }` only needs the block
half.

**Done** is the three rows pinned under `SHELL=/bin/zsh` as deferring with a
record, the control still denying, and the same three under `SHELL=bash`
unchanged.
