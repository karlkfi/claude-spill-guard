# A live credential shape in `capture_test.go` blocks reads of it

`internal/rules/capture_test.go` carries one high-entropy `AKIA`-shaped string
as test input, inline in a table rather than under `testdata/corpus/vectors/`.
The shipped `aws-access-key-id` rule matches it, so a session running this
plugin cannot `grep` or `cat` that file — the hook blocks the call and names the
rule and the byte offset.

Measured 2026-09-03 while working Q49, twice: a `grep` for two identifiers
across the package, and a read of the whole file. Both were refused. Reading it
took a `python3` pass that masked the match first, which is a workaround
producing exactly the reading the guard is there to prevent somebody skipping.

The neighbouring literal in `internal/rules/load_test.go` does not trip it, and
the difference is the point: that one is `AKIA` followed by sixteen zeros, so the
`entropy` validator drops it under the 3.0 floor. The one in `capture_test.go`
was written random enough to pass.

CLAUDE.md already names the home for this — `testdata/corpus/vectors/` is
"the credential-shaped strings the unit tests read, kept where secret scanning
is told not to look" — and `internal/testvec/` is the loader. So the fix is to
move the literal there and read it through `testvec`, not to weaken a rule.

Two things to settle rather than assume:

- Whether the vector has to stay high-entropy. Both sites that use it only need
  a string the pattern matches, and lowering the entropy would fix this without
  moving anything. That is the cheaper repair and the worse one — it makes the
  test input unrepresentative of what the rule is for, and the next author
  writing a random-looking one reintroduces this.
- Whether any other tracked file is in the same state. One file is the
  measurement; the census is not taken. `spill-guard hook` over every tracked
  file would answer it, and is the shape of a gate: a repo whose own source
  trips its own scanner cannot be read by a session running it.
