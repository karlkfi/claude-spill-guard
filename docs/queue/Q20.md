# Supply-chain gates: SHA pins, govulncheck, and Dependabot

Blocked by [Q3](Q3.md).

**This is a different surface from [Q3](Q3.md)'s gates and the overlap in the
names is misleading.** Q3 checks the shipped binary's supply chain — no
`require` block, stdlib-only import graph, no `net`. This checks the *build's*:
the third-party code that runs in CI holding the repository token, and the
known vulnerabilities in whatever the binary does link.

## Every `uses:` pinned by SHA, gated rather than conventional

A tag is mutable by whoever owns the action, and an action runs inside a job
holding the repository token, so a tag-pinned step is third-party code that can
change under us between one run and the next.

**actionlint does not close this.** It reads the ref and asserts only that one
is present and well formed, so `@v4` and `@main` both pass it. Dependabot bumps
pins and cannot stop one being written as a tag. A gate is the only thing that
catches the reference written by hand next year.

Do the checking over a real YAML parser rather than a regex: `uses:` can appear
inside a comment or a `run:` block, and neither is a mapping key. Local `./…`
actions and reusable workflows are exempt; `docker://` images need a digest
instead.

The same shape covers the release tools — cosign and goreleaser pinned by
digest or SHA, not by tag.

## The rest

`govulncheck` on a schedule and on PRs. With no third-party dependencies it is
mostly reporting stdlib advisories, which is exactly the class that otherwise
goes unnoticed in a binary nobody rebuilds between releases.

Dependabot on the `github-actions` ecosystem so the SHA pins stay fresh. It is
the maintenance half of the pin rule — pinning without updating trades a
mutable dependency for a frozen vulnerable one.
