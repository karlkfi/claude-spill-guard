# Benchmark the prefilter as implemented, and retire the inherited 280x

`docs/design/language-choice.md` section 2 puts the prefilter at 255–307 MiB/s
against 1.0 MiB/s for the regex pass — roughly 280x — and that figure was taken
on a `strings.Contains` prefilter. The same subsection then says that
implementation has to be replaced, because naive matching finds `sk-` inside
`disk-containerd-…`. So the number describes the shape the design corrects, and
it was never a measurement of the boundary-aware code that shipped.

The doc comment on `hasKeyword` quoted it as though it were, until a review
caught it.

## What is measured now, and why it is not enough

Two independent runs on 2026-08-24 agree on the finding and disagree on its
size by an order of magnitude. Both compare the prefilter stage against a regex
pass over the same corpus in the same process, both use real heterogeneous
files rather than a repeated chunk, and both assert the arms agree before
timing anything:

| | byte-at-a-time walk | `bytes.Index` | speedup |
|---|---|---|---|
| this repo's own files, 67 files, 0.32 MiB, min-of-7 | 0.398x of the regex pass | 0.139x | 2.9x |
| a 0.52 MiB corpus, 30 rules × 4 keywords, five runs | 0.78–1.10x | 0.0085–0.0162x | 52–96x |

What they agree on is the part that mattered: the walk cost about what the
regex pass it exists to skip costs, which is roughly 250x off the design's
figure, and `bytes.Index` is much better. The shipped implementation is the
`bytes.Index` one. What no one has is a number for it that two runs reproduce.

Both were taken on a machine under heavy load from parallel sessions, which is
the obvious suspect, and the corpora differ. Neither explains an order of
magnitude on its own.

## What this row has to produce

A benchmark in the tree rather than in a scratch directory, following the four
rules the design already paid for: real heterogeneous files, never a repeated
chunk, match counts asserted identical before any two timings are compared, and
fixed startup cost measured separately from throughput — below about 8 KB it
dominates, and a per-invocation hook lives there.

Then rewrite section 2's figure, or annotate it, so the repo stops carrying a
throughput claim about code it does not have. A number nobody can reproduce is
worse than no number, because it reads as evidence.

The corpus this wants is `testdata/corpus/`, which [Q7](Q7.md) brings. Taking
the measurement before then is possible and gives an answer about whatever
files happened to be lying around, which is how both readings above were
taken.
