# A declared encoding lands in the allowed class

Q74 decided that a buffer which declared itself text and could not be read
blocks, and that the binary skip does not — the axis being declaration against
inference. `internal/scan`'s prefix routing crosses that axis in both
directions, and Q74's verdict made both crossings user-visible for the first
time.

**A declared buffer in the allowed class.** A UTF-16 byte-order mark whose
decoded sniff window holds a `U+0000` returns `SkippedBinary`, so the call is
allowed in silence. Measured at the `scan.Buffer` layer:

| Buffer | First four bytes | Skip | Findings |
|---|---|---|---|
| UTF-16LE BOM, `U+0000`, then an AWS-shaped key | `FF FE 23 00` | `binary: a NUL byte in the first 8 KiB` | 0 |
| the same without the `U+0000` | `FF FE 23 00` | *(scanned)* | 1 |
| UTF-16LE BOM, leading `U+0000` | `FF FE 00 00` | `UTF-32: declared by a byte-order mark, and not decoded` | 0 |

The second row is the control: the same bytes minus the `U+0000` are read and
the key is found, so row one's silence is the skip rather than an empty file.

**The third row is the other direction.** `FF FE 00 00` is both the UTF-32LE
mark and a UTF-16LE mark followed by `U+0000`, and `decode` tests the longer
mark first — which the Unicode standard endorses and `decode.go` already
explains. Harmless while nobody reads the reason. It stops being harmless once
the reason is a deny whose value to the user *is* naming the encoding, because
there it names one the file is not in.

## Why this is not simply a bug in the decode stage

The first crossing is deliberate and pinned.
`TestBufferSkipsAUTF16BufferThatDecodesToBinary` has been on the trunk since
before Q74, and its comment states the rule as a property worth having: a NUL in
the decoded text is a statement about the text rather than about the encoding.
Read on its own terms that is defensible — the file said UTF-16 and the decode
believed it, and what came back was not text.

So this is two rules meeting rather than one rule being wrong. `internal/scan`
routes on decoded content; `internal/hook` routes on declaration. They agree
everywhere except here, and nothing in either package says which wins. Anyone
picking this up should read that test before changing it, or they will reverse a
decision somebody made on purpose and leave its rationale standing beside the
new behaviour.

## What it would take

A distinct `Skip` from the UTF-16 arm is the cheap shape: `blocks` already
routes an unrecognised reason to a block by its `default`, so the verdict
follows with no signature change and no new case. The cost is that
`internal/scan` grows a constant for a distinction only `internal/hook` cares
about, and the existing test's rationale has to be answered rather than deleted.

Not measured, and it decides how much the change is worth: how often a buffer
carrying a UTF-16 mark holds a `U+0000` in its first 8 KiB. Nothing in this
repository says. [`Q85`](Q85.md) asks the same question for the surface split
and is the neighbour to groom this against.
