# Prose asserts a release exists, and nothing reads whether one does

`docs/design/distribution.md` says **Both artifacts are already published by
the release workflow, so this asks it for nothing new.** There are no
artifacts, because there is no release: `gh release list` returns nothing and
`git ls-remote --tags` returns nothing, both measured 2026-08-31 against
controls showing the probes can come back non-empty. The sentence is on the
merge-base `793abbe`, so it predates Q12 and is live on `main` today.

**Its neighbours are the argument for a check rather than another edit.** Two
more instances of the same shape were written and fixed during Q12, both by
hand and both found by a reader rather than by a gate — one saying the
launcher's deny message was "true rather than aspirational", and Q101, which
is the same fault seen from the other side.

**The discriminator, which is the useful half.** `distribution.md` carries two
**This is built.** blocks and only one of them is wrong. The clean one asserts
*configuration that exists in the tree* — the release is created as a draft,
the workflow refuses without `docs/releases/<tag>.md` — all of which a reader
can check with no release in existence. The other asserted *outcomes that
require a release to have happened*. That is the fault line, and it is sharper
than "check the tense": a claim about a file in the tree is verifiable now, a
claim about what a release published is not.

**Distinct from [Q105](Q105.md), and the split is by what could catch each.**
Q105 is about a message naming a channel absent from `.goreleaser.yaml`, and it
deliberately excludes design prose as a false-positive source. This is about
prose asserting a release exists, its instrument is `gh release list` rather
than `.goreleaser.yaml`, and design prose is exactly where it lives. Q101 is
the state — no release — rather than a check that anything notices.

Not the third member of that family: overstating a *guarantee*, which also
happened twice during Q12 in opposite directions, is not mechanizable at all.
No check separates "the checksum database does the verifying" from "proves you
got the same code as everyone else". That one stays a reader's job.
