# A PEM key in grep output is prefixed past the rule

`spill-guard filter` reads grep's output, and grep starts every line with
`path:` or, on a context line, `path-`. `private-key-block` allows only a
diff's `+` or `-` and whitespace before each line after the header, so a key
printed by `grep -rn -A30 'PRIVATE KEY' .` arrives as lines the rule does not
match, and the filter passes it.

Reasoned from the rule's regex rather than driven: the shipped pattern's
per-line prefix is `[-+]?[ \t]*`, and nothing in it admits `./k.pem-12-`.

Same shape as Q187 and Q193, which are both about a marker column the rule
does not expect in front of a key line. One fix may close all three, so read
those first and merge if it does.

What to drive first: a planted PEM block under `grep -rn -A30` through the
filter, which should block and is expected to exit 0. The precision side
matters as much as recall here, since grep output of ordinary source is the
filter's whole traffic.
