# `matchRule` chooses its arm inline, so no test can see which one ran

[`matchRule`](../../internal/scan/scan.go) picks between running a rule at its
prefilter hits and scanning the whole buffer for it. The two arms are required
to return identical findings — that is what the 824-finding differential in
`anchor_test.go` establishes — so **nothing but cost separates them**, and the
choice is made by an expression inline in the function. No test observes it.

The consequence is bounded and real: a rule that quietly stops taking the
anchored arm costs throughput and nothing else. Measured by the reviewer of
[#110](https://github.com/karlkfi/claude-spill-guard/pull/110), excluding one
rule from the arm costs **36%** of the ruleset's throughput, from 34.07–35.26
MB/s to 22.08, with `go test ./internal/scan/ ./internal/rules/` exiting 0.

## What is already covered, so nobody re-adds it

`TestWhichShippedRulesRunFromTheirKeywordPositions` pins each rule's
eligibility boolean **and** its `Reach`, so a `reach+1` fails seven rows.
`TestEveryAnchoredRuleRefusesADenseHitListAndKeepsASparseOne` asserts both
budget arms for every anchored rule, so `budget()` returning 0 fails seven.
`TestReachIsTheLongestMatch` in `internal/rules` pins the computation.

Those went in with the change. **They do not close this**, and the drive says
so rather than the argument: with all three in place, putting
`rule.ID != "openai-api-key" &&` in front of the eligibility check leaves the
suite at exit 0. They assert `keywordPositions` and `Reach`; none of them
observes the arm `matchRule` takes.

## What would close it

Extract the arm choice from `matchRule` into a predicate the test can call, so
the condition is asserted where it is decided rather than copied into a test.
Today `anchor_test.go` recomputes `rule.Anchor != nil && boundedKeywords(...)`
as its own expression, which is the duplication that lets the two drift.

Not a timing assertion. This repo's own benchmarking rules make a wall-clock
gate untrustworthy, and the throughput-only consequence does not earn a flaky
one.

## Why it is not urgent

Every direction of this failure costs throughput. It cannot cause a missed
secret, a precision regression or a wrong verdict, because the fallback arm
reports byte-identical findings. Filed so it is not lost with the review that
found it.
