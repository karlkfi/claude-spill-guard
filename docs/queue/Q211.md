# An ANSI-C string defers the call, where upstream decodes it

A `$'…'` word is read as a bare `$` followed by a single-quoted run, so a
backslash-escaped apostrophe inside one closes the run early and the line no
longer lexes, and an operand written this way is never resolved. Each of these
reads its file under bash 5.3.15 and defers here, with every reader in the call
left unscanned. Driven 2026-10-25 on the Q202 branch against a copy of
`testdata/corpus/planted/aws-access-key-id.env` named `k.env`:

| Command | bash reads the file | Verdict here |
|---|---|---|
| `cat $'k.env'` | yes | defers: unresolvable operand |
| `cat $'w\x2fa.txt'` | yes | defers: unresolvable operand |
| `echo $'it\'s'; cat k.env` | yes | defers: `no closing quotation` |
| `echo $'\'' ; cat k.env` | yes | defers: `no closing quotation` |

`claude-bouncer` fixed this as its Q225 (`b0e3fdc`): `requote` rewrites each
unquoted `$'…'` as the single-quoted word it decodes to, and `strip_comments`
steps over one whole. The Q202 port took `requote`'s double-quote hold and the
scanner `ansiCEnd`, not the decode, so the flat reading here is still the raw
text.

`requote`'s other unported arm is Q274's (`f440dbd`), which rewrites an
unquoted backtick substitution as one double-quoted word. It was driven on
three operand shapes, a backtick substitution as `cat`'s whole operand, glued to
a prefix, and inside double quotes, and each already defers as a runtime
expansion. So it changes no verdict measured here. Port it with the decode
anyway, since the two share one function upstream and leaving half of it out
is what this row has to explain.
