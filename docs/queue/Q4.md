# Rule schema, registry loading, and project overrides

The schema is specified in `docs/design/README.md` under **Rule schema**:
`id`, `family`, `regex`, `group`, `keywords`, `entropy`, `validators`,
`enabled`. This item builds `internal/rules` — load, validate, compile — and
the merge between the shipped `rules/spill-guard.json` and a project's
`.claude/spill-guard.json`, matching how the sibling guards extend a registry
rather than replace it.

## A rule that does not compile is a startup failure

Not a skipped rule. This is the one decision in here that is easy to get
backwards, because skipping looks defensive and is the fail-open shape: a
scanner missing a rule reports the same clean result as a scanner that checked
everything.

That property is what makes gitleaks' ruleset safe to borrow from — it uses
stdlib `regexp` with no PCRE fallback, so a non-RE2 rule panics at its startup
rather than shipping.

## RE2 constraints to encode in the loader

No lookaround, no backreferences, and bounded repetition capped at 1000.
`docs/design/language-choice.md` §4 names the nine inherited rules that use
lookaround and the one that trips the repeat cap. The `group` field is what
replaces a boundary guard: capture a wider window, post-filter in code.

Reject a rule whose `keywords` are empty and whose `family` is `credential` —
that combination is an ungated full-corpus regex pass, which is the expensive
case and should be deliberate.
