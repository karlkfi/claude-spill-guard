# The documented re-vendor copies from a working tree, not from a revision

[`scripts/README.md`](../../scripts/README.md) tells the next re-vendorer to
run:

```bash
cp <skills-checkout>/session-backlog/scripts/queue.py scripts/vendor/claude-skills/queue.py
```

A checkout is not a revision. Its working tree can be behind its origin, ahead
of it, on another branch, or dirty, and the row the same edit writes names a
commit — so the two halves of the record are produced by different oracles and
nothing compares them. `make vendor` cannot help: it asserts the bytes match
the digest beside them, and both are written in one edit by whoever ran the
`cp`. The failure it leaves is a row naming a commit the bytes did not come
from, which reads exactly like a correct row.

**It did not fire on Q37, and the margin was luck.** Measured 2026-08-23: the
local `claude-skills` checkout stood at `4a1c0b3` against an origin of
`616a56f`, one commit behind. That commit is `docs(status)` and touches no
script, so the working tree's `queue.py` already hashed to `b1a0345d7efff9a9`
and a `cp` would have been correct. Had the missing commit been the one to
`queue.py` instead, the `cp` would have written `a055c5e`'s bytes under a row
saying `c0a239b`, and every gate here would have passed.

The fix is to document the read that names its own revision:

```bash
git -C <skills-checkout> fetch origin
git -C <skills-checkout> show origin/main:session-backlog/scripts/queue.py \
    > scripts/vendor/claude-skills/queue.py
```

which is what Q37 actually ran, and which leaves the mode alone: a `>` onto an
existing file truncates rather than recreates it, so the index entry stayed
`100755` — measured on Q37's commit. Worth settling in the same edit is whether
the commit the row names should be read back out of git too, since copying it
by hand is the other half of the same gap.

Not urgent. The path has been re-vendored twice — `e5dfb3f` (Q29) and Q37's own
commit — against six commits touching it in total, and `alloc-queue-id.sh` has
never been re-vendored at all. It is worth a row because the block is what a
session with no upstream history open will follow.
