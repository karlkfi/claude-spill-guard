# Deny a read of a secret-bearing config path on its shape

Q108 shipped one of its two halves. The environment half is in: a `Bash`
segment that would write the whole environment is refused on its shape, because
those values exist only in the tool process and no content rule can ever reach
them. This is the other half, and it was split out rather than shipped beside
it because the arguments do not run together.

The class the row named: `~/.claude/settings.json` first, then `.env`,
`~/.aws/credentials`, `~/.netrc`, `~/.git-credentials`,
`~/.docker/config.json`, and kubeconfig. The reason would name a filtered read
— `jq 'del(.env)' ~/.claude/settings.json`.

## Why it is not the same argument as the half that shipped

**It is reachable by content matching, and the environment half is not.** The
shipped rule exists because there is no buffer anywhere to open. These paths
are files: the reader table already resolves them, the pipeline already opens
them, and a value in one that matches a shipped rule already blocks today. What
a shape deny would add is coverage for the values the ruleset does *not*
recognise — real, and a different and smaller claim.

**It is capped by `internal/readers`, and saying so is part of the rule.**
Q108's own measurement has `cat ~/.claude/settings.json` drawing an `ask` from
workspace-guard while
`python3 -c "print(open('/Users/karl/.claude/settings.json').read())"` is
allowed outright, because existing coverage keys on the command rather than on
the path. A rule inheriting the reader table inherits that hole, and
[Q87](../design/README.md#the-rest-of-the-class-driven) settled that the table
is not about to grow: the reader class was driven on 2026-09-04 and no new
member landed in the scanner. So this half protects a path against `cat` and
not against an interpreter, and a reason that reads as *this path is guarded*
would be claiming more than it does.

**Its negative corpus is unmeasured, which is what actually stopped it.** The
half that shipped cleared a bar first: 0 refusals over 21,252 real `Bash` calls
in the week to 2026-09-04, driven through the shipped code with a positive
control. This half has no such reading. What Q108 measured is that the same
class of path is read 15 times in a week, all 15 at `~/.claude/settings.json`,
across 11 files — and it never says whether the rule would have denied all 15.
Fifteen denies a week, on a file the operator reads to debug their own config
and which workspace-guard already prompts on, is the shape Q108 itself calls
worse than no rule.

## What closing it needs

1. **The measurement, before the rule.** Sweep the same corpus for reads of the
   class and classify each: would this rule fire, and was that read one the
   operator would want stopped? The instrument is the one the shipped half
   used — drive the real code over commands lifted from transcripts, with a
   positive control proving the sweep can come back non-zero.
2. **A verdict on the in-repo `.env`.** Q108's measurement makes it the one
   member of the class where a deny is not duplicating a prompt somebody
   already sees. It is also the member most likely to hold `PORT=3000`.
3. **A reason that states the cap.** Whatever it says, it may not read as a
   claim that the path is protected, because an interpreter read of the same
   path is not.

Reads only. A **write** to `settings.json` changes what the harness does — adds
environment variables, edits `hooks`, disables a guard — which is not a spill
and is not this tool's goal. Today the two collapse into one workspace-guard
verdict for one reason, and that is the gap; spill-guard should not acquire the
write control on the way past.

## Provenance

Split from Q108 on 2026-09-04, on that row's own invitation — *the halves may
want splitting*, and *if the config half grows past a page, give it its own ID*.
The surrounding measurement is in
[`karlkfi/claude-bouncer` PR #69](https://github.com/karlkfi/claude-bouncer/pull/69),
rows Q139 and Q140. Q140 owns the `settings.json` env-injection measurement and
deliberately keeps that one path prompting while exempting the rest of
`~/.claude`; this row is the complement, turning a path-boundary `ask` into a
reasoned deny that carries its own fix.
