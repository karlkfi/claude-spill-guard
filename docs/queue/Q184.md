# Under zsh, defer on the shapes the bash port splits or leaves literal

Under zsh, two measured shapes cross with no verdict and no record. In one,
zsh glob syntax is split by the segmenter as bash operators. In the other, an
`=cmd` word is left as a literal. Under zsh, defer on both and record them,
the way Q194 defers a glob operand beside a qualifier. Do not port a zsh
segmenter.

## The shapes

Driven 2026-11-01 on the v0.6.0 binary as a zsh machine sees it
(`SHELL=/bin/zsh`, no `CLAUDE_CODE_SHELL`). The fixture is a scratch
directory with the planted AWS key as `k1.env`, and `cat k1.env` denies in
the same run.

| command | zsh 5.9 | hook | why it crosses |
|---|---|---|---|
| `cat (k1\|zz).env` | prints the key | silent | alternation, split as a pipeline |
| `cat k<1-1>.env` | prints the key | silent | numeric range, split as a redirect |
| `cat a.txt(P:k1.env:)` | prints the key | silent | a qualifier on a word with no glob metacharacter, which Q194's check never sees |
| `cat =ls` | prints `/bin/ls` | silent | `EQUALS` expansion; bash leaves it literal |
| `cat =(echo a) k1.env` | prints the key | silent | zsh's file-backed process substitution; the bash port has no `=(` |

The zsh column dates from this row's own drive on 2026-09-26 and from the
independent review of Q163. On 2026-11-01 only the hook column was re-driven,
and it is unchanged. The `=(` row was driven on 2026-11-05 under zsh 5.9, in both
columns, with a fixture named `key.txt`. `=cmd` reaches only `PATH` executables, so it is a poor
way to spill anything, but it is still a silent allow.

## The fix

Under zsh only, read the raw text before segmenting it, as Q194 already does
for a glued `(`. Defer with a record when an operand position holds any of:

- a `(`...`|`...`)` group glued to a word,
- `<`digits`-`digits`>`,
- a `(`...`)` qualifier on any word, not just one beside a glob operand,
- a word starting with `=` followed by a name or a `(`.

Under bash, all of these are unchanged.

The qualifier bullet starts from Q194's existing reading of a `(` glued to a
word and widens only the operand it applies to. It does not scan the text for
every `(`, because that would also match `$(…)`, `<(…)`, `>(…)` and a
`name()` definition. Under zsh, deferring on those would cost no findings,
since Q204 keeps the walk going, but it would flood the coverage log. How many
calls each exclusion spares has not been measured.

## The question this row asked, answered

This row asked what else in the zsh delta, beyond globbing, is a fail-open,
and whether that would mean a zsh segmentation layer. The unread members were
driven 2026-11-01 under `env -i zsh -f -c` and bash 5.3.15, against a
`cat k.env` control and through the hook as above. 40 shapes were driven,
two of them controls, and this is the outcome by class.

| member | result |
|---|---|
| named directories: `hash -d kd=<dir>; cat ~kd/k.env`, `KD=<dir>; cat ~KD/k.env`, and `cd ~KD` | zsh reads; hook defers and records. Covered. |
| `[[ ]]` and `(( ))` heads, including `[[ a =~ (a\|b) ]]` | both shells read; hook denies. No delta. |
| `foreach f (k.env) …; end`, `for f (k.env) cat $f` | zsh reads; hook defers and records. |
| `for f in k.env; cat $f` (short loop, no `do`) | zsh reads; hook denies. |
| `;;`, `;&`, `;\|` and `(x)` case arms | every arm zsh runs is denied. |
| `() { cat $1 } k.env`, `function { cat k.env }`, `&\|`, `&!`, `\|&` | denied. |
| `noglob`, `nocorrect`, `repeat N`, `coproc` | zsh reads; hook denies since Q220 |
| short `if`, `{ } always { }`, `repeat N { }` | **cross silently**: Q221 |
| bare `<k.env` (zsh's `READNULLCMD`) | zsh reads; hook denies since Q219, which was a bash defect with a zsh arm |

The decision has two halves. Where a construct has an exact grammar that the
existing peel can carry, peel it: that is Q220, which follows Q196's
precedent. Where a construct needs zsh's parser, defer under zsh: that is this
row and Q221, which follow Q163 and Q194. Nothing found needs a second
dialect. Every member that crossed is an unread head or an unsplit word, not
a different reading of a structure the port already splits.

The row's earlier tables, on `FOO[0]=x` and how far a zsh assignment error
reaches, are unchanged. They are a precision cost, not a coverage one: zsh
reads a subset of what the scanner reads. They are in this file's history at
`git show 162fcf9:docs/queue/Q184.md`.

**What this does not cover.** The 40 shapes are the ones this row and the
Q163 review named, plus precommand modifiers, short forms and the
null-command redirect, which were added from memory of zsh's grammar rather
than from a census of it. More shapes can still turn up, so call this the set
as of 2026-11-01. It does not show
the delta is closed. Sizing it by how often sessions write zsh syntax is still
the wrong instrument: this machine's tool shell is bash, so nothing here shows
what a zsh machine's sessions write.

**Done** is the four rows above pinned under `SHELL=/bin/zsh` as deferring
with a record, the `cat k1.env` control still denying, and the same strings
under `SHELL=bash` unchanged. Update the CLAUDE.md sentence that names Q184
for the operator-split shapes when it lands.
