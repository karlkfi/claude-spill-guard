# Four design sections still say a coverage failure blocks

The verdict on a coverage failure changed on 2026-09-05: an operand that will
not resolve, a buffer nothing decoded, and a scan past its budget now defer and
record instead of blocking. `docs/design/README.md` got the governing section
rewritten and the four downstream sections did not.

They are, by anchor:

- [An unread buffer is not a clean one, and the two reasons are not alike](../design/README.md#an-unread-buffer-is-not-a-clean-one-and-the-two-reasons-are-not-alike)
- [A declared encoding whose decoded text is binary blocks](../design/README.md#a-declared-encoding-whose-decoded-text-is-binary-blocks)
- [The scanner's own budget, and overrunning it blocks](../design/README.md#the-scanners-own-budget-and-overrunning-it-blocks)
- [A directory operand is refused rather than walked, and that is a decision now](../design/README.md#a-directory-operand-is-refused-rather-than-walked-and-that-is-a-decision-now)

Two of those say "blocks" in the heading itself, so the anchors move when the
prose is fixed and every citation to them has to move with it. That is the
reason this is a row rather than a `sed`.

**What is wrong is narrow, and saying so is the point.** The measurements in
all four stand. The axes stand -- declaration rather than content for the
unread buffer, and the argument against walking a directory is untouched, since
that one was never about the verdict. What is wrong is the verb: read "blocks"
as "is recorded" throughout, and the sections are correct. A rewrite that
changed anything else would be re-deciding settled questions under cover of a
prose pass.

The governing section carries a pointer saying exactly this, so a reader is not
misled in the meantime. That pointer is the thing to delete when this lands --
leaving it behind would be a second stale claim replacing the first.

## What a fix has to avoid

- **Do not repair the coverage claim by pointing at the record.** Same trap
  `CLAUDE.md` already names for the notice: the record says what went unread and
  nothing about what did not.
- **Do not rewrite the exit-code contract section.** It is measured against a
  real harness and none of it moved -- only exit 2 still blocks, a decision
  object on stdout still blocks whatever the exit, and a hook that cannot run
  still does neither. Deferring is the absence of a decision object, which that
  table already covers.
- **The release notes owe a line too.** [`docs/releases/v0.1.0.md`](../releases/v0.1.0.md)
  enumerates six cases under *What it does not read*; every coverage failure is
  now a seventh shape, and unlike the six it carries no notice to the person.
  Whether that is a patch note or waits for v0.2.0 is a release call this row
  does not take.
