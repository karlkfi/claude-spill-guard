# Other sk-ant- prefixes cross unreported, OAuth tokens among them

`anthropic-api-key` matches `sk-ant-api03-` and `sk-ant-admin01-`, each with 93 bytes
of `[A-Za-z0-9_-]` and a closing `AA`. Driven 2026-11-03 on a binary carrying that
rule, the same body behind `sk-ant-oat01-`, `sk-ant-ort01-` or `sk-ant-sid01-` exits 0
through `spill-guard filter`, where `sk-ant-api03-` exits 3.

This tool runs only under Claude Code, so its OAuth tokens are a likely Anthropic
credential to meet in a session. The independent review of the pull request that
added the rule read Claude Code 2.1.290 and reports `startsWith("sk-ant-oat")`, the
prefixes `sk-ant-si-`, `sk-ant-cc-`, `sk-ant-ccsr-` and `sk-ant-sid`, and a redactor of
its own matching `sk-ant-[A-Za-z0-9_.-]+`. Carried from that review, not re-read here.

What stops this being an edit is the length. No detector consulted publishes one for
these prefixes, and no such token near key length exists on this machine: 35
`sk-ant-` tokens over 12.36 GB, all under 20 bytes, so the census bounds nothing about
real ones. A bare prefix with no length floor is the shape to price first, against
how often sessions quote these prefixes in prose, which that census says is not never.
