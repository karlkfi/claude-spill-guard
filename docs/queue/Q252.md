# An unquoted command substitution hides the operands after it

A file named after an unquoted `$(...)` gets no verdict, even when the file holds a key.
The call defers with a record about the substitution, and the file behind it is never opened.

## Driven 2026-11-04

A built binary at `40bd774`, by payload, with `key.txt` holding a key, and the same command
under bash 5.3.15. The reviewer of #233 found it and Claude reproduced the rows:

| Command | Hook | Record | bash prints the key |
|---|---|---|---|
| `cat "$(echo plain.txt)" key.txt` | denied | 0 | yes |
| `cat key.txt $(echo plain.txt)` | denied | 0 | yes |
| `` cat `echo plain.txt` key.txt `` | denied | 0 | yes |
| `cat $X key.txt` | denied | 0 | yes |
| `cat $(echo plain.txt) key.txt` | no verdict | 1 | yes |
| `head -1 $(echo plain.txt) key.txt` | no verdict | 1 | yes |
| `grep deploy $(echo plain.txt) key.txt` | no verdict | 1 | yes |
| `cat $(pwd)/plain.txt key.txt` | no verdict | 1 | yes |
| `cat $(echo a) .env` | no verdict | 1 | not applicable, the file holds no key |
| `echo plain.txt \| xargs cat key.txt` | no verdict | 1 | yes |

The `.env` row is the path refusal missing too, where `cat "$X" .env` is denied. The record
reads `a file operand expands at run time`. That is true of the substitution and says nothing
about the file after it.

The `xargs` row is here because it looks the same and is not this bug. A wrapper that supplies
operands defers on purpose, per the comment on `wrap.Opaque` in `internal/hook/bash.go`. So
does `timeout $T cat key.txt`, which the reviewer drove by payload only, since `$T` was unset.

## What it looks like

This has not been traced through `internal/bash`. By payload, `cat $(echo a.txt) cat key.txt`
is denied while `cat $(echo a.txt) key.txt` is not, so the words after the `)` appear to be
read as a command of their own, and `key.txt` has no reader row. `$((1+1))` and
`${X:-$(echo a)}` defer the same way.

`internal/bash` is a port, so read `claude-bouncer` before writing a fix here, and take any
fix there too.

## Reach

Small and not zero. The reviewer's rough regex found this shape in 28 of 252,416 real `Bash`
calls on one machine. That regex was not validated, so read 28 as an order of magnitude.

## What is owed

The table above, red before the fix on the substitution rows that give no verdict. The `xargs`
row stays as it is.

Three places state the law "a gap does not hide a finding beside it" and name this row as the
exception: `README.md`, `CLAUDE.md` under *Block on a finding; defer on a gap*, and
`docs/design/README.md` under the same words in bold. Before #233 the last two stated it flat.
Take the exception out of all three when this lands.
