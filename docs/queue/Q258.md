# A tee or `>&2` stage after env sends the dump around the careful form

`env` alone is refused. `env | tee /dev/stderr | cut -d= -f1` and
`env | cat >&2 | cut -d= -f1` both exit 0 from the hook with no verdict,
driven 2026-11-09 on a binary built from the branch that closed Q233.
`lastInPipeline` in `internal/hook/shape.go` reads the `env` segment's own
`StdoutAway` and whether any stage follows it. It does not ask where those
stages send copies. This is the hole Q233 closed for a recursive grep and its
filter.

It is not a one-line port of `copiedAround`. For a grep, the stage that
filters is named. For `env`, any later stage counts as the careful form, so
`env | cat` is allowed today and puts the whole dump in the tool result. Which
later stages count as careful is the question to settle first.

**Done** when the `tee` and `>&2` shapes are refused, and a test pins them
beside `env | cut -d= -f1` still allowed.
