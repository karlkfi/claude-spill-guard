# The Segment.Inputs comment says an explicit descriptor is not read

The comment on `Segment.Inputs` in `internal/bash/bash.go` ends "An explicit
descriptor is not read: `3<in` opens in for reading on fd 3". Stream A
reported it stale after Q208 (#228) and Q219 (#227) landed, on 2026-11-01. The
loop that fills `Inputs` appends the target of any bare `<` token, and if the
lexer splits `3<in` into `3`, `<`, `in`, then `in` is read after all.

Neither reading has been driven for this row. A wrong comment here costs the
next session working on redirects a wrong premise, which is how Q219's
fail-open sat unread.

**Done** when a test pins what `3<in` contributes to `Inputs`, and the comment
says what the test shows.
