# The link check reads two markdown shapes it does not model

Both produce a false red, which is the direction that costs this repo most —
the gate runs on every PR and a wrong failure is what trains people to stop
reading it. Neither has an instance in the tree today, so both were measured by
construction rather than found.

**A setext heading offers no anchor.** `scripts/check-doc-links.py` collects
ATX headings only, so `Environment` underlined with `===` contributes nothing
to the file's slug set and a link to it fails. The naive fix is worse than the
gap: `---` is also a setext underline, and every row in this store closes its
frontmatter with one, so a checker that reads setext turns `size: S` into a
heading in 25 of the store's files. Whatever lands has to skip frontmatter
first. Measured 2026-08-22 on the tree at cdce10a: 28 lines would read as a
setext underline — 25 frontmatter closes and 3 inside fenced blocks the checker
already skips — and none of them is a heading.

**A link inside an indented code block is read as a link.** The checker strips
fenced blocks and inline spans; four-space indentation is the third way to
write code in markdown and it is not stripped, so a doc showing a link as an
example fails on it. `links_in` walks lines rather than blocks, which is what
makes this the harder of the two — a four-space indent means a code block only
outside a list, so the fix needs to know whether it is in one.

Take them together: one pass over `links_in` and `slugs_in` closes both, and
each on its own is too small to be worth a session.
