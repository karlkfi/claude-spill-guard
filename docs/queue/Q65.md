# Six mutation-control jobs cannot be driven on a Mac

`CLAUDE.md` names one instrument for the errexit class: *extract a step's
script verbatim from the workflow YAML and run it under `bash -e`*. It is the
only thing that reaches a `run:` block, because re-running the repo's gate over
the final tree never enters one.

Ten of those blocks start with `sed -i`, and BSD `sed` reads the next argument
as the in-place suffix. So the instrument dies on its first line with `sed: 1:
"README.md": invalid command code R` — measured 2026-08-26 at 3997cea, driving
`status-drift-mutation-control` step 0 under `bash -e` on Darwin 25.5.0.

| Job | `sed -i` blocks |
|---|---|
| `gate-drift-mutation-control` | 2 of 5 |
| `status-drift-mutation-control` | 3 of 4 |
| `hooks-check-mutation-control` | 1 of 4 |
| `test-mutation-control` | 1 of 2 |
| `action-pins-mutation-control` | 2 of 3 |
| `vulns-mutation-control` | 1 of 2 |

## Why it is worth a row

The failure is loud, which is what keeps it off the list of things that bite
silently. What it costs is the check itself: a worker adding a step to one of
these jobs cannot drive its neighbours, so the only evidence that the new step
behaves is CI, one round-trip away. The step this row came from was drivable
only because it mutates with `python3` instead — which is not a convention
anyone has stated, and the next step written will copy whichever neighbour is
nearest.

Not [Q42](Q42.md), which is about `/bin/bash` 3.2.57 running this repo's own
shell scripts. Same question — does this work on a stock Mac — and a different
mechanism, so a fix for either leaves the other standing.

## The shapes

`sed -i ''` is portable to neither: GNU sed reads the empty string as the
script. `sed -i.bak` works on both and leaves a file to clean up. `perl -i -pe`
works on both with no suffix. `python3` is already required by `make doctor`,
already used by every gate script here, and can assert its own precondition in
the same breath — which is what the mutation-control convention wants anyway,
and is the reason to prefer it over a portable `sed` spelling.

Whether the answer deserves a gate is part of the decision. A lint over `run:`
blocks for `sed -i` is cheap and would hold the convention; a convention stated
in `CLAUDE.md` and nowhere else is the shape this repo has already been bitten
by.
