# The citation window hides the drift a pull request causes itself

`stale-citation` compares a citation's line number against the tree with a
tolerance, and the tolerance is
`scripts/vendor/claude-skills/queue.py:75:CITATION_WINDOW = 10`. That window is
right for the case [Q30](Q30.md) measured and settled — a branch that moves a
line some other row cites should not go red for work it did not do, which is the
`dangling-link` shape. This row is the other case, and the window does not
distinguish them.

A branch that moves a cited line **by ten or fewer** ships a citation that is
now wrong, and no gate anywhere reports it. `make queue MERGED=true` is green,
the `queue` job on `main` is green, and the store carries a pointer that sends a
reader to the wrong line.

## Measured on this repository, 2026-08-31

The pull request completing Q85 added nine lines of comment to `blocks()` in
`internal/hook/hook.go`. [`Q10`](Q10.md) cites that file by line and fragment:

| | |
|---|---|
| Q10 cites | `exhibit:internal/hook/hook.go:237:case UserPromptSubmit:` |
| where the fragment was on `main` | 237 — correct when written |
| where it was on the branch | 246 |
| drift | 9, one inside the window |
| `make queue MERGED=true` | **exit 0, silent** |

The citation in that first cell is marked `exhibit:` because it is a record of
where Q10 pointed on `main`, not a pointer this row depends on. Unmarked it
would drift with every edit to `blocks()` — and it is worth noticing that it
sits at exactly ten lines' drift on this branch, one inside the window, which is
the defect this row is about closing over its own evidence.

It was found by hand, while checking a different citation, and it would have
merged. The next branch to move that line — the Q91 work, which adds eight more
— pushes the drift to 17 and reddens, so the branch that *reports* the defect is
not the branch that caused it. That is the same misattribution Q30 rejects, just
displaced by one PR: the window does not prevent it, it defers it.

## What would close it

The check the window cannot make: for each citation, was the cited file changed
**by this branch**, and did the fragment move? A branch's own diff is what
separates the two cases, and it is available — `git diff --name-only
origin/main...HEAD` names the files this branch touched, and any citation into
one of those has no claim on the tolerance. Everything else keeps the window.

That is a repo-side check rather than a change to the vendored linter, which
matters twice: `make vendor` pins `queue.py` by digest so patching it is a fork,
and the window has to stay for every citation the branch did not disturb.

Not decided here: whether it lives in `scripts/check-queue-index.py`, in a new
gate script, or as an argument upstream in `claude-skills`. Q30's flag work is
independent — pinning the window at the call site does not close this, because
the window is not the defect.
