# Measure whether PostToolUse can withhold a tool result

Open question in `docs/design/README.md`. It decides how much of the `Bash`
surface is reachable at all.

If a `PostToolUse` deny keeps the tool's output out of the model's context,
then `cat .env` is catchable after the fact and the command-operand heuristics
become a fast path. If it does not, `PostToolUse` is only good for warning
about content already sent, which is close to worthless, and every `Bash` case
has to be caught at `PreToolUse` from the command string alone.

## What to produce

Drive a `PostToolUse` hook that denies on a known marker string, then check
whether the marker appears in the session transcript under
`~/.claude/projects/`. The transcript is the ground truth for what went to the
API; the hook's own return value is not.

Both outcomes are useful. Record whichever one it is in
`docs/design/README.md` and adjust the hook-surface table there to match.
