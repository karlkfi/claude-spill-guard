# Digest gate for the vendored backlog tooling

[`scripts/README.md`](../../scripts/README.md) declares that `scripts/queue.py`
and `scripts/alloc-queue-id.sh` are byte-identical copies of two files in the
`session-backlog` skill, and records a sha256 for each. Nothing checks either
digest. So the declaration is prose: an edit to a vendored file moves the file
and leaves the record saying it did not, which is the state Q29 found the repo
in and the record alone does not prevent.

The property is local and cheap to assert — each vendored file still hashes to
the digest declared for it. That catches a fix written into the copy instead of
upstream, where it reaches no other repo running the same tooling and the next
re-vendor discards it. It also makes a deliberate fork legible rather than
forbidden: declaring one moves the digest in the same diff, so a reviewer sees
the file was modified without having to notice it.

**This cannot tell you whether upstream has moved, and should not try.**
`karlkfi/claude-skills` is private, so a gate that fetched it needs a token this
repo does not carry, and an oracle on the network fails when a third party is
down. `scripts/README.md` records that reasoning; this row does not reopen it.

Two things to decide:

- **Where the digests live.** They are in a markdown table today, which is a
  poor parse target. A small manifest beside the scripts — file, upstream path,
  upstream commit, sha256 — read by both the gate and the doc is the shape to
  prefer. Then settle whether the table is generated from it or duplicated with
  a check that the two agree, because a second copy is a second thing to drift.
- **Whether a fork is declarable at all.** A flag that rewrites a digest makes
  forking one command, which is either the honest escape hatch or the thing that
  makes the gate decorative. The answer decides whether the gate has one mode or
  two.

Per this repo's standing discipline the gate ships with a mutation control:
append a byte to a vendored file and require red, and require the message to
name which file, since a check that exits non-zero without saying what moved
sends the next reader to the wrong place.

The text assertions in `queue-mutation-control` are the neighbouring half and
are not this. They pin the vendored linter's *message* contract, so a re-vendor
that rewords `blocked-opener` or `dangling-link` turns them red on purpose.
A digest gate does not replace them and they do not cover a local edit that
leaves the wording alone.

Sequencing: wiring a job in touches `.github/workflows/tests.yml`, which
[Q19](Q19.md) and [Q17](Q17.md) restructure. Take this after them, or expect to
rebase the job into whatever shape they leave.
