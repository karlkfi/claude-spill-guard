# Move the vendored tooling under `scripts/vendor/`, and gate its digests

`scripts/queue.py` and `scripts/alloc-queue-id.sh` are verbatim copies of two
files in the `session-backlog` skill. Nothing about either path says so, and
[`scripts/README.md`](../../scripts/README.md) — the only thing in the tree that
does — records a sha256 for each that nothing checks.

Two halves of one fix, because the layout decides what the gate can assert.

**Move them to `scripts/vendor/claude-skills/`.** Decided 2026-08-22. The
Go-style `vendor/<source>/` grouping without the `github.com/karlkfi/` segments:
there is no resolver in `scripts/` to consume a module path, and the host and
org are already in `scripts/README.md`. Mirroring the upstream directory layout
was considered and rejected — this repo takes 2 of the 13 files in that upstream
directory, so a re-vendor is never a clean `cp -r` and the depth buys nothing.

**Then derive the gate's input set from the tree, not from a manifest.** This is
the reason the move comes first. A manifest can only check the files it already
lists, so a third vendored file added without a row is invisible to it — the
failure mode is silence, and it is on record in another repo that vendors from
the same skill. Everything under `scripts/vendor/*/` is in scope by
construction, and a file that arrives without a declared digest is a gate
failure rather than an omission nobody sees.

What the gate asserts is local: each vendored file still hashes to its declared
digest. That catches a fix written into the copy instead of upstream, where it
reaches no other repo running the same tooling and the next re-vendor discards
it. It also makes a deliberate fork legible rather than forbidden — declaring
one moves the digest in the same diff, where a reviewer sees it.

**It cannot tell you whether upstream has moved, and should not try.**
`karlkfi/claude-skills` is private, so a gate that fetched it needs a token this
repo does not carry, and an oracle on the network fails when a third party is
down. `scripts/README.md` records that reasoning; this row does not reopen it.

Still to decide: whether a fork is declarable at all. A flag that rewrites a
digest makes forking one command, which is either the honest escape hatch or the
thing that makes the gate decorative.

Per this repo's standing discipline the gate ships with a mutation control:
append a byte to a vendored file and require red, and require the message to
name which file. Add a second mutation for the property a manifest cannot have —
drop an undeclared file into `scripts/vendor/` and require red — since that one
is the whole reason for the layout.

The move is mechanical but wide: 13 call sites in `.github/workflows/tests.yml`
plus `CLAUDE.md`, [`docs/queue/README.md`](README.md),
[`scripts/README.md`](../../scripts/README.md) and a message string in
`scripts/check-queue-index.py`. It is safe — `queue.py` finds the store through
`git rev-parse --show-toplevel` rather than `__file__`, and `alloc-queue-id.sh`
uses `$0` only for its usage text, so neither cares where it lives. Verified
2026-08-22.

Both halves land after the gate list exists, so each vendor path change lands
once: `GATES` in the `Makefile` is the source of truth and `gate-drift`
reconciles it against the workflow.
