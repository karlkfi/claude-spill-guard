# A GNU tool under its Homebrew g name has no reader row

Homebrew installs GNU coreutils, grep, sed and findutils on a Mac with a `g`
prefix, so the GNU `cat` is `gcat` and the GNU `sed` is `gsed`. `aliases` in
`internal/readers/spec.go` names `gawk` and no other such name, so the rest
have no row, contribute no operands, and write no coverage record.

Driven 2026-11-09 on bash 5.3.15 against a binary built from the Q254 branch
at `3c5219d`, with `key.txt` holding a planted key:

| Command | Hook | bash prints the key |
|---|---|---|
| `cat key.txt` | deny | yes |
| `gcat key.txt` | no verdict, no record | yes |
| `ghead key.txt` | no verdict, no record | yes |
| `gwc --files0-from=key.txt` | no verdict, no record | yes |
| `gsort --files0-from key.txt` | no verdict, no record | yes |

`gsed`, `ggrep`, `gxargs` and `gfind` are not installed on this machine, so
those rows are not driven.

Of the 240,454 distinct `Bash` commands in this machine's transcripts, 37 use a
g name in command position: `gsed` 13, `gawk` 12 (already aliased), `ggrep` 5,
`gxargs` 4, `gwc` 2, `gfind` 1. The count is a regex over the command text,
not a segmentation.

`gxargs` is the wrapper half: it is not in `wrappers.go`, so nothing is peeled
off behind it and the reader it runs is never looked up.

## Done

Every g name Homebrew installs for a tool with a row in `spec.go` or
`wrappers.go` resolves to that row, and the table above denies. Where a row's
argument shape is BSD's and differs from GNU's, the g name gets GNU's reading
rather than the alias.
