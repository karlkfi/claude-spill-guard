# Four measured `internal/bash` coverage cases never reached `main`

Three `_test.go` files on `claude/cranky-bardeen-9ea62b-notes`, at `2b54a6f`,
carry 24 lines the trunk does not. That branch is not an ancestor of `main` and
has never had a pull request: `gh pr list --head
claude/cranky-bardeen-9ea62b-notes --state all` returns `[]`, where the same
query against the branch that carried #32 returns that number. [Q83](Q83.md) is
how the commit came to be sitting there.

The sources are identical either side — `git diff origin/main 2b54a6f --
internal/bash/` is those three files and nothing else — so `main` already
behaves correctly and this is coverage rather than a fix.

## The five lines nothing on `main` guards

The port shipped with 114 subtests and none of them reads these:

- `internal/bash/lex.go:207:case c == escapeChar && l.state == '"'` — the
  `l.state == '"'` half, which is what keeps a backslash literal inside single
  quotes. Two spellings, because the rule cuts both ways: `cat 'a\'` closes its
  quote and `echo 'x\'y'` leaves one open. The case already on `main` for the
  same line, `echo 'a\b'`, survives the guard's removal, which is why it does
  not stand in.
- `internal/bash/parse.go:166:for i < n && (text[i] == ' ' || text[i] == '\t')`
  — the delimiter may be separated from its operator. Without the skip,
  `cat << EOF` reads an empty delimiter, arms nothing, and the body survives
  into the lexer as phantom operands.
- The `quoted = true` in each of `scanHeredocDelim`'s backslash and
  double-quote arms. Quoting is bash's expansion switch, so `<<\EOF` and
  `<<"EOF"` each have to set it, and the single-quote arm the store already
  covers proves nothing about the other two.
- `internal/bash/subst.go:287:i += 2` — a backslash in a backtick body escapes
  the byte after it, so an escaped backtick does not close the body.

The heredoc pair is where this repository pays for a miss. One arm decides a
body is inert when it is expanded, so a substitution goes unscanned; the other
drops a body the scanner should have read. Both fail the way `CLAUDE.md` says
this class of tool fails — silently, reporting a clean result identical to a
real one.

## The condition on recovering them

All six test functions pass on a clean `cf2c78e` the moment the cases are
applied, which is also exactly what a case asserting nothing looks like.
Recovering them unproved would be worse than leaving them on the branch: the
tree would then record coverage it does not have. That is the failure
[Q66](Q66.md) sharpens — a control aimed at an equivalence reports green while
testing nothing.

So each case ships with the mutation that discriminates it, driven both ways:
red with the case present, green against `main`'s test files over the same
sources. The second arm is the one that says the line is unguarded today.
