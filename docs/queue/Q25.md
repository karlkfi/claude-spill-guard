# Check same-repo anchors in the doc-link gate

`scripts/check-doc-links.py` resolves the path half of every relative link and
throws the fragment away — `SKIP_PREFIXES` drops bare `#anchor` links, and the
file branch does `target.split("#", 1)[0]`. So a link to a heading that does not
exist passes the gate.

Found by hand while working Q1: `docs/design/language-choice.md` linked
`[Environment](#environment)` twice, and the heading is `## 6. Environment`,
whose GitHub slug is `6-environment`. Both were dead, one since the file was
written. The Q1 PR fixed those two and added four working anchors, none of
which the gate can tell apart from the dead ones.

## The docstring's reason does not cover this case

> Absolute URLs, mailto:, and bare anchors are out of scope -- a link checker
> that reaches the network is a different tool with different failure modes

That is the right call for `http://`. It does not apply to a fragment pointing
into a file already in the tree: the headings are on disk, so the check is a
second read of a file the gate has just opened, with no network and no new
failure mode.

## What to build

Collect each markdown file's heading slugs with GitHub's rule — lowercase, drop
everything that is not alphanumeric, space, or hyphen, then spaces to hyphens —
and fail any `path#fragment` or bare `#fragment` whose slug is not in the target
file's set. Duplicate headings in one file get the `-1`, `-2` suffixes GitHub
appends; either implement that or fail on duplicate slugs, but do not silently
accept an ambiguous one.

Keep the existing behaviour of reporting every failure in one run, and strip
inline code spans as well as fenced blocks before matching. A row like this one
quotes a broken link as an exhibit — a checker that only strips fences reports
the exhibit as a defect, which is how the hand-run version of this check behaved
while Q1 was being worked.

Out of scope: anchors into non-markdown files, and anything requiring the
network. Those are the cases the docstring is right about.
