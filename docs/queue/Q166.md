# A quoted operator run is split as a separator, and the file goes unread

`splitOperatorRuns` decides what to take apart by reading the token's text
alone. A word made entirely of the characters shlex groups as punctuation --
`;()<>|&` and a newline -- is treated as a run of operators and decomposed,
whether or not the quotes that made it a filename were there.

So `cat ';'` becomes `cat` followed by a `;` command boundary. The segment
carries no operand, `internal/readers` is handed a `cat` with nothing to read,
and a file the command really does open is never scanned.

## Measured

Driven 2026-09-09 against a binary built from `f0a9ea4` plus the Q92 fix, with
`testdata/corpus/planted/aws-access-key-id.env` copied to a file named `;` and
to a file named `f` in the same directory.

| command | bash opens | verdict |
|---|---|---|
| `cat f` -- control | `f` | **deny**, naming `aws-access-key-id` |
| `cat ';'` | a file named `;` | no verdict object at all, exit 0 |

The control is what says the probe can print a deny; without it a silent arm
reads the same as a scanner that was never pointed at anything.

bash's own reading, same day on 5.3.15: `cat ';'` in an empty directory prints
`cat: ;: No such file or directory`, which is the shell handing `cat` an
operand rather than ending a command.

## Why it is narrow, and why it is still a fail-open

The class is exactly the filenames spelled entirely from `;()<>|&` and newline.
Nobody names a credential file `;`. What makes it worth a row rather than a
shrug is the direction: this is a scanner reporting nothing for a file the
command reads, which is the one failure this project says it does not have, and
it is reached by quoting -- the same mechanism [Q117](Q117.md)'s glob half turns
on, and the mechanism Q92 closed for assignments and reserved words.

`cat 'a;b'` is not in the class and never was: the token holds
non-punctuation bytes, so it is left whole.

## Which way it gets built

**Upstream first**, on the route Q92 took and Q147 took after it -- the link is
dropped because that row shipped and is gone from the store. Since the
Q92 fix, `lex` already returns each token's quote provenance, so the local
change is small -- a run whose `QuotedFrom` is not `NotQuoted` is a word, not
operators -- and that is exactly what makes writing it here first the wrong
move. `CLAUDE.md` holds `internal/bash` structurally identical to its
`claude-workspace-guard` upstream so a fix transfers by inspection, and
`splitOperatorRuns` is that upstream's, unchanged.

Upstream has the same defect for a weaker reason: its guards ask whether a path
is outside the workspace, so a missed operand costs a prompt rather than an
unscanned credential. Say that in the filing, because it is why the row ranks
differently on each side.

## What happens if it is never built

Nothing reports it. A command whose only operand is spelled this way produces
no verdict, and no verdict is what a clean call produces too.
