# A quoted operator run is split as a separator, and the file goes unread

Blocked on the upstream fix in `claude-bouncer`'s `lib/bouncer_parse.py`, filed
2026-09-10 with the drive below. `CLAUDE.md` holds `internal/bash` structurally
identical to that upstream so a fix transfers by inspection, and
`splitOperatorRuns` is that upstream's, unchanged. Writing it here first is what
the row is avoiding, not the work.

**If upstream stalls, this is portable anyway.** The local change is small --
`internal/bash/lex.go:391:func splitOperatorRuns(tokens []string, quotedFrom []int) ([]string, []int) {`
already takes the provenance and does not read it -- so flip to `ready` and take
it here, recording the divergence the way [Q100](Q100.md) records the last one.
What the row must not do is sit blocked on a fix nobody is writing.

`splitOperatorRuns` decides what to take apart by reading the token's text
alone. A word made entirely of the characters shlex groups as punctuation --
`;()<>|&` and a newline -- is treated as a run of operators and decomposed,
whether or not the quotes that made it a word were there.

So `cat ';' f` becomes `cat`, a `;` command boundary, and a second segment
headed by `f`. The first segment carries no operand, the second is a command
name with no reader row, and `f` -- an ordinary file that the scanner denies on
when it is named plainly -- is never opened.

## Measured

Driven 2026-09-10 against a binary built from this branch's base, with
`testdata/corpus/planted/aws-access-key-id.env` copied to a file named `f` and
**no file named `;` present**, `cwd` set to that directory.

| command | bash opens | verdict |
|---|---|---|
| `cat f` -- control | `f` | **deny**, naming `aws-access-key-id` |
| `cat ';' f` | `f`, after erroring on `;` | no verdict object at all, exit 0 |
| `cat 'x;y' f` -- control | `f` | **deny**, naming `aws-access-key-id` |

The first control is what says the probe can print a deny; without it a silent
arm reads the same as a scanner that was never pointed at anything. The second
is the negative control: a token holding non-punctuation bytes is left whole, so
the split is the mechanism rather than the quoting.

Nothing is recorded either. `spill-guard coverage` over a fresh
`XDG_STATE_HOME` reports an empty log after the middle arm, so the call is a
silent allow and not a deferral somebody could sweep later.

bash's own reading, same day on 5.3.15: in a directory holding only `f`,
`bash -c "cat ';' f"` prints `cat: ;: No such file or directory` and then the
contents of `f`, rc=1.

## Why the earlier scope claim was wrong

This row was filed saying the class is "exactly the filenames spelled entirely
from `;()<>|&` and newline", and shrugging that nobody names a credential file
`;`. The mechanism was right and the scope was not, in the direction that
under-ranks the row.

**No such file has to exist.** The split is decided at tokenization, and `cat`
continues past an operand it could not open -- which is what the bash line above
establishes. So the credential file has an ordinary name, and what is exotic is
one quoted operator-only word somewhere in the command. Every operand after that
word goes unread, because the segment ends there.

That is still narrow. It is narrow for a different reason than the row gave, and
the reason it gave -- an oddly-named file on disk -- was the load-bearing half of
its own ranking. A groom should re-rank on the corrected class rather than on
`a3h`, which was set against the file-named-`;` reading; the key is left alone
here because a blocked row cannot be picked and the call is the groom's.

## What it costs upstream, which is more than this row said

The filed version said upstream has the same defect "for a weaker reason: its
guards ask whether a path is outside the workspace, so a missed operand costs a
prompt rather than an unscanned credential". Driven 2026-09-10 against a clone of
`claude-bouncer` at `540c1499f6dc09a7e30b938a285863aa00d238f4`, with `cwd` a
scratch git root:

| command | workspace-guard |
|---|---|
| `cat /etc/passwd` -- control | **ask**, `Outside-workspace path(s): /etc/passwd` |
| `cat ';' /etc/passwd` | **allow**, `Guarded commands target workspace/pipe only` |

It is a positive `allow`, so it suppresses the user's own permission rules on
that call rather than merely declining to add a prompt of its own. The cost
there is higher than the filing assumed, not lower, which is the argument for
the upstream fix rather than against it.

## Which way it gets built

A run whose provenance is not `NotQuoted` is a word, not operators. Upstream
already reads exactly that a few lines above the defect: its `is_reserved_word`
asks whether `quoted_from` is absent before treating a word as a shell keyword.
And `split_operator_runs` runs directly on lexer output, above every rebuild
boundary that strips the record, so the provenance is intact where the test
would go. Line numbers are left off deliberately -- that file is another repo's
and nothing here can hold a pointer into it.

Whether a run that *was* quoted should be split at all is upstream's call to
make and this row's to port. Do not answer it here.

## What happens if it is never built

Nothing reports it. A command carrying such a word produces no verdict for the
operands after it, and no verdict is what a clean call produces too.
