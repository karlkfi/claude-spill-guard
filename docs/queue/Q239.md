# The coverage record says nothing was scanned when the command string was

A deferred `Bash` or `PowerShell` call writes `Nothing scanned this call for secrets,
because the scan could not be completed`, followed by the reason. Driven on a built
binary, `Get-Content .env` through `PowerShell` and `cat "$X"` through `Bash` both
write that sentence. It is false of both: the command string was scanned, and the
same call with a key in that string is denied. `spill-guard coverage` repeats the
claim in its closing line, `Each of these is a call that proceeded with nothing
scanned`.

The sentence is `failed()` in `internal/hook/verdict.go`, and the closing line is in
`internal/hook/summary.go`. Comments in `shape.go` and `hook.go` already keep other
verdicts off that sentence because it would be false there, so the rule exists and
these two surfaces miss it. It predates the `PowerShell` tool being matched, and on a
machine with no Git Bash every shell call now lands in it.

**The fix** words the sentence for what was read: the command string was scanned, and
what it opens was not. `summary_test.go` pins the current text, so it moves with it.
