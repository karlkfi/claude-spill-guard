# Split stale-citation: two arms are branch-decidable, two are not

Q45 promoted `stale-citation` to bind on every event, and the argument it gave
holds for only half the class. Found in review of that PR, before it merged.

`queue.py lint` emits `stale-citation` for four different conditions:

| arm | decidable from | a sibling PR can flip it |
|---|---|---|
| the fragment has drifted to another line | the branch | no |
| the file no longer carries the fragment | the branch | no |
| the path does not resolve | the merged tree | **yes** — by adding the file |
| the line is past the end of the file | the merged tree | **yes** — by extending it |

The first two are what Q45 was filed to promote, and its reasoning is sound for
them: a fragment sits near the line it names or it does not, and no merge
changes that. The last two have the `dangling-link` shape exactly — red on the
branch that carries the pointer, correct in the merged set, and only until the
sibling lands. `--strict` names a class rather than an arm, so promoting the
first pair promoted the second pair with it.

Measured 2026-08-26 on Q45's own branch, citing a file only a sibling PR adds:

- post-Q45, sibling absent — `make queue` exits 2, `does not resolve from …`
- pre-Q45, same tree — exits 0, the same text as a note
- post-Q45, sibling's file present — exits 0

`make queue` is also the pre-commit hook, so this blocks the commit rather than
only a CI run.

## Why it shipped anyway

The cost was taken rather than waived, and Q45 says so at each of its four
claim sites. It is loud, it names the file, and the repair is one line — either
re-point it or mark it `exhibit:`. It fails closed, which is this repository's
posture everywhere else. The alternative was leaving the whole class merged-only,
which is the defect Q45 removed: a branch going green and reddening `main` on
the commit that lands it.

Blast radius when Q45 shipped was nil. `CITATION_RE` over the merge trees of
every open PR found live citations on one branch only, all of them resolving.

## The fix

Separate the arms so a caller can promote them independently. The shape to
check is a second class name — `unresolved-citation` for the two the merged
tree answers, `stale-citation` keeping the two the branch answers — so this
repository's `QUEUE_STRICT` takes the second and `QUEUE_STRICT_MERGED` the
first, and the two sets stop disagreeing with the reasoning printed beside
them.

`queue.py` is vendored, so this is upstream work in `session-backlog` plus a
`make vendor` refresh; `scripts/README.md` pins it by digest and the `vendor`
gate fails an edit in place. Size M for that reason rather than for the
change itself, which is small.

Adding a class also touches `NOTE_CLASSES`, and its comment argues against an
`all` switch for a reason that applies here too: a caller must not inherit a
promotion it did not ask for. Splitting is the version of that argument the
class itself needs.
