# Make `--strict` arm-granular, not class-granular

Q45 promoted `stale-citation` to bind on every event. `--strict` names a class
and the class is four separate checks, so promoting the one that matters
promoted three others with it. Found in review of that PR, twice — the first
pass caught that the promotion's stated reason was false, and the second caught
that its replacement was still wrong.

## What the four arms do

`queue.py lint` emits `stale-citation` for four conditions. The axis that
matters is not which arm fired but **who moved the line**, and that cuts across
all four:

- **Your own diff moved it.** The citation was correct when written and your
  branch's edits invalidated it. Your branch goes red, you re-point it, done.
  This is what promotion buys and it is the whole of what promotion buys.
- **A sibling branch moved it.** Your branch is green, because the citation is
  correct against the tree in front of you. `main` reddens on the merge. No
  event split reaches this: the merged tree is the first place it is visible.

Measured 2026-08-26 on Q45's branch against live PR #28, which edits
`scripts/check-doc-links.py`:

| cited | on this branch | with #28's file present |
|---|---|---|
| a fragment only #28's version carries | exit 2, `no longer carries` | exit 0 |
| the fragment at #28's line number | exit 2, `which is now at line 96` | exit 0 |
| the fragment at this branch's number | exit 0 | exit 2 |

And self-inflicted drift, same tree: a citation exact at `scripts/gates.py:40`
exits 0, and exits 2 with `now at line 60` once twenty lines are inserted above
it on the same branch.

## The distinction that does survive, and why the split is still worth making

One arm can fail on a citation whose author did everything right. A row citing
a file a **sibling PR adds** cannot resolve on your branch, because the file is
not there — the pointer is correct about the merged tree and red on the branch
carrying it, with no repair available but `exhibit:` or waiting for the sibling
to land. That is the `dangling-link` shape exactly.

The drift arms cannot do that to you. A citation written against the tree in
front of you matches it, so those arms fire only when something later moves the
line — your own diff, which is the case worth catching, or a sibling's, which
your branch cannot see either way.

So the split is real, and it is between *checks that can redden a branch for a
correct citation* and *checks that cannot*:

| arm | can fire on a citation correct against its own tree |
|---|---|
| the path does not resolve | **yes** — a sibling is adding the file |
| the line is past the end of the file | **yes** — a sibling is extending it |
| the fragment drifted to another line | no |
| the file no longer carries the fragment | no |

## The fix

Let a caller name an arm rather than the class. Either a second class name for
the top two — `unresolved-citation`, which this repository would put in
`QUEUE_STRICT_MERGED` while `stale-citation` stays in `QUEUE_STRICT` — or a
general `--strict <class>:<arm>`. The second is more work and does not
special-case one class's shape, which is the argument `NOTE_CLASSES` already
makes against an `all` switch: a caller must not inherit a promotion it did not
ask for.

`queue.py` is vendored, so this is upstream work in `session-backlog` plus a
`make vendor` refresh; `scripts/README.md` pins it by digest and the `vendor`
gate fails an edit in place. Size M for that, not for the change.

## What it does not fix

Nothing here closes the hole Q45 narrowed. A sibling that moves a cited line
still leaves a branch green and reddens `main` on the merge, whichever arm
fires and however `--strict` is spelled. `MERGED=true` on the trunk is what
catches that, and it catches it one merge late by construction.
