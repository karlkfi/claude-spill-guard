# selftest writes its canary record into the real coverage log

Every `spill-guard selftest` run appends a false record to the coverage log
the person reads with `spill-guard coverage`. Its UTF-32 arm drives a `Read`
of a file it planted itself through `hook.Run` in-process, and the deferral
that arm asserts on goes through `record`, which writes to the real
`$XDG_STATE_HOME/spill-guard/coverage.jsonl` as well as to stderr.

Measured 2026-10-01 on v0.5.0, over the log from 2026-09-07 to 2026-10-01:
225 of 2,400 records (9.4%) carry the UTF-32 reason, and all 225 name a path
under `/var/folders/…/spill-guard-selftest-*/notes.utf32`. None of them is
traffic. The test suite had the same leak, which #119 closed and which left
`coverage.jsonl.test-pollution.bak` behind on this machine; `selftest` was not
part of that fix.

The cost is per selftest run, and selftest is what a person is told to run to
check the install, so the false class grows with exactly the checking the
project asks for. It is also the one class in the log that reads as a real
encoding gap.

Point the state directory at a temporary one for the length of the run, since
`selftest` is its own process and owns its environment, and keep the stderr
record the arm asserts on. A test that runs `selftest.Run` with
`XDG_STATE_HOME` set to a temp dir and asserts no `coverage.jsonl` appears
there is the control.
