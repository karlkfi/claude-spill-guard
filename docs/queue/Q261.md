# A bash 5.3 `${ list; }` body is never read

Bash 5.3 added two command substitutions that run their body in the current
shell, `${ list; }` and `${| list; }`. `internal/bash` does not lex either. It
splits `${ cat key.txt; }` at the inner `;`, leaves `${` at the end of the word
before it, and reads the `|` of `${|` as a pipe, so the body's words join the
command around them and no reader in the body is judged.

Driven 2026-11-09 on bash 5.3.15 against a binary built from `main` at
`b814140`, with `key.txt` holding a key:

| Command | Hook | bash prints the key |
|---|---|---|
| `echo ${ cat key.txt; }` | no verdict, no record | yes |
| `echo "${ cat key.txt; }"` | no verdict, no record | yes |
| `echo ${\| cat key.txt; }` | deny, because the pipe split put `cat key.txt` in a stage of its own | yes |
| `echo $(cat key.txt)` | deny | yes |

The change that completed the in-shell-cd row records a funsub instead: any
token holding an unescaped `${` before whitespace, a `|` or the end of the word
makes the call a coverage failure and loses the directory, so the first two rows
defer with a record now. That is the gap stated, not the body read, and it
over-records a single-quoted `'${ x; }'` and a zsh `${(…)}` the lexer splits at
its `(`: 3 of 240,454 distinct `Bash` commands in this machine's transcripts.

**Done** is the lexer reading a funsub's body as a substitution that runs in the
current shell, so its readers are judged and a `cd` inside it is followed like
one in a `{ list; }` group. Upstream has no reading of either form:
`claude-bouncer`'s workspace-guard at `c1e1f81` (2026-11-06) matches neither, so
this is written here rather than ported, which CLAUDE.md asks to be argued at
the site. The `opensFunsub` check in `internal/hook/bash.go` then goes.
