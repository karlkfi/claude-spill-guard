# A process substitution's pattern is read as the outer reader's operand

In `diff <(sed -e '$a\' p.md) p.md`, an argument inside `<(...)` is reported
as a file operand of `diff`, the reader outside it. When that argument holds a
`$` or a glob character, it fails to resolve, so the call is deferred and
recorded against `diff`. Driven 2026-11-01 on the v0.6.0 binary:

| command | hook |
|---|---|
| `diff <(cat p.md) p.md` | exit 0, silent |
| `diff <(sed -e '$a\' p.md) p.md` | exit 0, record: in the `diff`, an operand "expands at run time" |
| `diff <(grep -E '^[+-]' p.md) p.md` | exit 0, record: in the `diff`, an operand "is a glob" |

The record's `operands` field names `$a\` and `^[+-]`, which are a sed script
and a regex. `'$a\'` is single-quoted, so bash expands nothing in it.

**It is not a fail-open.** Swap `p.md` for
`testdata/corpus/planted/aws-access-key-id-asia.env` in all three, and each one
denies, so the file inside the body is still read. What it costs is 5 of the
252 real operand-bearing records, 2026-10-02 to 2026-11-02: four `diff` and
one `cmp`, all over `<(...)`. It also costs precision once Q205 lands, since
Q205 refuses an unresolved operand toward the filter. Without this fix, each
of these calls would be refused over an operand that does not exist.

The mechanism has not been read. Two candidates fit the table: the body's
tokens reach the outer segment's operand list, or quote provenance is lost
inside a substitution body. The second would explain why a single-quoted `$`
reads as an expansion. Read `substStates` in `internal/hook/bash.go` first,
since it is what resolves a body where it was written.

**Done** is the three rows pinned in a hook test, with the planted-key control
beside them still denying.
