# The loader must reject configuration a check cannot use

`internal/rules` checks that a setting is *present* and that some check reads
it. It does not check that the value is one the reading code can do anything
with, so a rule can name the right check, carry the right field, load clean, and
get a gate that does not gate. Q27 closed the case where the *check* cannot
pass; this is the case where the *value* is unusable, which the presence test
cannot see.

Two of them, both measured 2026-08-24 against `internal/rules` on the tree that
closed Q27:

- **`entropy` named with no floor.** `EntropyAtLeast(s, min)` is
  `Shannon(s) >= min` and `Shannon` is never negative, so a floor of zero admits
  every candidate — measured true for `""`, `"aaaaaaaa"` and `"\x00"`. A rule
  naming `entropy` and omitting the field loads clean and returns one rule. The
  author who meant to write a floor and forgot gets no gate and no error, and
  the result is indistinguishable from a rule whose author meant no floor.

- **`keywords` holding nothing but an empty string.** The loader refuses a
  credential rule with no keywords, because an unkeyworded credential rule is
  the ungated full-corpus regex pass the prefilter exists to avoid.
  `"keywords": [""]` satisfies that guard with a list naming no literal: it
  loads, and the rule comes back carrying `[""]`.

  The consequence is the opposite of what the guard was protecting against, and
  it is worse. Read 2026-08-25 off `internal/scan/prefilter.go` at
  `origin/claude/focused-murdock-1080a2` (f6454fc, PR #22, unmerged): `hasKeyword`
  skips an empty keyword exactly as `NearLabel` skips an empty label, so it
  returns false for every buffer and the regex never runs. Once that lands, a
  credential rule with `"keywords": [""]` is silenced outright rather than
  ungated. On `main` today there is no prefilter, so nothing reads the field at
  all and the defect is latent.

One fix closes both, and `hasLabel` in `internal/rules/load.go` is the shape it
takes: read past presence into whether the value is one the check can use. That
is the same reading `NearLabel` and `hasKeyword` already do at their own end,
which is why the loader can do it once instead of every consumer doing it again.

PR #22 files a separate row for a third `keywords` defect — the field on a `pii`
rule, which no stage reads. Different fix, adjacent field; check it before
starting here.
