# The rule schema cannot express a context-proximity rule

Found while building `internal/validate`. The schema in
[`../design/README.md`](../design/README.md) under **Rule schema** has eight
fields, and none of them can hold the labels a context-proximity rule needs.

`NearLabel(buf, at, labels, window)` takes a label list and a window. The
schema offers `validators`, which is a list of names, and `keywords`, which is
something else: `keywords` are the prefilter's word-boundary literals, gating
the credential family before the regex runs at all. The design says in the same
section that numeric PII rules have no literal to anchor on and are the reason
that family ships disabled — so reusing `keywords` for labels would give every
numeric rule a prefilter it was specified not to have.

Two fields are missing, and one of them is a decision rather than an omission:

- **`labels`.** The words the value may sit near. Straightforwardly additive.
- **`window`.** Whether it is per-rule at all. `internal/validate` exports
  `DefaultLabelWindow`, measured at 64 bytes, and a rule that never overrides
  it needs no field. Per-rule is defensible — a postal code sits closer to its
  label than a free-text address does — but a knob nobody turns is a knob that
  goes stale, and this one was measured on a corpus the doc comment says
  outright is the wrong shape.

Take it before `Q4`, which builds the loader against this table. A loader
written from the schema as it stands cannot load the validator that already
exists, and the gap does not announce itself: the rule parses, compiles, runs
and reports nothing.
