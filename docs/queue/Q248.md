# A verdict or record repeats a key held in a file's name

A shell glob can hand this hook a path holding a key the model has never seen. The hook then
prints that path in its own output, and on a deny that output is what the model reads.
`found()` labels a finding with its path, and six `%w` sites wrap an `os` error whose text
holds the path into a record's reason. `coverage.go` keeps such a value out of `Operands` and
says a record's reason never names a token, and the `CLAUDE.md` rule is no fragment "because
stderr reaches the API", so all of these break a stated rule.

## Driven 2026-11-04

A built binary at Q245's head. The file's name is a rule-matching key, and no command string
below holds it:

| Call | The file | Verdict | Key on stdout | Key on stderr | Key in the log |
|---|---|---|---|---|---|
| `Bash` `cat hotdir/*` | holds a key | deny | yes | no | no |
| `Read` of that path | holds a key | deny | yes | no | no |
| `Grep` `content` over that path | holds a key | deny | yes | no | no |
| `Bash` `cat globdir/*` | mode `0o000` | no verdict, one record | no | yes | yes |
| `Bash` `for f in globdir/*; do cat "$f"; done` | mode `0o000` | no verdict, one record | no | yes | yes |
| `Bash` `cat loopdir/*` | a symlink to itself | no verdict, one record | no | yes | yes |
| `Read` of the `0o000` path | mode `0o000` | no verdict, one record | no | yes | yes |

The control is `cat ctldir/*` over a plain-named file holding the same key: deny, naming the
rule, with the key on none of the three.

Through a real `claude` 2.1.290 and the loopback fake from `scripts/check-hook-harness.py`,
`cat hotdir/*` was blocked and the `tool_result` sent to the API held the key, where the
control's did not. So the deny itself delivers the value. `cat globdir/*` proceeded and its
`tool_result` held the key too. That reads as `cat`'s own error naming the file, so the hook is
not what carried it there, though Claude did not print the text. Whether the `hook_success`
attachment carrying stderr reaches the model is unmeasured.

The sites are `reading a file this command would send`, twice in `bash.go`, `reading the file
this call would send`, twice in `hook.go`, and `reading the path this Grep call searches` and
`reading the file this Grep call searches` in `grep.go`. The driven rows reach `bash.go`'s two
and at least one of `hook.go`'s, and an earlier drive with a NUL in the path reached the first
of `grep.go`'s. Which of `hook.go`'s two a row hits, and `grep.go`'s read failure with a keyed
name, were not told apart. `TestNoPromptRefusalCarriesTheToken` already holds an `@` token out of
both streams, and that is the assertion to copy.

The population is small. The reviewer of #238 counted, with a positive control: 0 of 125,779
distinct names among 540,375 entries under `~/workspace`, `~/go/pkg/mod` and `~/.cache`, and 0
of 10,049 distinct `Read` `file_path` values across 2,924 transcripts. That is one machine and
the shipped rules, and those figures are carried from that review rather than re-taken.

## What is owed

Decide what a label says when the path itself matches a rule, in `found()` and at the six
sites, using the check `withheld` already runs. Nothing here has been built, so the remedy is
unmeasured. The test asserts stdout, stderr and the log, on each arm above.
