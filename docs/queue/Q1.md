# Measure which exit codes Claude Code treats as blocking

The whole fail-closed design rests on a claim nobody here has measured. That
only 2 blocks is documentation, carried into `docs/design/language-choice.md`
§7 as an explicitly unverified item.

The predecessor's failure is what this costs when it is wrong.
`coo-quack/sensitive-canary` exits 2 on internal error, which is correct, and
needs Node ≥22.6 for `--experimental-strip-types`. On Node 18 it exits **9**
instead, the harness does not treat 9 as blocking, and the plugin sits
installed and enforcing nothing. The exit-9 behaviour was measured; the
harness's treatment of it was inferred.

## What to produce

A table of what a `PreToolUse` hook exiting 0, 1, 2, 9, 126, and 127 actually
does to the tool call, alongside what stdout content does — the empty-stdout
case matters most, because that is what a missing binary produces and it is
the shape `docs/design/distribution.md` argues the launcher exists to prevent.

Write the result into `docs/design/README.md`, replacing the open question
rather than sitting beside it.

Do this with a throwaway hook that logs and exits with a chosen code, driven
from a scratch project. Reading the source of the installed Claude Code build
is a second-best answer and should be labelled as one if that is what the
result rests on.
