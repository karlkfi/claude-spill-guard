# Release pipeline: five targets, checksums, cosign, provenance

Blocked by [Q3](Q3.md).

Every install channel is a front-end onto one set of artifacts, so this is the
item they all depend on. Specified in `docs/design/distribution.md` under
**The base layer**.

Each release publishes five archives — darwin/arm64, darwin/amd64,
linux/amd64, linux/arm64, windows/amd64 — a `checksums.txt` over them, a
Sigstore signature of that file, and a GitHub build provenance attestation via
`actions/attest-build-provenance`, verifiable with `gh attestation verify`.

**Keyless signing, not a GPG key.** It uses the workflow's OIDC identity, so
there is no key to store, rotate, or lose. A key held by one person is a key
that expires unnoticed on a project maintained in spare hours.

GoReleaser is a release-time tool and does not touch the zero-dependency
property, which is about the shipped binary's import graph and an empty
`require` block. Pin it by commit SHA. The alternative — a hand-rolled build
matrix with `gh release upload` — has fewer moving parts and then leaves the
tap and bucket updates to be hand-rolled too.

Also needs `docs/development/release-process.md`, following the sibling repos:
which files carry the version, the direct-to-main exception for the bump
commit, and the sign-off step before anything leaves the worktree.
