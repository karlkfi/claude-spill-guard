# Stale "blocks" prose on coverage failures outside the design sections

Q144 re-verbed the four design sections the governing pointer named, and the
sweep it ran for the defect's signature found the same claim in files the row
did not name. A coverage failure — a buffer nothing decoded, a scan past its
budget, an operand that will not resolve — has deferred and been recorded since
2026-09-05, and these still say it blocks:

- `CLAUDE.md:114:skip reason it has not been taught blocks` — the UTF-8-mark
  paragraph, and `CLAUDE.md:162:a scan still running at the end of it` beside
  `CLAUDE.md:173:8s past the ceiling, blocked`, the budget paragraph. That
  file's own *Block on a finding; defer on a gap* section says the opposite
  eighty lines down, so the tree contradicts itself in the one document every
  session loads. The operand paragraph below those, which also says "blocks",
  is being rewritten by another lane and is deliberately not listed.
- `internal/hook/deadline.go:40:before it stops and blocks` and
  `internal/hook/deadline.go:48:A scan that overruns it blocks`, beside a test
  #117 renamed to `TestAScanThatOverrunsItsBudgetDefers`.
- `internal/hook/deadline_test.go:145:a spent budget blocks on the` and the
  `block above is the clock` comment in the same test.
- `internal/hook/hook.go`: the package comment's `the one path here that does
  not block`, and the two comments above `blocks()` reading `What blocks is a
  buffer that declared itself` and `what blocks and was allowed anyway`.
  Q73 touches that package comment, so take the reading after it lands.
- `internal/hook/hook_test.go:545:so it blocks for the reason` and the
  `SkippedUTF16Binary does not block` failure message six lines under it.
- `internal/scan/scan.go:92:internal/hook blocks on that` and
  `internal/scan/scan.go:197:Past the deadline the verdict is a block`.
- `internal/scan/decode.go:27:the UTF-32 arm blocks and`.
- `internal/selftest/selftest_test.go:142:arm is blocked by a skip reason`.

Same rule as Q144: only the verb moves. Where a comment names the verdict, say
*is recorded*; where it argues from the verdict — "the only verdict that keeps
this tool's promise" — the argument is the one `internal/hook/hook.go` already
makes above `abstain` for the budget branch, and the comment should cite it
rather than re-argue. `blocks()` keeps its name: it still decides which skip
reasons are treated as declared, and renaming it is a code change this row does
not ask for.

`docs/releases/` is out of scope here as it was for Q144: the invariant there
is that the file matches the published body.
