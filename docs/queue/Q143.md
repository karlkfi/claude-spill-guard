# A whitespace-only separator line defeats the PEM body clause

`private-key-block` steps from the header to the body across `[\r\n]+`, which
matches newlines and nothing else. A separator line carrying spaces is
therefore not crossed, and the key goes unreported. Driven through the compiled
shipped rule, four arms so neither direction can be a silent no-run:

| Between header and body | Reported |
|---|---|
| nothing — body on the next line | yes |
| an empty line, then an indented body | yes |
| **a line of spaces, then an indented body** | **no** |
| **a line of spaces, then an un-indented body** | **no** |

The last two rows are the gap, and the fourth is what places it: the
un-indented case fails too, so this predates the leading-whitespace widening
rather than being caused by it. The clause has stepped across newlines only
since it was written.

**There is no observed traffic.** A differential over `~/go/pkg/mod` — 239,670
files, 5.05 GiB — turned up no instance of the shape. So this is a real hole
with nothing coming through it, which is the combination that makes it a row
rather than an edit: widening a shipped rule on zero evidence is how precision
goes, and `rules/README.md` is explicit that every widening here is paid for by
a measurement.

**What would settle it is a toolchain that writes one.** OpenSSL and
`ssh-keygen` both write a bare empty line before the body of an encrypted key,
which is why the `Proc-Type:`/`DEK-Info:` arm works today. A YAML emitter that
pads a blank line inside a block scalar to the block's indent would produce
exactly the missing shape — plausible, and unobserved. Find one writing it,
or find an instance in a corpus, and the fix is one character: `[\r\n]+`
becomes `[ \t\r\n]+`.

**Check that character against the runbook before shipping it.**
`testdata/corpus/clean/tls-runbook.md` is what holds this clause's shape down,
and the change widens the *separator* rather than the line prefix, which is a
different axis from the one that was measured. Its "What the parts look like"
section is a header, prose, then an indented body line: prose is still not
whitespace, so it should stay quiet — but that is a prediction, and the clean
corpus's zero is the thing to re-take rather than reason about.

Found by the review of the pull request that widened this clause for
indentation (Q76, completed — the reference is to `git log` rather than to a
file). Out of scope there for the reason above, and recorded here so the next
person to touch the clause meets the hole rather than rediscovering it.
