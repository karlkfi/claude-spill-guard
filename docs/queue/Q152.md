# Three `self-scan` allowlist entries describe rather than decide

`scripts/check-self-scan.py` names eight tracked files that match the shipped
ruleset and are allowed to. An entry there is supposed to be a decision somebody
took. Four of the eight are Go tests carrying a credential-shaped literal, and
only one of those four is:

| File | Its entry says | Settled? |
|---|---|---|
| `internal/validate/jwt_test.go` | a table of JWT shapes, each case a specific malformation | **Yes.** The bytes are the assertion, and a JSON file would put each malformation far from the case it belongs to |
| `cmd/spill-guard/main_test.go` | the literal sits inside a JSON payload driven through the binary end to end | No |
| `internal/hook/hook_test.go` | the value the block assertions are written against | No |
| `internal/scan/decode_test.go` | the key a UTF-16 fixture is built around | No |

The bottom three read as reasons and are descriptions: each says what the
literal is doing, and none says why it could not come from
`testdata/corpus/vectors/` through `internal/testvec`. That is the difference
between an allowlist and a list of things that were already like this.

## The convention exists and does not reach them

`internal/testvec/vectors.go` states it in its package comment: what stays
inline is "the case no scanner can mistake for one -- a body a character too
long, a lowercase suffix, a padded placeholder -- because there the bytes are
what the assertion is about and belong beside it."

Two conditions, and these three satisfy one each way. All three *are*
mistakable, which points at `testvec`. But for `decode_test.go` the bytes
plausibly are what the assertion is about, since the literal is what a UTF-16
fixture gets built around. So the convention as written does not decide them,
and the row it needs is this one rather than a re-reading of that comment.

## What it costs while it stands

Each is a file a session working in this repository is refused when it reads.
Measured 2026-09-07 while taking the census: four refusals in one sitting, one
of them on a `python3` edit script bundled with a `sed` that read the file it
was editing -- the whole call was refused, so the edit never ran and the failure
looked like a no-op.

## What settles it, per file

Whether the test can take its value from `testvec` without losing what it
asserts. `Load(t)` is already available to any `_test.go` file, so the question
is legibility rather than mechanism: `main_test.go` would build its JSON payload
with `fmt.Sprintf`, and `hook_test.go` would drop a `const` for a lookup.
Neither is obviously worse and neither is obviously the same.

Anything that moves takes its line off the allowlist in the same pull request.
The gate asserts the list in both directions, so an entry left behind after its
file stops matching is a failure rather than dead weight -- which is what makes
this row's outcome verifiable either way.

`internal/selftest/selftest.go` is **not** in this class and is not part of this
row. Its canary is compiled in because a canary read from a file is one a broken
install can lose silently, and the argument is in that file's own comment. It is
a permanent member of the list. The row that measured the census settled it, and
the row that moves the `capture_test.go` literal is in flight separately.
