# Expand a glob operand instead of refusing it

`resolve` refuses any operand containing `*`, `?` or `[`
(`internal/hook/bash.go:276:strings.ContainsAny(operand, "*?[")`) because the
file set is not settled. But a glob is expanded by **bash**, before the command
runs, against the same filesystem this hook can read — so the set is settled
here in a way a directory operand's never is.

**That distinction is what keeps this out of the settled question.**
`docs/design/README.md` refuses to *walk* a directory, and the argument is that
a walk reads a different file set from the one the command sends: ripgrep
honours `.gitignore`, `grep -r` does not, `--include` and `--max-depth` change
it again, so agreement means re-implementing each reader's traversal. None of
that reaches a glob. Bash hands the command an argv the shell computed, and no
reader flag alters it. Do not close this row by citing the directory row.

**Measured 2026-09-04** across this machine's transcripts: **51 of 393**
denials land on this arm, and all 51 carry a plain POSIX pattern — no `**`, no
brace expansion. `grep -ln 'v0.2.0' docs/queue/*.md` and `grep -n … internal/hook/*.go`
are the whole population.

## Three divergences, measured rather than assumed

Driven 2026-09-04 against Go 1.x `path/filepath` and bash 5, over a directory
holding `a.txt` and `.hidden.txt`:

| Pattern | `filepath.Glob` | bash (default options) |
|---|---|---|
| `d/*` | `d/.hidden.txt`, `d/a.txt` | `d/a.txt` |
| `d/nomatch*` | empty | the literal token `d/nomatch*` |
| `d/[` | `ErrBadPattern` | passed through literally |

Only the first is a problem, and it is a precision one rather than a coverage
one: Go matches dotfiles where bash's `dotglob` is off, so a naive expansion
scans files the command never receives and can block on one of them. Filter a
leading dot per path element to match the default, and settle whether
`GLOBIGNORE` or a `shopt` earlier in the string has to poison the expansion.

The second agrees by a different route — bash passes the unmatched token
through, `os.Stat` finds nothing, and the existing "nothing there sends
nothing" path already covers it. The third is the fail-closed arm: a pattern Go
will not compile stays refused, as today.

## What decides it

51 refusals in two days of one machine's sessions, every one of them a
read-only search during code reading. The cap the expansion needs is the
scanner's own budget, which now exists — `internal/hook/deadline.go`, 45
seconds — so a glob matching thousands of files reaches a timeout block rather
than an unbounded read.
