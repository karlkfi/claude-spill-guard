# The skip verdict is per reason, and the argument under it is per surface

Q74 decided what an unread buffer does per skip reason: a declared encoding this
build cannot decode blocks, and the binary skip does not. The second half rests
on one argument — denying every image read gets the hook uninstalled, and an
uninstalled scanner enforces nothing — and that argument is about `Read`. It was
applied to both surfaces because the reason is what `internal/hook`'s `blocks`
is given, and the surface is not.

On `Bash` it is much weaker. `cat core.dump` sends the file's bytes to the model
as command output, and nobody runs that on a PNG by accident the way a session
opens an image on purpose. So the population that makes the allow necessary on
`Read` is largely absent from the operand path, while the population that makes
it cost something — a heap dump, a `.pack`, an SQLite file with a token in it —
is most of what a reader is pointed at when the operand is binary at all.

## What it does not settle

Whether the split is worth having. A verdict keyed on reason and surface is two
policies where there is now one, and the frequencies that would justify it are
not measured anywhere in this repo: nothing says how often a session `cat`s a
buffer with a NUL in the first 8 KiB, and that number is the whole case. Take it
before writing the branch, because a split that fires on nothing is a second
policy to keep true for no gain.

`internal/hook/hook.go`'s `blocks` takes a `scan.Skip` and nothing else, so
giving it the surface is a signature change and the argument for it lives in the
same comment. `docs/design/README.md`, "An unread buffer is not a clean one",
carries the per-reason half and would grow the second axis.
