# Nothing checks the release workflow's job list against anything

`gate-drift` reconciles three copies of the gate list — `GATES` in the
`Makefile`, the CI job list and the table in `CLAUDE.md` — and it reads
`tests.yml` alone, because `scripts/gates.py` pins that path:

```
$ grep -n 'WORKFLOW = ' scripts/gates.py
49:WORKFLOW = ROOT / ".github" / "workflows" / "tests.yml"
```

So `release.yml` has no such reconciliation. A job deleted from it goes
unnoticed by the check that exists to catch exactly that, and the symptom is
the one this repository already names at the top of that file: a job that does
not run reports no check, which reads identically to one that passed.

`release.yml` said so in a comment and pointed the reader at the row that
covered the mutation-control half rather than this one. That row is now
complete, so the pointer has nowhere to go and this is the row it should have
pointed at.

## Why it is worth more than it was

The file now carries a job whose entire purpose is to run on every pull
request — `published-release-verify`, which exercises the signature check the
`release` job depends on. Deleting it takes away the only coverage the signing
path has outside a tag, and removes a green tick nobody was reading rather than
producing a red one.

The same argument applies to the two `*-mutation-control` jobs already there:
each exists to fail, so each is a job whose absence is invisible.

## What the check would read

The same shape `gate-drift` already has, one file over: the jobs `release.yml`
declares, against a list something else holds. What that something is, is the
question — `GATES` is the wrong home because these are not gates and
`docs/development/release-process.md` says why. A list in the workflow's own
header comment is the cheapest candidate and the one most likely to rot; a list
in `scripts/gates.py` beside `WORKFLOW` is the one a gate can hold.

Whatever it becomes needs a mutation control that deletes a job and requires
red, on this repository's standing rule that a gate without one is a claim.
Neighbour rather than duplicate: [Q78](Q78.md) is the same shape over the
validator list, and a fix for either does not settle the other.
