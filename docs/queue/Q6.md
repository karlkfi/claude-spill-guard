# Validators: Luhn, mod-11, entropy, reserved ranges, context

Ready ahead of the pipeline: these are pure functions over a candidate string
and can be written and tested before there is anything to call them.

This is where precision comes from. `docs/design/language-choice.md` §3 is the
argument: on 257 real text files the inherited ruleset produced 5,679 matches
across 9 rules with zero credential hits, and a 27.6% file-level false-positive
rate with no true positives is a design problem rather than a tuning one.
Numeric-only patterns cannot be made precise by regex alone.

## The five

- **Luhn** for payment cards.
- **mod-11** for national ID numbers.
- **Shannon entropy floor** over the captured group, for high-entropy
  credential candidates.
- **Reserved-range exclusion** for IP rules: RFC1918, loopback, link-local,
  documentation ranges, and `0.0.0.0`. The inherited `pii-ipv4-public` matched
  `10.0.0.1` and `0.0.0.0` despite `public` in its name — that one is a
  correctness bug, not noise, and it is the clearest case for this validator
  existing.
- **Context label proximity**, so a bare numeric run counts only near a label
  like `phone:` or `ssn=`. Window size is a parameter and wants a default
  chosen against real files rather than picked.

Each gets table-driven tests asserting both directions. A validator with only
positive cases is how `65536` and a Kubernetes NodePort become postal codes.
