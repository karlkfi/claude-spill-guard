# Every install route names a release, and there is no release

`gh release list` returns nothing, measured 2026-08-31. So
`https://github.com/karlkfi/claude-spill-guard/releases/latest/download/install.sh`
is a 404, and so is the `install.ps1` beside it. Everything that points a
stuck user at a release therefore points them at nothing:

- the launcher's `DENY_MISSING` reasons, both halves, which fire exactly when
  a user has the plugin and no binary;
- the two-step form in the README and in `distribution.md`;
- `install.sh` itself with no `--version`, which resolves the `latest`
  redirect, lands on `.../releases`, sees no leading `v`, and dies naming the
  problem. That one is handled and says something useful, which is the shape
  the others should reach.

**This was not visible while the launcher named two channels instead of one.**
Q12 and Q10 between them took the deny messages from naming a Homebrew tap and
a Scoop bucket that do not exist down to naming the release assets, which was
the right edit and left one dead pointer where there had been two. The
narrowing is what exposed it.

**The window is real rather than theoretical.** Q10 makes the plugin
installable from git, so a user can reach the deny before any tag is cut. Until
the first release, the only route that works is `go install
github.com/karlkfi/claude-spill-guard/cmd/spill-guard@latest` — measured
resolving to `v0.0.0-20260829022233-793abbe87475`, with the module checksum
database doing the verifying.

Two ways to close it and they are not exclusive. Cut the first release before
the plugin is installable, which makes every pointer true at once and is the
ordering the release process wants anyway. Or name `go install` in the deny as
the route that needs no release, accepting that it asks for a Go toolchain and
that the deny reasons are otherwise deliberately per-platform.

What should not happen is a third pass over those four strings. They have been
rewritten twice in one afternoon, once per PR, and each rewrite has to keep the
launcher's split line endings intact — `make launcher` asserts them, and a
`tests.yml` control pins the CRLF count.
