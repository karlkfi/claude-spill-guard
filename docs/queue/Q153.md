# `check-plugin-version.py` carries a shebang at mode 644

`scripts/README.md` states the rule: a file advertises exactly the way it can
be run, and "a shebang on a file at `644` names an interpreter the mode
refuses." Every entry point there is meant to carry a `#!/usr/bin/env python3`
line, a `main()`, an `if __name__ == "__main__"` block, and mode `755`. The one
library, `workflow_model.py`, carries `644` and no shebang, which is the same
rule from the other side.

Measured 2026-09-07 on `04a1ba7`, reading the index rather than the working
tree:

```
git ls-files -s scripts/*.py
```

Twenty-one files, twenty with a shebang. Nineteen of those twenty are `100755`.
`scripts/check-plugin-version.py` is `100644` and has the shebang, so
`./scripts/check-plugin-version.py` does not run. It was added 2026-09-03 and
nothing has said anything since.

Nothing breaks. The same page argues that, and the argument holds: no file
there is invoked by path -- the Makefile runs `$(PYTHON) scripts/x.py` and the
workflow runs `python3 scripts/x.py` -- so the `plugin-version` gate works
exactly as it does for every other script. That is why this is small and why
nothing caught it.

It is still a violation of a rule the repository states in prose, and the fix
is one command:

```bash
git update-index --chmod=+x scripts/check-plugin-version.py
```

## What this row is not

It is not the counts. `scripts/README.md` also hand-keeps a count of its own
files, that count is stale by two again as of today, and there is already a row
for it which argues for a generated block over a hand edit. This one is about
one file's mode, which that row explicitly sets aside: its own text says the
ungated-modes argument "is about the modes. It is not about the count."

Whether to keep asserting the mode in prose at all is the open half. The page
says no gate asserts any of this **on purpose**, and one drifted file in four
days is either evidence the prose is not enough or evidence that it does not
matter. Both readings are available and this row does not take one -- fixing
the file is worth doing either way, and a gate is a separate decision from
straightening the instance.
