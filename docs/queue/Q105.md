# Nothing checks that a user-facing message names a channel that exists

Q12's review found the install scripts telling a blocked user to run `brew
install karlkfi/tap/spill-guard`, a literal command that fails because the tap
does not exist. It was fixed by hand. Nothing stops it coming back.

`scripts/check-install-scripts.py` asserts the substring `neither cosign nor
gh` and reads no further, so the whole tail of that refusal is unchecked. Every
one of the fifteen gates and every check on the pull request would stay green
if someone re-added the sentence tomorrow. `install/install.sh`'s header now
states the invariant in prose — *the refusal below names neither channel* —
which is the shape this repo treats as a claim rather than a check.

**The reason it is worth a check rather than more prose.** The message is read
by a user at the moment they are stuck, which is the worst moment to be sent
somewhere that 404s, and it is on the path the design deliberately chose: the
refusal is designed behaviour, not an error.

**What makes it mechanizable is that the answer is already in the tree.**
`.goreleaser.yaml` is the file that would carry a `brews:` or `scoops:` block,
and it carries neither, so a check has a real thing to read rather than a list
to hand-keep — the same shape as `check-release-artifacts.py` importing its
target list from `cross-compile.py` rather than restating it.

**The hard half is telling a message from a comment, and it is why this is not
a one-liner.** `install/install.sh`'s own header names `brew install
karlkfi/tap/spill-guard` deliberately, as the thing not to do, and
`docs/design/distribution.md` describes both channels at length because it is
the design of record. A naive grep over the file flags all of that. So the
check has to scope to the strings the scripts actually print — the `die`
arguments and the `NO_VERIFIER` / `$NoVerifier` constants — which is a small
parse rather than a pattern.

Its own row rather than [Q101](Q101.md): that one is about the release not
existing, this one is about nothing noticing when a message points somewhere
that does not.

Whether it belongs in `check-install-scripts.py`, which the release workflow
already runs on every pull request, or as a gate of its own is open. The first
costs nothing new and only covers the install scripts; the second reaches the
launcher's deny reasons too, which is where two instances of this exact class
survived until Q10 removed them.
