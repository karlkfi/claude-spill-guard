# Nothing reconciles `rules/README.md` with what the loader refuses

`rules/README.md` tells a rule author what a new rule needs. `internal/rules`
decides what it will accept. The two are hand-kept against each other and no
gate compares them, so the page can instruct exactly what `compile` refuses and
every check stays green.

Measured 2026-09-19, on the branch that made it true. Step 1 of "Adding a rule"
read:

> 1. A literal anchor in `keywords`, with a word boundary the regex agrees
>    with.

A clause landing in the same pull request made keywords on a non-credential
family a startup error, so that instruction became a refusal for one of the two
families. The gate over the tree that held both:

```
$ make docs
python3 scripts/check-doc-links.py
all relative links resolve, fragments included
$ echo $?
0
```

`make docs` checks relative links and nothing else. There is no other gate over
that page, so the disagreement could have stood indefinitely.

That instance is repaired in the pull request completing the item that caused
it -- named here in prose rather than linked, because the row file is deleted by
a pull request in flight. The gap is not.

**Two more instances of the same gap, found the same week and not repaired.**
Both are recorded in the row that asks whether an explicitly-ungated credential
rule should exist, named in prose for the same reason. `internal/scan/prefilter.go`
tells a rule author such a rule "ships with `keywords` empty", a spelling the
loader has refused for as long as the clause has existed; and before the
rule-schema table was edited this week, `docs/design/README.md` said "Empty
means ungated, which is expensive -- say so deliberately", of a value that was
a startup failure rather than expensive. Three sentences, three files, one
loader, and no gate over any of them. A single instance reads as a slip; three
is why this is worth a check rather than a careful reader.

**What makes this page the one worth gating, rather than docs generally.** It is
the page a rule author is sent to before writing a rule, and the only reader who
follows it is a person about to add a pattern to a security scanner. Being
wrong there costs a startup failure at best, and at worst a rule written around
an instruction the loader has quietly stopped honouring. The design doc's rule
schema has the same exposure and is cited far more, so a gate over one should
probably cover both.

**Why no existing sweep reaches it.** The citation lint keys on `path:N:fragment`
pointers, and a page giving *instructions* about behaviour carries no pointer
into the code it describes. Neither does a diff read: the falsifying change and
the falsified sentence share no file, and nothing links them. What found it was
a reviewer reading the page against the clause, which is a habit rather than an
instrument.

**What a check could compare.** The page's normative claims about the loader are
few and each names a field: which families take `keywords`, that RE2 rejects
what it rejects at startup, that an entropy floor above the group's ceiling is
refused. Each is a `compile` clause. The cheap end is a test that drives `Load`
over a rule shaped the way the page instructs and asserts it loads; the
expensive end is extracting the claims from the prose. Either beats the nothing
that is there now. The shape is unmeasured and the sizing is a guess.

**Sequence this after the decision row**, not before. Two of the three
sentences above cannot be reconciled with `compile` until somebody settles
whether the capability they describe should exist, and a gate built first would
pin whichever answer the tree happens to hold. The row that asks that question
is the one to do first.

Neighbour, not a duplicate: Q78 asks for a gate over the *validator name list*
against `rules.go`, and one fix does not close both -- a name-list comparison
says nothing about whether the authoring instructions match what `compile`
accepts. They are close enough that a maintainer may want one gate serving both,
which is worth deciding once rather than twice.
