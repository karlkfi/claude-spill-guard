# A mutation-control restore is destructive off the runner

`CLAUDE.md` tells you to drive a workflow step by extracting its script verbatim
and running it under `bash -e`, because re-running the repo's gate over the
final tree never enters a `run:` block's shell. Most of those blocks restore
themselves with `git checkout -- <path>`, which is correct on a runner and
destroys uncommitted work anywhere else.

Measured 2026-09-17 over `.github/workflows/tests.yml`: **59 steps across 19
mutation-control jobs restore with `git checkout -- <path>`; exactly two capture
the file first and restore what they captured.** On a runner the tree is a fresh
checkout at HEAD, so the two forms are equivalent. Off a runner they are not.

## What it cost, twice in one day

Two sessions hit it inside twenty-four hours during one dispatch run.

It reverted an author's uncommitted edits partway through a drive, so the next
arm went red for the right reason against the wrong file — a false red that
reads exactly like a real one, since the arm's own assertion is what fails.

It wiped a reviewer's inversion partway through a step. That measurement
survived only because the check happens to run before the restore line, which is
luck rather than design.

## The fix is a sentence, not 59 edits

Beside the paragraph in `CLAUDE.md` that mandates the practice: commit or stash
first, drive one step at a time, and never while holding a mutation you care
about. A clean tree is necessary and not sufficient — the hazard is what you are
holding *now*, not what is committed.

**Do not convert the 59 steps to capture-and-restore.** That buys the ability to
drive arms concurrently, which nobody in the run that found this needed, against
59 edits to jobs that are correct where they actually execute.

## The shape that is already right

`script-modes-mutation-control`'s empty-walk arm, added by Q153's pull
request (#170), runs both restores *before* every assertion, confirmed across four
drives — so a red arm leaves the tree and index clean. Its author did not write
that deliberately; it fell out of putting the restores immediately after the
`make` call. Worth recording that the safe shape is cheap and reachable by
accident, rather than only that the hazard exists.
