# Two of the three surfaces cannot be driven in CI, and nothing says so

**Answered 2026-09-01, and the answer split.** A session can be scripted, and
the surface this repo's fixture covers costs nothing at all to drive — no
credential, no API call, no tokens. The other two are on the far side of a
credential. The gate is [Q109](Q109.md); the residue is this row.

## What was measured

Driven against Claude Code 2.1.251 on darwin/arm64: `claude -p` under a clean
`HOME` holding no credential of any kind. The run reports `Not logged in ·
Please run /login`, bills 0 input and 0 output tokens at `total_cost_usd` 0 —
and before it gets there it has already resolved the `@` tokens it recognises,
written each file it resolved to the transcript as an attachment whose
`attachment.type` is `file`, and fired `UserPromptSubmit` with the payload
`internal/hook` decodes.

All 24 cases of `internal/hook/testdata/prompt-oracle.json` were replayed that
way, over the fixture's own tree rebuilt from `oracleTree`, and **24 of 24
agreed with the recorded `harness_files`** — 87 seconds for the set, 3.63s a
case. 14 of the cases expect a non-empty splice; 33 files cross across the set.

Two controls, because 24 of 24 is the uniform result that is usually a fact
about the instrument rather than about the subject:

- **The comparison can disagree.** Dropping one `@` token from the `positives`
  prompt moved the harness's own answer from three files to two.
- **The record tracks resolution, not the sigil.** A prompt naming
  `@secret.txt @sub/inner.txt @nosuchfile.txt @notafile` produced `file`
  records for the two that resolve and none for the two that do not.

## The premise this row was filed on was half wrong

It read: *driving a real session in CI means a Claude Code binary, credentials,
and a transcript to read — none of which this repo has or wants.* The
transcript is a file under `~/.claude/projects/`, the credential is not needed,
and the binary is the one clause still owed a measurement — this machine's is a
native executable under `~/.local/share/claude/versions/`, not an npm global,
and how a runner would get one is [Q109](Q109.md)'s to settle. The credential
clause was the load-bearing one, and for this surface it is false.

## Where the boundary actually falls

Not prompt-versus-tool, which is how it reads. **Everything before the first
API call is free, and everything after it costs a credential.** A `Read` path
or a `Bash` operand reaches a hook only once the model has chosen a tool call,
and choosing one is an API call. That is the mechanism; the observation
beside it is 25 unauthenticated runs with the `PreToolUse` matcher wired the
whole time, in which the recording hook fired `UserPromptSubmit` 25 times and
`PreToolUse` **0** times. Neither alone would settle it.

## The batch of 2026-08-28 still says what it said

Seven defects, filed as Q85, Q86, Q91 and the rest. **Every one was found by
driving. None by reading. All seven were under a green `make check` at the
moment they were found.**

Five of the seven are fail-opens: a file crosses into the model's context and
the scanner reports clean. That class has no symptom and no reporter — a user's
whole experience of it is a session that felt fine. The one defect with a
natural reporter, an over-scan that read the working directory, was caught
inside a single review round.

**So the classes this project is already good at catching are the ones with a
feedback loop, and the class the product exists to prevent has none.** Q109
gives one third of that class a loop. This row is the other two thirds.

## What is left here

A stated limitation in [`docs/design/README.md`](../design/README.md) naming
`Read` and `Bash` as the surfaces no gate can drive, why — the credential
boundary above, not a shortage of effort — and what stands in for them. The
original body argued that a stated limitation is worth more than a gate that
cannot fail, and that still holds for the half no gate can reach.

The wording depends on whether Q109 has landed, *two of three* against *all
three*. The claim is true either way, so this is not blocked on it.

## What it does not give Q95

[Q95](Q95.md) wants how long a walk of a real repository takes against the
budget a `PreToolUse` hook has. This reading produces neither number, and they
have different owners:

- **The walk time** is a local benchmark over a real tree. No harness and no
  credential, so it is Q95's own to take and cheap.
- **The budget** is [Q96](Q96.md)'s — what Claude Code does to a hook that runs
  past its timeout. What this reading does give Q96 is the shape of its own
  cost: the `UserPromptSubmit` arm it asks for is credential-free by the
  measurement above, and the `PreToolUse` arm is on the far side of the
  boundary.
