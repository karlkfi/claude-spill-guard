# `internal/bash`: the ported segmentation layer, owned by no row

`Bash` is the hard case in the design's hook surface, and half the answer to it
is resolving a command's file operands so the readers — `cat`, `head`, `tail`,
`grep` — can be scanned the way `Read` is. That resolution needs a shell
segmentation layer, and `CLAUDE.md` states as a rule that is not negotiable:

> **Do not hand-roll shell parsing.** The Bash operand resolution is a port of
> `claude-workspace-guard`'s segmentation layer, kept structurally identical so
> a fix there transfers by inspection. Writing quote-state tracking from
> scratch is the documented failure mode for this class of tool, and it fails
> silently in both directions.

`internal/bash/` appears in the proposed tree in
[`docs/design/README.md`](../design/README.md#repo-layout) and nowhere else in
the repository. Before this row, no backlog item owned it — so a rule the repo
states in bold, about the component whose failure mode is silent in both
directions, had no work item behind it.

## What the port has to preserve

Structural identity is the requirement, not behavioural equivalence measured
once. The point of keeping the shape is that a fix upstream can be read across
by inspection, and a rewrite that happens to agree today diverges the first
time either side changes.

So: same segmentation boundaries, same quote-state machine, same treatment of
`$(...)`, heredocs and redirections, function and variable names recognisable
against the original. Where Go forces a difference from the Python, say so at
the site rather than quietly.

## The two directions it fails in

A segmenter that under-splits hands the scanner a command string as one blob
and misses the operand entirely, so a `cat secrets.env` goes unscanned and
reports clean. One that over-splits invents operands that are not paths and
scans files nobody named. Neither shows up in output: the first is silence
where a finding belonged, and the second is noise that trains people to ignore
the tool. That is the same pair the precision argument turns on, one layer down.

Tests come from the same place as the code. A port that does not bring the
upstream cases across is a port whose agreement was never measured.
