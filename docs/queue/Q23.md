# Prose gates: em-dash density and page density

**Event:** the docs grow past the design set, or a review finds the same
writing tell twice in files nobody edited together.

A per-file em-dash ceiling that fails when a doc gains dashes above its
recorded baseline, or when a new doc exceeds a density rule, plus a target that
re-records the baselines so a cleanup shows up as the diff that cleared them.
The page-density companion fails on a wall of admonitions, or on two pages
saying the same thing.

## Why it is deferred rather than queued

The repo currently has a README, a privacy policy, four design docs and a
backlog. At that size a `deslop` pass reads every file in one sitting, and a
gate would be enforcing a baseline against prose one person wrote in one week.
The pattern pays when there are enough docs that nobody reads them all, and
when several people write them.

Filed because the trigger is observable and because retrofitting baselines onto
prose that has already drifted is the expensive way to arrive here.
