# Pin the citation window at the call site, at the measured value of 10

Q45 bound `stale-citation` on every event, so the window that decides what
counts as drift now governs every pull request rather than only the trunk. The
gate does not name that window. It runs `queue.py lint` with no
`--citation-window`, so the threshold is
`scripts/vendor/claude-skills/queue.py:75:CITATION_WINDOW = 10` — a default
inside a vendored file this repository does not author, which `make vendor`
pins by digest. A refresh that moves it moves the gate, and the digest says
only that the file changed.

The remaining work is one flag: `make queue` passes `--citation-window 10`
explicitly, so the number is stated where the gate reads it.

## The decision, taken 2026-08-26

Ten, and the value is not delicate. Anything from 5 to 20 behaves about the
same. What matters is that it is not 0.

**Window 0 is the one wrong answer**, and it is wrong in Q45's own terms.
Driven on this tree against `exhibit:scripts/gates.py:40:import os`, a citation
that was exact when it was written — marked, because it is a record of a drive
rather than a pointer this row depends on, and an unmarked one would make every
PR that edits `gates.py` redden on this file: clean at both settings before any edit, then one
line inserted at the top of that file. Window 0 exits 1, reporting the fragment
is now at line 41. Window 10 exits 0.

The branch that goes red there is the one that moved the line, not the one that
wrote the citation. That is the `dangling-link` shape exactly — two correct
branches, a correct merged set, one of them red for the other's work. **A
non-zero window is what keeps Q45's argument true for the arms it reaches.**
Setting it to 0 falsifies that reasoning silently, since the gate stays green
until somebody writes a citation.

**It reaches two of the four arms, and that bound is worth stating.**
`queue.py` notes and `continue`s on an unresolvable path and on a line past a
file's end before the window is ever computed, so those two fire identically at
every setting. Driven here on an unresolvable pointer: exit 1 at window 0, 10,
100 and 100000 alike, with a resolvable exact citation green at window 0 as the
control. So this row settles a knob on the drift arms; the other two are
[Q67](Q67.md)'s, which is filed to move them out of the branch-bound set
entirely. The two facts are complementary rather than in tension — what the
window cannot reach is exactly what Q67 proposes to demote.

**How often 0 would fire.** Every commit on `origin/main` at the time of
writing (49), every modified text file, the shift computed for every line
position in the pre-commit file:

|  drift | share of moving line positions |
|---:|---|
|    1-2 | 26.5% |
|    3-4 | 12.0% |
|    5-6 |  2.0% |
|   7-10 |  4.7% |
|  11-15 |  8.6% |
|  16-20 |  1.0% |
|  21-30 |  7.3% |
|  31-50 |  9.4% |
| 51-100 | 16.2% |
|   101+ | 12.3% |

21,172 moving positions out of 33,258 measured. The shift arithmetic was
checked against a line read by hand: the `run: make queue MERGED=` step in the
workflow moved +8 under Q45's own commit, which is inside 10 and outside 0.

Two things follow. The dense band is 1-4 lines — 38.5% of all movement, and the
drift a paragraph-sized insertion causes — so 0 is not a stricter setting, it
is a different gate. And 5 to 20 holds 16.3%, thinly spread: sixteen distinct
drift values sharing what four values carry below them. That is why the exact
setting is insensitive — 5 absorbs 39.3% of movers, 10 absorbs 45.1%, 20
absorbs 54.8%. The cliff sits between 0 and 5, nowhere near 10.

**Split the window by event, as this row used to propose?** No. That
reproduces Q45's defect in a new variable. Both events promote the class now,
so a split threshold leaves a pull request green at 10 and the push red at 0 —
a branch going green, merging, and reddening `main` on the commit that lands
it, which is the sentence Q45 was filed to delete.

**What ten does not buy.** It does not make a citation exact, and both doc
sites now say so rather than reading stronger than they are. A clean gate means
no citation has drifted more than ten lines. Drift accumulates across commits,
so the window buys about one commit of grace on the 45% of movers inside it and
nothing after that. It is a noise floor, not a defence.

## Where this row's old evidence went

It asked for two counts before recommending anything. Both were taken, neither
discriminates, and that is why the decision rests on the tree's edit history
instead.

**Rows failing at window 0: zero.** Also zero at 10, and at every setting
between, because at the time of measuring, the store held no live citation to
fail. Census over all 33 items using `queue.py`'s own `CITATION_RE` and loader
rather than a hand-rolled pattern, positive-controlled by planting three
citations at known drifts and confirming it classified all three. Repo markdown
outside the store held none either. A count of failing rows was a check with no
subject, and it returns 0 whichever answer is right.

**The trigger fires with this row.** The old row said to settle the window when
the first citation landed; this row is what lands it, so a session re-deriving
the census after this merges should not expect zero.

The rule this batch applies: a pointer the row *depends on* stays live, and a
record of a drive is marked `exhibit:`. So the drive above is marked —
`gates.py` is an ordinary file and an unmarked pointer into it would tax every
unrelated PR that edits it — while
`scripts/vendor/claude-skills/queue.py:75:CITATION_WINDOW = 10` stays live,
because it names the constant this decision is about, inside a digest-pinned
vendored file that only a deliberate `make vendor` refresh moves. That is the
pointer the gate should be protecting, and a refresh that shifts it ought to
redden something.

**And it does not contend with [Q99](Q99.md)**, which is the row that calls the
window a defect. The two populations are disjoint: this row settles the tolerance
for a citation the branch did not disturb, which is the population its 33,258-line
census measured and the one where window 0 reddens the wrong author. Q99 removes
the tolerance only where the branch's own diff touched the cited file, and keeps
this row's window everywhere else. Ship the flag here; that check consults the
branch diff before it consults the window.

That leaves this row carrying one live pointer, named twice, and [Q64](Q64.md)
one more into the same file. Both are into the vendored `queue.py`. Neither is
into a file an ordinary PR touches, which is the property that makes them safe
to leave unmarked under Q45's promotion.

**The two pointers the store held were one pointer.** `Q43` and this row both
carry `exhibit:parse.go:1567:26: undefined: yaml.ParserError` — the same
actionlint error, copied, with the marker travelling as designed. This row used
to say one had landed; re-derived, it was two rows holding one citation, and
neither could fire the trigger, both being marked. What fires it is the live
pointer this row ships, above.

**The `exhibit:` marker is orthogonal to the window**, rather than what makes a
tight one affordable. `lint` exempts a marked citation before every check, the
window included, so an exhibit is exempt at 0 exactly as it is at 10. The
marker removes rows that quote a pointer as their subject. The population a
tight window fires on is rows that *rely* on a working pointer, which the
marker never touches.

## Two residuals, neither of them the window

`queue.py lint` reads item bodies only, so a `path:N` pointer in
`docs/queue/README.md`, in `CLAUDE.md` or under `docs/design/` is invisible at
any window. `check-positional-citations.py`, which `queue.py`'s own comments
name, does not exist in this repository. That costs nothing today, because the
count outside the store is also zero.

The second is filed as its own row: `CITATION_RE`'s leading `\b` drops the dot
from a dotfile path, so a citation into `.github/workflows/` matches as
`github/workflows/...`, resolves from nowhere, and is reported stale whatever
its line says. Since Q45 that reddens a branch — [Q64](Q64.md), and note that
it lands on the unresolvable arm, so [Q67](Q67.md) landing first would make it
a note on a branch again.
