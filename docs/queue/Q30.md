# Pick the citation window the store gate runs with

The `queue` job promotes `stale-citation` to a failure on `main`, and runs
`queue.py lint` with the default `--citation-window 10`. That window suppresses
any drift of ten lines or fewer, which is most of what a paragraph-sized
insertion causes — so the gate as shipped has a blind spot it never reports,
and the promotion reads stronger than it is.

Nothing forced the question when the gate landed: the store holds zero
`file.ext:N` pointers, measured 2026-08-21, so both settings are green on
everything and neither is tested by anything but the mutation control. The
question arrives with the first row that cites a line.

The two settings fail in opposite directions and both are real:

- **`--citation-window 0`** requires the fragment on the line it names. Exact,
  and it reddens `main` when a sibling PR moves a cited line by one — which is
  a legitimate merged state, since the citation was correct on both branches.
- **The default 10** absorbs that, and absorbs the drift a reader would want
  reported. It is also the window under which a repointing session gets no
  signal that anything moved.

A third answer worth pricing: keep 10 on a pull request and drop to 0 on
`main`, which is the same event split the note classes already use and for the
same reason — the merged tree is where the answer is not a guess.

Settle it when the first citation lands, not before; the row exists so the
window is a decision rather than a default nobody looked at.
