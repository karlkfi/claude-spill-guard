# Point a hand-prober at selftest, not at a key it planted itself

Somebody checking whether this scanner works plants a credential-shaped string
in a file and runs `cat` over it. Four of the five shapes that come naturally to
hand produce **exit 0, no verdict, an empty stderr** — which is the signature of
a scanner that is failing open, and is here the signature of one working exactly
as specified.

Measured 2026-09-17 on a built binary, `cat k.env`:

| Planted value | Result |
|---|---|
| `AKIAIOSFODNN7EXAMPLE` | allowed |
| `ASIAIOSFODNN7EXAMPLE` | allowed |
| `AKIA` + sixteen `X` | allowed |
| anything ending `EXAMPLE` | allowed |
| `AKIA` + sixteen random | **denied** |

Two validators are doing it, both deliberately: `NotPlaceholderAWSKeyID`'s
suffix test refuses the documented example keys, and the Shannon entropy floor
of 3.0 refuses the `X` form at 1.0219 bits. Both are documented in
`rules/README.md`.

**The hazard is the inversion.** The more precise the ruleset, the more
convincing a false fail-open report becomes — because the person testing it
reaches for the values least likely to be real, which are exactly the values the
precision work exists to reject. Two of the two people who probed the scanner
during one dispatch run hit this and both initially read it as a defect.

## The fix

A sentence pointing a hand-prober at `spill-guard selftest`, which drives canary
payloads through `hook.Run` in-process and reports what it can and cannot
establish, and naming the two reasons a hand-planted key comes back silent: the
placeholder suffix test and the entropy floor.

Where it goes is open — `rules/README.md` beside the validators, the README's
install section where a new user is standing, or `CLAUDE.md`. The README is
where somebody about to probe is actually reading; `rules/README.md` is where
the explanation belongs. It may want a line in both.

The table above is measured. The fix is not.
