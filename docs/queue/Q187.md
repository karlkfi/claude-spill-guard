# A hunk header between a key header and its body is crossed by nothing

`private-key-block` steps from the PEM header to the base64 body over
horizontal whitespace, line endings and — since Q157 — a unified diff's `+` and
`-`. All three are things that sit *in front of* a line the key's own file
contains. A hunk header is a line the file does not contain at all, and nothing
crosses it.

Under `git diff`'s default three lines of context, a change close enough to a
key puts `@@ -n,m +n,m @@` between its header and its body. Driven 2026-09-19
against the shipped rule, before the Q157 change and after it, both arms
identical:

| Shape | Reported |
|---|---|
| a key on context lines, no hunk header between header and body | yes |
| a key on added lines, no hunk header between header and body | yes |
| the same with `@@ -20,3 +20,4 @@` between them, context lines | **no** |
| the same with `@@ -20,3 +20,4 @@` between them, added lines | **no** |

**Do not read this as a licence to widen.** Admitting an arbitrary line between
the header and the body is the bounded-window shape `rules/README.md` refuses
by name, and the file that refuses it is
[`testdata/corpus/clean/tls-runbook.md`](../../testdata/corpus/clean/tls-runbook.md),
whose "What the parts look like" section is a header, prose, and a body line
inside 200 bytes. A `@@`-shaped arm is a different proposition from a window
and is the candidate worth pricing; `TestTheGenericStepReportsWhatTheNamedPairDoesNot`
is the precedent for how a refused alternative gets held down.

**What is not measured**, and what would settle it:

- whether the shape has any traffic. Q157's sweep found 303 patch-like files in
  `~/go/pkg/mod` and **none** of them carrying `PRIVATE KEY`, so that
  population cannot answer it in either direction, and no other population has
  been walked.
- what a `@@` arm costs on the clean corpus, which is 13 files and cannot
  settle precision on its own, and on a differential, which can.
- whether the hunk boundary falls there often enough to matter. It needs a
  change within the context window of the key's own header, which a manifest
  with an annotation above its `tls.key` produces and a standalone `.pem` never
  does.

The producer is the same one Q157 named — `git diff`, `git show`,
`git format-patch`, reaching a session through `Read`, through a `Bash` reader
pointed at a `.patch`, and through an `@` splice. Only the recall is in
question.

Found while completing the row that admitted the diff markers, and it is a
different mechanism: that one is about what may sit in front of a line, this
one about a line the key's file never had.
