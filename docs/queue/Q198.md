# cosign 3.1 deprecates the bundle flag every verifier here passes

`cosign verify-blob --new-bundle-format` prints this on cosign v3.1.3 and
still verifies:

```
Flag --new-bundle-format has been deprecated, this will be the only supported format in future versions
```

Seen 2026-09-26 in the v0.5.0 publish check, where `install.sh` from the
published release verified `checksums.txt` and printed that line above
`Verified OK`. The flag is passed in `install/install.sh`,
`install/install.ps1`, `scripts/check-signature-identity.py` (as
`BUNDLE_FLAGS`), and in the `cosign verify-blob` line each release body carries
under **Verifying this release**.

The warning says the new format will become the only format. It does not say
the flag will be removed. If a later cosign removes it and rejects the unknown
flag, both install scripts would fail verification on every machine whose
verifier is cosign. They refuse rather than fall back, which is the intended
failure mode, and every such install would stop.
`check-signature-identity.py` names cosign v3 turning two flags into no-ops as
the thing that cost `v0.1.0-rc.1` a tag cycle, so this has happened here once
already.

What would settle it: whether cosign's release notes or source schedule a
removal, and whether the pinned cosign in the release workflow is already past
the version that warns. Dropping the flag is correct only on a cosign whose
default is the new format, which is v3 onward. A v2 cosign on a user's machine
without it would read the bundle the old way, so the scripts may need a
version check rather than a deletion.
