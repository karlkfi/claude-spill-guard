# The vectors floor equals the vector count, with zero slack

`internal/testvec/vectors.go` carries `const minVectors = 11`, and
`testdata/corpus/vectors/credentials.json` now holds exactly 11 vectors.
Zero slack.

The next person to remove a vector from that file — for any reason, in any
pull request — fails `TestTheShippedFileLoads`, and the failure names the
floor rather than the deletion that caused it:

```
credentials.json holds 10 vector(s), want at least 11
```

So the repair is a coupled edit to `vectors.go` that the remover has no reason
to expect, in a file their change did not otherwise touch. **The coupling is
this row, more than the count is.** A floor that happens to sit one below the
population is a floor; one that sits exactly on it is an equality assertion
nobody wrote down, and it will read as an unrelated failure.

## How it got here

The AWS-prefix work removed `aws-a3t-key-id` — correctly, since the shipped
rule no longer carries that arm — taking the file from 12 vectors to 11. The
floor was already 11. Nothing in that change was wrong and nothing failed;
the slack simply ran out, and no gate says so because a floor met exactly is a
floor met.

Measured 2026-09-07 on `8a7e23e`:

```
git show origin/main:testdata/corpus/vectors/credentials.json | python3 -c "import json,sys; print(len(json.load(sys.stdin)))"
grep -n 'minVectors =' internal/testvec/vectors.go
```

## What the floor is for, which decides the fix

`vectors.go` says it: "A decode returning an empty map fails no assertion by
itself: every table reading it reports zero cases, and a table test with no
cases reports the same green as one with all of them." The floor exists to
catch an **empty or truncated** read, not to pin the population.

That argues for lowering it to something well under the real count — enough to
catch a decode that returned nothing, loose enough that ordinary vector
churn never touches it. What it should not become is a number somebody has to
maintain in step with the file.

## It pulls against the other row filed in this change

The row about `TestLoadRejects` — two of its four cases cannot fail for the
check they name — has a repair that pads each fixture body past the floor.
That couples those fixtures to `minVectors` from the other direction: pad them
to 11 and lowering the floor later means revisiting them.

The two are compatible if the other row takes its *first* repair instead
(assert which failure was recorded, rather than counting), which couples
nothing. Whichever lands first should say what it did to the other.
