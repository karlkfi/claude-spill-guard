# File the Node-18 fail-open upstream to sensitive-canary

`coo-quack/sensitive-canary` requires Node ≥22.6 for
`--experimental-strip-types` and exits **9** on older Node. The harness does not
treat 9 as blocking, so the plugin is installed, checking nothing, and
reporting nothing — while presenting as an active secret scanner.

This repo's public design docs already describe the defect, and its maintainer
has not been told.

## Why this is the maintainer's call and not a groom's

It publishes outside this repository, which is the test — not that the write-up
is hard. The defect disables their tool rather than exploiting it, so the
disclosure stakes are low and ordinary issue-filing is the right channel.

The report should carry the measurement rather than the symptom: the exact Node
version, the observed exit code, and the claim it collides with — that only
exit 2 blocks, which is documentation this project has itself flagged as
unverified and which [Q1](Q1.md) is measuring. Filing before Q1 lands means
filing an inferred mechanism, which costs the maintainer a round trip.
