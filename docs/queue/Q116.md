# Two branches incrementing one count merge cleanly to the wrong number

A count written by hand in prose goes stale because nothing re-reads it, which Q72 argues for the corpus table.
This row is the cost that parallel branches add on top of that, and the shape it takes changed when #277 made every Markdown file one sentence per line.

**Before #277 the cost was a conflict.** On 2026-09-01 two branches each added a script and each rewrote `scripts/README.md`'s count from `fifteen` to `sixteen`.
The words agreed and the line breaks did not, because the longer number made the paragraph rewrap, so the merge conflicted on bytes that meant the same thing.
The workflow comments had the same shape: `release.yml`'s `dry-run-mutation-control` header read `Two mutations`, two branches rewrote it to `Three` and `Four`, and their rewraps conflicted while the step insertions merged.

**After #277 the Markdown case merges, and merges wrong.** One sentence is one line, so two branches that each add one item from a base of `sixteen` both write the same line saying `seventeen`.
`git merge-file` takes identical changes on both sides as agreement and exits 0, and the true count is eighteen.
Replayed 2026-11-26 with three blobs: wrapped, as on 2026-09-01, it exits 1; one sentence per line, it exits 0 with `seventeen` in the result.
A conflict at least stopped somebody; this is staleness that arrives through the merge itself, with nothing to see.

The workflow comments are wrapped by hand and outside `md-reflow`, so they still conflict.
The pull request that narrowed this row removed their headline counts, which leaves Markdown as the open half.

## What would close it

Find the Markdown prose that states a running count of something the tree holds, outside a dated measurement, and apply one of the two repairs that already exist here.
Either derive it, as `gates.py` and `check-status.py` derive their tables with a `--check` mode, or drop it and let a list carry the information, as `scripts/README.md`'s **Modes** section now does.
A census comes first.
No sweep of the Markdown for running counts has been taken, so how many there are is unmeasured.
