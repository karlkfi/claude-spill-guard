# The scan set names its readers by instance, and one of them has no hook

[Q15](Q15.md) settled what to scan by asking whether a payload field's bytes
have crossed the filesystem-to-context boundary. The answer named three places
the hook reads the local side for itself: a `Read` path, a `Bash` reader's
resolved operands, and an `@path` in a prompt. Those are instances. The class is
**any hook input naming a filesystem path whose result comes back as content**,
and the design says so without enumerating it.

The distinction is new work rather than pedantry. Under the axis this replaced,
anything that was not `Read` or `Bash` was runtime output and excluded alongside
`PostToolUse`. Under the crossing axis those same inputs are uncrossed hops
where a deny does work, so the change opens an obligation instead of
discharging one.

## `@path` is the member that is measured, and it is the sharpest

Typing `@secret.txt` puts a file in front of the model and **no hook runs for
it**. Measured 2026-08-27 on Claude Code 2.1.238, darwin/arm64, in a project
wiring all three events to a stdin logger:

The marker column is read from the transcript the hook payload's own
`transcript_path` names, not from what the run printed — a blocked turn prints
nothing whatever the splice did, so stdout cannot separate the two:

| Prompt | Hook records | `tool_use_id` | Marker in transcript |
|---|---|---|---|
| `… @secret.txt … Do not use any tool.` | 1, `UserPromptSubmit` | 0 | 2, in 21,722 bytes |
| `Use the Read tool on secret.txt …` — control, same dir and config | 4, `PreToolUse` `Read` present | present | present |
| `… @secret …` — near-miss token, file untouched | 1, `UserPromptSubmit` | 0 | 0, in 21,384 bytes |
| `… @secret.txt …` again, `UserPromptSubmit` exiting 2 | 1, `UserPromptSubmit` | 0 | 0, in 1,404 bytes |

The `Read` control makes row one an absence rather than a dead hook. The zero
`tool_use_id` makes it a splice rather than a hop already covered — a model free
to call `Read` delivers the same content by a route `PreToolUse` sees, and the
two are indistinguishable from stdout.

**Do not take the model's word for which of those happened.** Asked where the
bytes came from, it has answered "already read into this conversation via a tool
call" for a turn whose transcript holds no `tool_use_id` at all, and "surfaced
via a system reminder" for another. Both are narration, one of them was wrong,
and neither is an instrument. The `tool_use_id` count is, and it is the reason
that column is in the table rather than a prose sentence. The deny row makes this a resolution
problem rather than a limitation: the prompt carries the token unexpanded, and
denying there takes the transcript to 1,404 bytes with no marker in it.

So the work is a resolver over the prompt — find `@` tokens, resolve them to
paths, scan those files, deny on a finding. It is the [Q62](Q62.md) reader-spec
problem with a much simpler grammar, and the same rule applies at the end of it:
**fail closed on what it cannot resolve.** A token naming a directory, a glob, a
path outside the workspace, or a file that does not exist is not a token to skip
quietly.

Two things to settle while measuring rather than after:

- **What the grammar actually is.** The near-miss row above says the splice is
  keyed to an exact token — `@secret` beside a file named `secret.txt` moves
  nothing — which is the result that de-risks this row, because a literal
  resolver then matches the harness and there is no divergence to fail open
  through. **Measured under `-p` only.** An interactive session has a file
  picker on `@`, which was not driven, so do not write "literal" unqualified.
  `@` inside a word, `@` in a code fence, an escaped `@` and a bare `@` are
  still undriven in both modes.
- **Whether the splice is bounded.** A `@path` on a large file, or a directory,
  puts an unknown quantity in front of the model, and the scanner's binary-skip
  and prefilter both assume a buffer it opened itself.

## The rest of the class is not enumerated

An installed MCP file or transcript reader is a member, and until this row and
the design section beside it, the words did not appear in this repository at
all: `git grep -n 'MCP\|WebFetch' origin/main -- docs/ README.md CLAUDE.md`
exits 1. Whether v1 covers them is a scoping decision this row should
take deliberately: enumerate what a default install exposes, decide which are in
the shipped `hooks.json` matcher, and write the ones that are out into *What it
is not* so the gap is stated rather than implied.

A matcher of `*` on `PreToolUse` sees every tool including ones installed later,
which argues for deciding by *payload shape* — a field naming a path — rather
than by a list of tool names that goes stale silently. That is the same argument
the ruleset makes for rejecting an unknown field at load rather than ignoring
it.
