# BSD `sed -i ''` makes the script read as a file operand

macOS `sed` takes the next argument after `-i` as the backup suffix, so `sed
-i '' 's/a/b/' f` edits `f` in place with no backup. The `sed` row in
`internal/readers/spec.go` treats `-i` as a flag that takes no argument, which
is GNU's reading. So `''` becomes the program and `'s/a/b/'` becomes a file
operand. When the script contains a `$`, that "operand" fails to resolve, and
the call is deferred and recorded.

Driven 2026-11-01 on the v0.6.0 binary, over a scratch `f.txt`:

| command | hook |
|---|---|
| `sed -i '' 's/a/b/' f.txt` | exit 0, silent |
| `sed -i '' 's/a/${X}/' f.txt` | exit 0, coverage record naming the script as an operand that "expands at run time" |
| `sed -i.bak 's/a/${X}/' f.txt` | exit 0, silent |
| `sed 's/a/${X}/' f.txt` | exit 0, silent |

**It is not a fail-open.** `f.txt` is still an operand and is still read, and
an in-place edit writes nothing to stdout. What it costs is the coverage log.
117 of the 252 real `Bash` records that name an operand, 2026-10-02 to
2026-11-02, are this shape. That is 46% of the log, and it is in every count
taken from the log: Q205's had to strip it out by hand. A script with no `$`
becomes a nonexistent path instead and stays silent, so the 117 are a floor
on how often the misread happens.

**The fix cannot simply switch to BSD's reading**, because GNU really does
take `''` as the script in `sed -i '' s/a/b/ f`. It then edits a file called
`s/a/b/`, if one exists, as well as `f`. A hook cannot run `sed --version`,
since `os/exec` is forbidden. Two answers stay inside that limit:

- Read `-i` followed by an empty token both ways and take the union. Under
  either sed, nothing an in-place edit reads goes to stdout, so the union costs
  nothing in output scanned.
- Treat an in-place `sed` as a writer whose operands send nothing. This one is
  wrong for a `w /dev/stdout` command in the script, so it needs that case
  ruled out first.

**Done** is the four rows above pinned in `readers_test.go` or a hook test,
the `$` case no longer recorded, and `f.txt` still read in every case. The
row's reading has to hold for GNU as well, so drive one GNU sed case on a
Linux runner, or state that only the BSD half was driven.
